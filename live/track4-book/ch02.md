# 2장. HTML로 내용의 구조와 의미 만들기

학습 기록장에 제목과 문장을 띄웠다고 해서 문서의 구조가 완성된 것은 아닙니다. 제목처럼 보이는 글자를 보통 문단으로 만들 수도 있고, 문단처럼 보이는 글자를 제목으로 만들 수도 있습니다. 눈으로 보이는 크기만으로는 둘을 구분하기 어렵습니다. 그러나 브라우저와 문서를 읽어 주는 보조 기술은 우리가 정한 요소의 의미를 이용합니다. 이 장에서는 모양보다 먼저 ‘이 내용은 무엇인가’를 표시하는 방법을 배웁니다.

HTML을 처음 보면 꺾쇠와 영어 단어가 본문 사이에 끼어 있어 복잡하게 느껴집니다. 하지만 작은 단위부터 읽으면 역할이 분명해집니다. ‘오늘 CSS를 배웠다’라는 문장은 내용이고, 그 문장을 문단이라고 표시하는 부분은 구조입니다. 내용과 구조가 어떻게 결합하는지 알면 처음 보는 화면도 조금씩 나누어 읽을 수 있습니다.

## 2.1 태그와 요소를 정확하게 나누어 읽기

다음 한 줄을 보겠습니다.

```html
<p>오늘은 HTML을 공부했습니다.</p>
```

`<p>`는 문단의 시작을 표시하는 여는 태그입니다. `</p>`는 끝을 표시하는 닫는 태그입니다. 둘 사이의 문장은 내용입니다. 시작, 내용, 끝을 포함한 전체를 요소라고 부릅니다. 일상 대화에서는 이 전체를 느슨하게 ‘태그’라고 부르기도 하지만, 처음 배울 때는 무엇을 가리키는지 구별해 두는 편이 좋습니다.[3][4]

닫는 태그에는 이름 앞에 `/`가 붙습니다. 이것은 ‘나누기’ 계산 기호가 아니라 해당 요소의 끝을 나타내는 HTML 표기입니다. Python에서 본 기호의 뜻을 모든 언어에 그대로 적용하지 않아야 합니다. `p`는 우리가 마음대로 지은 변수 이름이 아니라 HTML에서 문단을 나타내도록 정한 요소 이름입니다.

모든 요소가 같은 형태를 가지는 것은 아닙니다. 이미지를 표시하는 `img`나 입력을 받는 `input`은 내부 내용을 넣고 닫는 태그로 감싸는 방식이 아닙니다. 이런 요소에 임의로 `</img>`를 덧붙이지 않습니다. 따라서 ‘HTML은 무조건 모든 여는 태그와 닫는 태그가 한 쌍이다’라는 설명은 정확하지 않습니다. 우선 자주 사용하는 요소의 형태를 실제 예제로 확인하면 됩니다.

요소에는 추가 정보를 붙일 수 있습니다. 다음 코드에서 `lang`과 `class`는 속성의 이름이고, 따옴표 안은 각각의 값입니다.

```html
<p lang="ko" class="intro">오늘의 학습 기록입니다.</p>
```

`lang="ko"`는 이 요소의 언어 정보를 나타냅니다. `class="intro"`는 이 요소를 `intro`라는 분류에 넣습니다. `intro`는 사람이 정한 이름입니다. 이 이름을 붙이는 것만으로 글자가 커지거나 색이 바뀌지는 않습니다. 나중에 CSS가 이 분류를 선택해 스타일을 적용할 수 있게 이름을 붙여 둔 것입니다.

### 연습 2-1. 이름이 다른 두 종류의 단어

`<p class="memo">복습할 내용</p>`에서 `p`를 마음대로 `banana`로 바꾸는 것과 `memo`를 `study-note`로 바꾸는 것은 같은 종류의 변경일까요? 각각 어떤 역할인지 설명해 보세요.

### 풀이 2-1

같은 종류의 변경이 아닙니다. `p`는 문단이라는 HTML 요소의 이름이므로 문서의 의미와 관련됩니다. 이것을 알 수 없는 이름으로 바꾸는 것은 단순한 별명 변경이 아닙니다. `memo`는 우리가 정한 클래스 이름입니다. 이름을 바꿀 수 있지만, CSS나 JavaScript가 `.memo`를 찾고 있다면 그 연결도 함께 바꿔야 합니다.

즉 정해진 언어의 이름과 사람이 정한 연결용 이름을 구별해야 합니다. 컴퓨터가 `study-note`라는 영어를 이해해서 공부 메모 모양을 만들어 주는 것은 아닙니다. 그 이름을 선택하는 코드가 어떤 일을 하도록 작성되어 있는지가 중요합니다.

## 2.2 제목의 크기보다 제목의 단계가 먼저다

책의 제목, 장의 제목, 장 안의 소제목은 같은 단계가 아닙니다. HTML에도 제목의 단계를 나타내는 `h1`부터 `h6`까지의 요소가 있습니다. 숫자는 글자 크기 설정값이 아니라 제목의 단계입니다. 이 기록장에서는 화면의 주된 제목에 `h1`, 주요 구역에 `h2`, 그 안의 세부 구역에 `h3`를 사용하겠습니다.

```html
<h1>나의 학습 기록장</h1>
<h2>오늘의 기록</h2>
<p>HTML 요소의 포함 관계를 배웠습니다.</p>
<h2>이번 주에 복습할 내용</h2>
<h3>아직 헷갈리는 개념</h3>
<p>요소 이름과 클래스 이름을 구별합니다.</p>
```

기본 상태에서 브라우저는 제목을 크게 보여 주는 경우가 많습니다. 그러나 이것은 제목의 기본 표현 방식입니다. CSS로 `h2`를 아주 작게 만들 수도 있습니다. 작게 만들었다고 문단으로 바뀌지는 않습니다. 반대로 문단의 글자를 크게 만들었다고 제목 구조가 생기는 것도 아닙니다. 의미와 모양은 연결되어 있지만 같은 것은 아닙니다.[1][3][5]

이 구별은 AI가 화면을 만든 뒤 수정할 때 유용합니다. ‘제목을 작게 해 줘’라는 요청은 제목 요소를 문단으로 바꾸라는 뜻이 아닙니다. 제목의 의미는 유지하면서 크기만 조정할 수 있습니다. ‘여기에 새로운 소제목 구역을 만들어 줘’라는 요청은 크기만 바꾸는 것보다 문서 구조를 먼저 생각해야 합니다.

### 연습 2-2. 작은 제목을 만들고 싶은데

AI가 작은 소제목을 만들기 위해 본문 전체를 `p`로 바꾼 뒤 굵게 표시했습니다. 화면 모양은 비슷합니다. 현재 장 안의 두 번째 구역 제목이라면 어떤 접근이 더 적절할까요?

### 풀이 2-2

구역 제목에 맞는 `h2` 같은 제목 요소를 사용하고 CSS에서 크기와 굵기를 조절하는 편이 적절합니다. ‘작게 보인다’라는 표현 요구 때문에 ‘이것은 제목이다’라는 구조 정보를 잃을 필요는 없습니다. 정확한 단계는 문서의 나머지 구조에 맞춰 정합니다. 모든 작은 글자를 `h6`로 만드는 방식도 숫자를 크기 도구로 오해한 것입니다.

## 2.3 안에 넣는다는 것은 어떤 관계일까?

기록 여러 개를 보여 줄 때는 목록을 사용할 수 있습니다. 순서가 의미 없는 항목 묶음에는 `ul`, 첫째·둘째처럼 순서가 중요한 목록에는 `ol`을 사용합니다. 각 항목은 `li`로 표시합니다. 다음은 `body` 안에 들어갈 부분 코드입니다.

```html
<ul>
  <li>HTML 제목 구조 읽기</li>
  <li>링크 경로 확인하기</li>
  <li>입력창 설명 붙이기</li>
</ul>
```

`ul`이 전체 목록을 감싸고, 그 안에 `li` 세 개가 들어 있습니다. `ul`을 부모 요소, 그 안의 `li`를 자식 요소라고 부를 수 있습니다. 같은 부모 아래에 나란히 있는 `li`끼리는 형제 관계입니다. 여기서 부모와 자식은 실제 사람이나 상속 관계를 뜻하는 것이 아니라 포함 관계를 설명하는 용어입니다.

들여쓰기를 두 칸으로 맞춘 이유는 그 포함 관계를 눈으로 읽기 쉽게 하려는 것입니다. 같은 코드를 한 줄로 적어도 이 예제의 요소 관계는 태그에 따라 만들어집니다. 그러나 사람이 실수를 찾기 어려워지므로, 읽고 수정할 목적이라면 줄바꿈과 들여쓰기를 유지하는 편이 좋습니다.

브라우저가 잘못 작성된 HTML을 어느 정도 복구하여 보여 주기도 한다는 점이 초보자에게는 오히려 함정이 됩니다. 태그를 잘못 닫았는데도 화면이 얼핏 정상처럼 보일 수 있습니다. 그렇다고 원래 코드가 올바르다는 증거는 아닙니다. 우리가 쓴 구조와 브라우저가 복구해서 만든 구조가 다를 수 있습니다. 나중에 CSS나 JavaScript가 예상하지 않은 요소를 선택하는 원인이 될 수 있습니다.[4]

```html
<p>오늘의 기록 <strong>완료</strong></p>
```

위 코드에서 `strong`은 문단 안의 ‘완료’를 중요하게 표시합니다. 안쪽 요소가 먼저 끝나고 바깥쪽 문단이 끝납니다. `<p><strong>완료</p></strong>`처럼 서로 교차해서 닫는 형태를 좋은 작성 방식으로 삼지 않습니다.

### 연습 2-3. 어떤 목록을 선택할까?

‘오늘 공부한 주제 세 개’와 ‘앱을 실행하는 순서 세 단계’를 표시하려고 합니다. 각각 `ul`과 `ol` 중 무엇을 먼저 고려할지 정해 보세요. 화면에서 숫자가 예쁘게 보이는지는 판단 기준에서 제외합니다.

### 풀이 2-3

공부한 주제의 순서가 특별한 의미가 없다면 `ul`을 고려합니다. 실행 순서가 중요하다면 `ol`을 고려합니다. 목록의 뜻으로 선택하는 것입니다. 실제로 공부한 시간 순서가 중요한 기록이라면 주제 목록도 순서가 있는 목록으로 설계할 수 있습니다. 태그를 고르는 기준은 사물의 이름이 아니라 이 화면에서 전달하려는 관계입니다.

## 2.4 링크와 이미지에는 위치 정보가 필요하다

링크는 다른 위치로 이동하는 요소입니다. `a` 요소의 `href`에 이동할 주소를 적고, 그 안에 사용자가 읽을 문구를 넣습니다.

```html
<a href="review.html">복습 기록 보기</a>
```

`review.html`이라는 글자가 화면에 반드시 그대로 보이는 것은 아닙니다. 화면에는 ‘복습 기록 보기’가 나타나고, 이동할 위치는 `href`에 들어 있습니다. 링크 문구와 목적지는 구별됩니다. 문구만 보고 목적지가 자동으로 결정되는 것도 아닙니다. ‘저장’이라고 적힌 링크라도 `href`가 다른 페이지를 가리키면 그 위치로 이동합니다.

페이지 안의 특정 위치로 이동할 수도 있습니다. 먼저 대상 요소에 `id`를 붙이고, 링크에서는 `#` 뒤에 그 이름을 적습니다.

```html
<a href="#review">복습 구역으로 이동</a>
<h2 id="review">복습할 내용</h2>
```

`id`는 해당 문서에서 요소를 구별하는 고유한 이름으로 사용합니다. 여기서는 `review`라는 이름의 위치로 이동하기 위해 사용했습니다. 같은 문서에 같은 `id`를 반복해서 붙이지 않아야 목적지를 분명하게 정할 수 있습니다. 반면 `class`는 여러 요소를 같은 묶음으로 분류할 때 사용하므로 반복할 수 있습니다. CSS를 배울 때 다시 만나겠지만, 지금은 ‘하나를 구별하는 이름’과 ‘여러 요소에 함께 붙일 수 있는 분류’를 구분하면 됩니다.

이미지는 `img`의 `src`에 파일 주소를 적습니다. `alt`는 이미지를 보지 못하는 상황에서도 그 이미지가 전달하는 정보를 얻을 수 있도록 하는 대체 텍스트입니다. 다음 예제는 실제로 `images/study-desk.jpg`라는 파일을 함께 준비해야 이미지를 표시할 수 있는 부분 코드입니다.

```html
<img src="images/study-desk.jpg" alt="노트와 태블릿이 놓인 공부 책상">
```

여기서 파일 이름이 대체 텍스트를 자동 생성하지 않습니다. 반대로 `alt`에 아무 설명이나 길게 적는 것이 언제나 좋은 것도 아닙니다. 내용 이해에 필요한 이미지라면 그 역할을 설명하고, 정보가 없는 순수 장식이라면 빈 대체 텍스트가 적절할 수 있습니다. 장식인지 정보인지 판단하지 않은 채 모든 이미지에 ‘이미지’라고만 쓰면 필요한 정보를 전달하기 어렵습니다.[4][5]

### 연습 2-4. 같은 이름을 여러 번 붙인 기록

목록의 각 항목에 모두 `id="record"`를 붙였습니다. 나중에 JavaScript로 특정 항목을 찾으려 합니다. 공통 스타일을 적용하려는 목적과 개별 항목을 구별하려는 목적을 어떻게 나누면 좋을까요?

### 풀이 2-4

공통 스타일에는 `class="record"`를 반복해서 사용할 수 있습니다. 하나씩 구별할 필요가 있다면 `record-1`, `record-2`처럼 중복되지 않는 식별자를 쓰거나, 이후 배울 데이터 식별자와 요소를 연결하는 방식을 사용합니다. 지금 핵심은 같은 목적에 두 이름을 무작정 혼용하지 않는 것입니다. ‘모두 기록이다’라는 분류와 ‘그중 두 번째 기록이다’라는 식별은 다른 정보입니다.

## 2.5 화면을 구역으로 나누되 의미 없는 상자를 늘리지 않기

제목, 메뉴, 주된 내용, 아래쪽 안내를 구분하면 문서를 읽기 쉬워집니다. `header`는 소개나 머리말 구역, `nav`는 주요 탐색 링크, `main`은 페이지의 주된 내용, `footer`는 해당 구역이나 문서의 끝부분 정보를 나타내는 데 사용합니다. `section`은 주제별 구역을 나타내며 제목과 함께 구성하면 관계가 더 분명해집니다.[5]

어떤 요소를 썼다는 이유만으로 화면이 자동으로 정교하게 배치되는 것은 아닙니다. `nav` 안의 링크가 가로로 예쁘게 나열되려면 CSS를 더할 수 있습니다. 구조를 정하는 일과 배치하는 일을 다시 분리해서 생각해야 합니다. 다음은 지금 단계의 기록장 전체 문서입니다.

```html demo
<!doctype html>
<html lang="ko">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>나의 학습 기록장</title>
  </head>
  <body>
    <header>
      <h1>나의 학습 기록장</h1>
      <p>오늘 이해한 내용을 조금씩 남깁니다.</p>
      <nav aria-label="페이지 안에서 이동">
        <a href="#today">오늘의 기록</a>
        <a href="#review">복습할 내용</a>
      </nav>
    </header>
    <main>
      <section id="today">
        <h2>오늘의 기록</h2>
        <ul>
          <li>제목과 문단을 구별했습니다.</li>
          <li>링크에 목적지가 필요하다는 것을 배웠습니다.</li>
        </ul>
      </section>
      <section id="review">
        <h2>복습할 내용</h2>
        <p>id와 class의 차이를 다시 설명해 봅니다.</p>
      </section>
    </main>
    <footer>
      <p>이 기록은 학습용 예시입니다.</p>
    </footer>
  </body>
</html>
```

처음 보는 `aria-label`은 이 탐색 구역의 이름을 보조 기술에 알려 주는 속성입니다. 화면에 별도 글자를 반드시 추가하지는 않습니다. 이미 의미가 분명한 기본 HTML 요소를 잘 사용하는 것이 먼저이며, 모든 요소에 ARIA 속성을 많이 붙여야 좋은 문서가 되는 것은 아닙니다.

이 문서를 실행했을 때 기본 글꼴이나 간격이 마음에 들지 않아도 HTML이 실패한 것은 아닙니다. 구조가 생긴 상태이고, 아직 우리가 원하는 스타일을 작성하지 않았을 뿐입니다. 예쁜 완성 화면을 바로 보려는 마음 때문에 구조와 스타일을 한 번에 바꾸면 어떤 변경이 어떤 결과를 만들었는지 파악하기 어려워집니다.

`div`와 `span`도 자주 보게 됩니다. 특별한 의미를 정하지 않은 일반적인 묶음이 필요할 때 사용합니다. 적절한 의미 요소가 있는데도 모든 부분을 `div`로 바꾸는 것은 문서의 정보를 줄일 수 있습니다. 반대로 작은 묶음 하나마다 의미 있는 거대한 구역인 것처럼 `section`을 남발할 필요도 없습니다. ‘이 부분은 어떤 내용인가’에 대한 답이 먼저입니다.

### 연습 2-5. 두 링크 중 어느 쪽이 어디로 갈까?

위 전체 문서에서 ‘복습할 내용’을 누르면 무엇이 연결되어 작동하나요? 문구를 ‘다시 공부할 것’으로만 바꾸면 이동 목적지도 바뀔까요?

### 풀이 2-5

링크의 `href="#review"`와 대상 구역의 `id="review"`가 연결됩니다. 화면 문구를 ‘다시 공부할 것’으로 바꾸더라도 `href`를 그대로 두면 같은 대상 위치를 가리킵니다. 이는 링크의 표시 내용과 목적지가 별도 정보라는 예입니다.

목적지를 `today`로 바꾸고 싶다면 `href="#today"`로 수정해야 합니다. 문구만 ‘오늘’이라고 바꾸는 것은 사용자를 잘못 안내할 수도 있습니다. 코드가 하는 일과 사람이 읽는 설명이 일치하는지도 확인해야 합니다.

## 2.6 HTML에 코드를 글자로 보여 주는 상황

교재나 도움말 페이지에서는 `<p>`라는 문자를 화면에 그대로 보여 주고 싶을 수 있습니다. 그런데 HTML 문서 안에 `<p>`를 그냥 적으면 브라우저는 이를 문단 시작 태그로 해석할 수 있습니다. 이런 경우 `<`와 `>`를 각각 `&lt;`, `&gt;`로 표현합니다.

```html
<p>문단은 &lt;p&gt; 요소로 표시합니다.</p>
```

화면에는 ‘문단은 <p> 요소로 표시합니다.’라는 문장이 보입니다. 브라우저에게 구조로 해석할 부분과 내용으로 보여 줄 부분을 구별해 주는 것입니다. 코드 예제를 표시할 때 자주 만나는 문제입니다. 나중에 사용자가 입력한 문자열을 화면에 보여 줄 때도 비슷한 구별이 중요해집니다. 사용자의 글자를 문서 코드로 해석해도 되는지 함부로 결정하면 안 됩니다.

### 연습 2-6. 표시하려던 태그가 사라졌다

도움말에 ‘제목은 <h1>로 만듭니다’라고 적었는데 화면 구조가 이상해졌습니다. 태그 이름을 글자로 보여 주려면 문장을 어떻게 적어야 할까요?

### 풀이 2-6

HTML 문서에서는 `제목은 &lt;h1&gt;로 만듭니다`처럼 적을 수 있습니다. 여는 꺾쇠와 닫는 꺾쇠를 문자로 표현한 것입니다. 이 해결은 JavaScript에서 사용자 글자를 안전하게 표시하는 방법 전체를 대신하지는 않습니다. 그 상황에서는 뒤에서 배울 `textContent` 같은 방식을 함께 이해해야 합니다.

이 장에서 문서에 제목과 목록, 구역, 연결을 붙였습니다. 아직 사용자가 새로운 기록을 입력하지는 못합니다. 다음 장에서는 문서를 읽는 사람을 입력하는 사람으로 바꾸어 봅니다. 입력창 하나를 만드는 것에서 시작하되, 그 입력이 어디까지 준비된 상태이고 아직 무엇이 빠져 있는지도 분명하게 구분하겠습니다.
