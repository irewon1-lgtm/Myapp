# 4장. CSS는 어떤 규칙으로 화면에 적용될까?

앞 장에서 입력창과 설명, 버튼을 만들었습니다. 이제 글자가 너무 작고 요소 사이가 붙어 있다는 것이 눈에 들어옵니다. 이때 HTML 요소의 이름을 바꾸거나 JavaScript를 추가할 필요는 없습니다. 내용을 어떤 크기와 간격으로 보여 줄지 정하는 CSS를 작성하면 됩니다.

CSS를 배우는 첫날부터 속성 이름 수십 개를 외우면 코드가 길어질수록 더 어려워집니다. 지금 필요한 것은 규칙 한 덩어리를 읽는 방법입니다. ‘어느 요소를 고르는가’, ‘그 요소의 무엇을 바꾸는가’, ‘어떤 값으로 바꾸는가’를 구분하고, 규칙이 여러 개 있을 때 적용 결과를 설명하는 연습부터 시작하겠습니다.

## 4.1 CSS 한 덩어리를 문장으로 읽기

```css
p {
  color: #243044;
  font-size: 18px;
  line-height: 1.7;
}
```

첫 줄의 `p`는 선택자입니다. 여기서는 문서의 `p` 요소를 선택합니다. 중괄호 안에는 선택한 요소에 적용할 선언들이 들어갑니다. 각 선언은 속성 이름, 콜론, 값으로 구성됩니다. `color`는 글자색, `font-size`는 글자 크기, `line-height`는 줄 높이와 관련된 속성입니다. `18px`는 이 선언에서 사용한 크기 값이고, `#243044`는 색을 표현하는 값입니다.

`color: #243044;`를 읽을 때는 ‘선택한 문단의 글자색을 이 색으로 정한다’라고 풀어 읽으면 됩니다. 세미콜론은 선언의 끝을 구분합니다. 중괄호는 이 선택자에 속한 선언 범위를 감쌉니다. Python에서 콜론 뒤에 들여쓴 부분을 묶었던 것과 표기 방식이 다릅니다. CSS에서는 중괄호 안팎을 살피면 어느 규칙에 속하는지 읽을 수 있습니다.[1][2][3]

이 규칙은 HTML에 없는 문단을 새로 만들지는 않습니다. 이미 있는 문단을 선택해 표현을 바꿉니다. 실제 문서에 `p` 요소가 없다면 이 규칙으로 바뀔 문단도 없습니다. CSS가 틀리지 않았는데 변화가 없는 경우에는 ‘규칙이 선택할 대상이 있는가’를 먼저 확인할 수 있습니다.

### 연습 4-1. 무엇을 선택한 것일까?

`button { font-size: 20px; }`라는 규칙이 있습니다. 이것은 ‘button이라는 이름의 변수를 20으로 만든다’는 뜻일까요? 어느 대상의 어떤 부분을 바꾸는지 설명해 보세요.

### 풀이 4-1

문서의 `button` 요소를 선택하고 그 요소의 글자 크기를 `20px`로 설정하는 규칙입니다. JavaScript 변수 선언이나 값을 계산하는 식이 아닙니다. `button`이 이 위치에서 선택자로 사용된다는 점이 중요합니다. 언어와 위치를 함께 읽어야 같은 영어 단어를 잘못 해석하지 않을 수 있습니다.

## 4.2 모든 문단과 일부 문단을 구별하기

모든 `p`에 같은 규칙을 적용하면 오류 안내문까지 같은 모양이 됩니다. 일부 문단을 따로 꾸미려면 앞에서 배운 클래스 이름을 활용할 수 있습니다.

```html
<p class="intro">오늘 배운 내용을 남겨 보세요.</p>
<p class="message">아직 저장된 기록이 없습니다.</p>
<p>이 기록장은 학습용입니다.</p>
```

```css
p {
  line-height: 1.7;
}

.intro {
  font-size: 20px;
}

.message {
  color: #7a2e22;
}
```

CSS에서 클래스 이름 앞에 점을 붙입니다. `.intro`는 `class="intro"`에 해당하는 요소를 선택합니다. HTML의 class 값에는 점을 넣지 않았다는 것에 주의하세요. 점은 CSS 선택자의 표기입니다. `intro`라는 단어 자체가 ‘소개글처럼 꾸며라’라는 내장 명령은 아닙니다. 두 파일에서 같은 이름으로 연결한 것입니다.

`id="record-form"`이라는 요소를 고를 때는 `#record-form`처럼 `#`을 사용할 수 있습니다. 그러나 무엇이든 id로만 선택해야 하는 것은 아닙니다. 반복되는 표현은 클래스로 묶는 편이 관리하기 쉬울 수 있습니다. 중요한 것은 이름의 길이나 멋이 아니라, 실제 HTML의 대상과 연결되는지입니다.

공백이 들어간 선택자도 보게 됩니다. `.entry p`는 `entry` 클래스를 가진 요소 안의 `p`를 선택합니다. `.entry`와 `p`라는 두 대상을 각각 선택하는 뜻이 아닙니다. 여러 선택자를 따로 묶을 때 사용하는 쉼표와 구별해야 합니다.

```css
.entry p {
  margin-bottom: 8px;
}

h1, h2 {
  line-height: 1.3;
}
```

첫 규칙은 특정 구역 안의 문단에 적용됩니다. 두 번째 규칙은 `h1`과 `h2` 각각에 적용됩니다. 작은 공백이나 쉼표 하나가 대상을 바꿀 수 있으므로, 선택자 부분도 선언 못지않게 자세히 읽어야 합니다.

### 연습 4-2. 클래스 철자 하나가 다른 경우

HTML에는 `<p class="warning">시간을 확인해 주세요.</p>`라고 적었습니다. CSS는 `.warn { color: red; }`입니다. 글자색이 바뀌지 않는다면 우선 무엇을 수정해야 할까요?

### 풀이 4-2

HTML의 `warning`과 CSS의 `warn`이 서로 다른 이름이라는 점부터 수정해야 합니다. 예를 들어 CSS를 `.warning`으로 바꾸면 실제 요소를 선택할 수 있습니다. 스타일의 우선순위를 높이기 전에 선택이 맞는지 확인하는 것입니다.

이 경우에는 ‘warning과 warn은 영어 뜻이 비슷하니까 컴퓨터가 알아줄 것’이라고 생각할 수 없습니다. 분류 이름은 정해진 문자열로 연결됩니다. 사람에게 비슷한 말이라는 사실은 선택 규칙을 대신하지 못합니다.

## 4.3 글자의 크기, 줄 높이, 상속을 함께 이해하기

문서 전체의 기본 글꼴을 정할 때는 `body`에 규칙을 둘 수 있습니다.

```css
body {
  font-family: system-ui, sans-serif;
  font-size: 18px;
  line-height: 1.7;
  color: #202734;
}

input, button, textarea, select {
  font: inherit;
}
```

`system-ui`는 실행하는 환경의 사용자 인터페이스 글꼴을 사용하도록 요청하는 글꼴 계열이고, `sans-serif`는 그 뒤의 대체 계열입니다. 정확히 같은 글꼴 파일이 모든 기기에 있다는 뜻은 아닙니다. 한글을 보여 줄 때 사용할 수 있는 글꼴은 환경에 따라 선택될 수 있습니다.

부모 요소에 정한 일부 속성이 자식에게 이어지는 것을 상속이라고 합니다. 글자색이나 글꼴처럼 상속되는 속성이 있지만, 모든 CSS 속성이 자동으로 같은 방식으로 상속되지는 않습니다. 테두리를 부모에 주었다고 자식마다 똑같은 테두리가 생기는 것은 아닙니다. 입력창과 버튼의 글꼴은 브라우저 기본 스타일의 영향을 받을 수 있으므로 예제에서는 `font: inherit`로 주변 글꼴 설정을 따르도록 했습니다.[4]

`line-height: 1.7`처럼 단위 없이 비율을 주면 글자 크기를 기준으로 줄 높이를 정하는 데 사용할 수 있습니다. 글자 크기가 18px인 단순한 경우 이 값은 약 30.6px의 줄 높이에 해당합니다. 글자 모양의 실제 검은 부분 높이와 줄 높이는 같은 것이 아닙니다. 글자가 커졌을 때 줄끼리 겹치지 않고 읽을 공간을 남기는 관점으로 보아야 합니다.

`px`는 CSS에서 사용하는 길이 단위입니다. 실제 기기의 물리적인 발광 점 하나와 언제나 1대1로 대응하는 뜻은 아닙니다. `rem`은 루트 요소의 글자 크기를 기준으로 하는 단위입니다. 예를 들어 루트 크기가 16px인 상황에서 `1.25rem`은 20px입니다. 기준이 달라지면 결과도 달라집니다. 이 책에서는 픽셀 숫자만 늘리는 것과 사용자의 글자 설정을 존중하는 설계를 뒤에서 비교합니다.

### 연습 4-3. 상속이 되는데 왜 버튼 글자가 작을까?

본문 글자는 커졌는데 버튼 글자는 그대로 작습니다. ‘CSS 상속이 고장 났다’라고 판단하기 전에 무엇을 확인하면 좋을까요?

### 풀이 4-3

버튼에 브라우저 기본 스타일이나 별도의 글꼴 규칙이 적용되는지 확인합니다. 예제처럼 입력 컨트롤에 `font: inherit`를 명시하는 방법도 있습니다. 부모에게 준 모든 속성이 모든 요소에 무조건 똑같이 적용된다고 가정하면 이런 차이를 오류로 오해하기 쉽습니다.

수정 후에는 버튼 글자가 커졌을 때 버튼 높이와 줄바꿈도 괜찮은지 함께 봅니다. 하나의 속성을 바꾸면 그에 필요한 공간도 달라질 수 있습니다. 이 문제는 다음 장의 박스 모델로 이어집니다.

## 4.4 여러 규칙이 겹칠 때는 무엇이 적용될까?

같은 문단에 서로 다른 색을 정하면 어떤 색이 보일까요? 단순히 ‘가장 아래에 적은 코드가 언제나 이긴다’고 외우면 실제 프로젝트에서 쉽게 틀립니다. CSS는 규칙의 출처와 중요도, 계층, 선택자의 구체성, 순서 같은 요소를 고려하여 적용할 값을 정합니다. 처음에는 조건을 좁힌 예제로 시작하겠습니다.[4][5]

다음 예제는 같은 작성자 스타일 안에서, 별도 계층이나 `!important` 없이 작성한 규칙입니다.

```html
<p class="message">기록을 확인해 주세요.</p>
```

```css
.message {
  color: #183a68;
}

p {
  color: #8c332a;
}
```

이 조건에서는 `.message`가 일반적인 `p`보다 선택자의 구체성이 높기 때문에 첫 번째 색이 적용됩니다. 아래에 적힌 `p` 규칙이라고 무조건 덮어쓰는 것이 아닙니다. ‘어떤 요소를 얼마나 구체적으로 선택했는가’가 관여합니다. 선택자의 종류를 점수처럼 비교하는 자세한 방식도 있지만, 지금은 클래스 선택자와 요소 선택자를 구별하는 것부터 확실히 하면 됩니다.

같은 조건과 같은 구체성의 규칙이라면 뒤쪽 선언이 적용되는 상황을 볼 수 있습니다.

```css
.message {
  color: #183a68;
}

.message {
  color: #8c332a;
}
```

이 경우에는 나중의 색이 적용됩니다. 따라서 결과를 설명할 때 ‘같은 중요도와 계층 등의 조건에서 선택자의 구체성도 같으므로, 뒤쪽 규칙이 적용된다’라고 범위를 좁혀 말하는 것이 정확합니다. 모든 경우를 한 문장으로 뭉개지 않는 연습입니다.

규칙이 먹히지 않을 때마다 `!important`를 추가하는 방법은 잠깐 해결처럼 보일 수 있습니다. 하지만 어떤 규칙이 왜 필요한지 모르는 상태에서 강한 규칙만 계속 쌓이면 이후 수정이 더 어려워집니다. 먼저 요소가 선택되었는지, 실제로 어떤 선언이 적용되는지, 기존 규칙을 정리할 수 있는지 확인하는 편이 낫습니다.

### 연습 4-4. 맨 아래에 썼는데도 바뀌지 않는다

위 첫 번째 예제에서 `.message`는 파란 계열 색, 뒤의 `p`는 붉은 계열 색입니다. 붉은 계열이 보일 것이라고 예상했다면 무엇을 놓친 것인가요? 다른 조건이 같다는 전제에서 답해 보세요.

### 풀이 4-4

순서만 보고 선택자의 구체성을 놓쳤습니다. `.message`는 클래스 선택자이고 `p`는 요소 선택자입니다. 이 예제 조건에서는 클래스 규칙이 우선합니다. 바꾸려는 대상이 message 문단이라면 `.message`의 색을 직접 수정하는 것이 간단할 수 있습니다. 무작정 세 번째 규칙을 덧붙이는 것보다 원래 규칙을 고치는 편이 명확합니다.

## 4.5 기록장에 처음으로 스타일 입히기

다음은 3장의 HTML에 연결할 `style.css`의 시작 부분입니다. 이미 `head`에 `<link rel="stylesheet" href="style.css">`가 있어야 사용됩니다. 파일을 만들기만 하고 연결하지 않으면 이 규칙이 자동으로 발견되지는 않습니다.

```css
body {
  font-family: system-ui, sans-serif;
  font-size: 18px;
  line-height: 1.7;
  color: #202734;
  background: #f6f4ee;
}

h1 {
  font-size: 1.8rem;
  line-height: 1.3;
}

label {
  font-weight: 700;
}

input, button {
  font: inherit;
}

button {
  color: #ffffff;
  background: #294d43;
  border: 1px solid #294d43;
}
```

이 단계에서는 아직 배치를 완성하지 않았습니다. 글자와 배경의 관계, 기본 폰트의 일관성을 먼저 정했습니다. 색 값의 의미를 전부 암기할 필요는 없습니다. 코드가 어떤 대상의 전경색과 배경색을 바꾸는지 읽을 수 있으면 됩니다. 색을 고를 때는 배경과 글자가 구별되는지 함께 보아야 합니다. 배경만 어둡게 하고 글자색을 그대로 두면 잘 안 보일 수 있습니다.

같은 색을 여러 곳에서 사용하면 나중에 수정할 때 누락이 생길 수 있습니다. CSS 사용자 정의 속성을 사용하면 공통 값을 이름으로 묶을 수 있습니다. 흔히 CSS 변수라고 부릅니다.

```css
:root {
  --ink: #202734;
  --paper: #f6f4ee;
  --accent: #294d43;
}

body {
  color: var(--ink);
  background: var(--paper);
}

button {
  background: var(--accent);
}
```

`--accent`는 우리가 정한 이름이고, `var(--accent)`는 그 이름의 값을 사용하는 표현입니다. `accent`라는 영어 때문에 자동으로 강조색이 되는 것은 아닙니다. 이 예제에서 버튼 배경에 연결했기 때문에 그 역할을 맡는 것입니다. 공통 값을 이름 붙이는 목적은 수정 위치를 모으고 관계를 읽기 쉽게 하는 데 있습니다.

### 연습 4-5. 배경만 어둡게 바꾼 경우

`--paper`를 어두운 색으로 바꿨더니 본문이 거의 보이지 않습니다. 기존 `--ink`도 어두운 값입니다. 어떤 관계를 함께 수정하고 확인해야 할까요?

### 풀이 4-5

배경색과 글자색을 함께 확인해야 합니다. 어두운 배경에 맞는 충분히 구별되는 글자색을 정하고, 링크·입력창·버튼·오류 안내 같은 다른 요소의 조합도 확인합니다. ‘다크 모드’는 배경 하나를 검게 만드는 기능과 같지 않습니다. 구체적인 검사는 6장에서 이어집니다.

## 4.6 적용이 안 될 때 줄을 늘리기 전에 확인할 것

스타일이 바뀌지 않으면 먼저 CSS 파일을 실제로 불러왔는지 살핍니다. 경로가 틀린 경우와 선택자가 틀린 경우는 해결 위치가 다릅니다. 그다음 선택한 요소가 맞는지 보고, 선언의 철자나 값이 유효한지 확인합니다. 마지막으로 다른 규칙과의 관계를 확인합니다. 브라우저는 잘못된 선언 일부를 무시할 수 있으므로, 다른 부분이 보인다고 모든 줄이 정상이라는 뜻은 아닙니다.

개발자 도구에서는 요소에 적용되는 스타일과 덮어쓰인 선언을 관찰할 수 있습니다. 모바일 기기만 사용하는 동안에는 도구 접근이 다를 수 있으므로, 특정 데스크톱 단축키를 모든 기기에서 그대로 쓰라고 하지 않겠습니다. 중요한 것은 정보를 보는 목적입니다. ‘이 요소에 지금 적용된 값이 무엇인가’를 확인하려는 것입니다. 이후 오류 진단 장에서 이 관찰을 더 체계적으로 연결합니다.

지금까지 CSS가 대상을 고르고 값을 정하는 언어라는 것을 배웠습니다. 다음에는 여백과 폭, 배치가 왜 예상과 다르게 움직이는지 살펴보겠습니다. 글자색은 맞는데 화면 밖으로 밀려나는 입력창은 색 규칙의 문제가 아닙니다. 요소가 차지하는 공간을 계산하는 방식부터 이해해야 합니다.
