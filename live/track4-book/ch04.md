# 4장. CSS는 어떤 규칙으로 화면에 적용될까?

앞 장까지 우리는 웹페이지에 제목, 설명, 입력칸, 버튼을 만들었습니다. 그런데 지금 화면은 조금 심심합니다. 글자는 전부 비슷해 보이고, 버튼도 기본 모양 그대로입니다.

이럴 때 HTML을 다시 뜯어고치는 것이 아닙니다. **HTML은 “무엇이 있는지”를 적는 쪽이고, CSS는 “그것을 어떻게 보이게 할지”를 정하는 쪽**이라고 생각하면 됩니다.

집에 비유해 보겠습니다. HTML이 책상, 의자, 문, 창문을 놓는 일이라면 CSS는 벽 색을 바꾸고, 글씨를 크게 하고, 버튼에 색을 입히는 일입니다. 책상을 빨간색으로 칠한다고 책상이 의자로 바뀌지는 않습니다. 웹페이지도 마찬가지입니다. CSS는 보이는 모습은 바꾸지만, 제목을 버튼으로 바꾸는 식으로 내용의 역할 자체를 바꾸는 도구는 아닙니다.

여기서 처음 나오는 이름이 **CSS**입니다. CSS는 웹페이지의 글자색, 글자 크기, 배경색, 간격, 위치 같은 **겉모습을 정하는 규칙**입니다. 영어 이름을 외울 필요는 없습니다. 지금은 그냥 **“웹페이지 꾸미기 규칙”**이라고 생각해도 충분합니다.

이 장에서는 어려운 단어를 먼저 외우지 않습니다. 먼저 눈으로 결과를 보고, 그다음에 “아, 이런 것을 개발자들은 이렇게 부르는구나” 하고 이름을 붙이겠습니다.

## 4.1 CSS는 “누구를, 무엇을, 어떻게” 바꾸는 문장이다

먼저 아주 짧은 코드 하나만 보겠습니다.

```css
p {
  color: blue;
}
```

처음 보면 `p`, `{`, `color`, `blue`, `;`가 전부 낯설 수 있습니다. 한 번에 외우지 말고 사람 말로 바꿔 읽어 보겠습니다.

> **“웹페이지에 있는 문단(p)을 찾아서, 글자색(color)을 파란색(blue)으로 바꿔라.”**

이게 전부입니다.

코드를 조각조각 보면 다음과 같습니다.

- `p` → **누구를 바꿀지** 정합니다. 여기서는 문단입니다.
- `{ ... }` → 그 대상에게 적용할 꾸미기 규칙을 안에 넣습니다.
- `color` → **무엇을 바꿀지** 정합니다. 여기서는 글자색입니다.
- `blue` → **어떻게 바꿀지** 정합니다. 여기서는 파란색입니다.
- `;` → “이 규칙은 여기까지”라고 구분하는 표시입니다.

이제 개발자 용어를 하나 붙여 보겠습니다.

**선택자(selector)**라는 말이 있습니다. 뜻은 어렵지 않습니다. **“바꿀 대상을 고르는 부분”**입니다. 위 코드에서는 맨 앞의 `p`가 선택자입니다.

**속성(property)**은 **“무엇을 바꿀지 적는 이름”**입니다. 위에서는 `color`가 속성입니다.

**값(value)**은 **“어떤 모습으로 바꿀지 적은 내용”**입니다. 위에서는 `blue`가 값입니다.

그러니까 개발자가 이렇게 말한다면,

> “선택자로 p를 잡고 color 속성 값을 blue로 줬어요.”

우리말로는 그냥,

> “문단을 골라서 글자를 파랗게 했어요.”

라는 뜻입니다.

전문용어를 모르는 상태에서도 먼저 뜻을 이해할 수 있어야 합니다. 그다음 용어는 이름표처럼 붙이면 됩니다.

### 조금만 더 바꿔 보기

```css
p {
  color: blue;
  font-size: 20px;
}
```

이번에는 규칙이 하나 더 생겼습니다.

`font-size`는 **글자 크기**를 뜻합니다. `20px`는 글자 크기를 어느 정도로 할지 적은 값입니다. `px`는 화면에서 크기를 정할 때 자주 쓰는 단위입니다. 지금은 “숫자가 커지면 대체로 글자도 커진다” 정도만 알아도 됩니다.

이 코드를 사람 말로 읽으면 다음과 같습니다.

> “문단의 글자는 파랗게 하고, 글자 크기는 20px로 해라.”

CSS를 볼 때는 항상 이 세 질문부터 해 보세요.

1. **누구를 바꾸지?**
2. **무엇을 바꾸지?**
3. **어떻게 바꾸지?**

이 세 가지를 찾으면 처음 보는 CSS도 훨씬 덜 무섭습니다.

### 연습 4-1. 코드를 사람 말로 바꿔 보기

다음 코드를 보고 사람 말로 설명해 보세요.

```css
button {
  font-size: 22px;
  color: white;
}
```

`button`은 무엇을 고른 것이고, `font-size`와 `color`는 각각 무엇을 바꾸는 것일까요?

### 풀이 4-1

`button`은 웹페이지의 버튼을 고른 것입니다. 개발자 용어로는 **선택자**입니다.

`font-size: 22px;`는 버튼 안의 글자 크기를 22px로 정하는 규칙입니다. `color: white;`는 버튼 안의 글자색을 흰색으로 정하는 규칙입니다.

사람 말로 바꾸면 다음과 같습니다.

> **“버튼의 글자를 크게 하고, 글자색은 흰색으로 해라.”**

이것을 “button이라는 변수를 만든다”라고 읽으면 안 됩니다. 같은 영어 단어라도 어느 언어의 어느 위치에서 쓰였는지에 따라 역할이 달라집니다.

## 4.2 모든 글자를 바꿀까, 딱 하나의 종류만 바꿀까?

이번에는 실제 상황을 생각해 보겠습니다.

페이지에 문단이 세 개 있습니다.

```html
<p>오늘 배운 내용을 적어 보세요.</p>
<p>아직 저장된 기록이 없습니다.</p>
<p>이 기록장은 학습용입니다.</p>
```

그리고 CSS를 이렇게 적었습니다.

```css
p {
  color: green;
}
```

어떻게 될까요?

세 문단이 전부 초록색이 됩니다. 왜냐하면 `p`라고 적으면 **모든 p 문단을 고르기 때문**입니다.

그런데 두 번째 문장만 빨간색으로 만들고 싶다면 어떻게 해야 할까요?

사람에게 일을 시킨다고 생각해 봅시다.

> “학생들 모두 일어나세요.”

라고 하면 학생 전체가 대상입니다.

하지만

> “빨간 모자를 쓴 학생만 일어나세요.”

라고 하면 특정한 학생만 고를 수 있습니다.

웹페이지에서도 비슷하게 **이름표를 붙여 특정한 종류만 골라낼 수 있습니다.** HTML에서는 그 이름표를 `class`라고 부릅니다.

`class`라는 말을 먼저 외우려고 하지 마세요. 뜻은 그냥 **“여러 요소에게 붙일 수 있는 분류 이름표”**입니다.

HTML에 이렇게 이름표를 붙여 보겠습니다.

```html
<p>오늘 배운 내용을 적어 보세요.</p>
<p class="warning">아직 저장된 기록이 없습니다.</p>
<p>이 기록장은 학습용입니다.</p>
```

두 번째 문단에 `warning`이라는 이름표가 붙었습니다.

이제 CSS에서는 이름표 앞에 점(`.`)을 붙여서 고릅니다.

```css
.warning {
  color: red;
}
```

사람 말로 읽으면 이렇습니다.

> **“warning이라는 이름표가 붙은 요소만 골라서 글자색을 빨갛게 해라.”**

여기에서 중요한 것은 `warning`이라는 영어 단어의 뜻이 아닙니다. 컴퓨터는 “warning이면 경고니까 알아서 빨갛게 해야지”라고 생각하지 않습니다.

우리가 HTML에서 `warning`이라는 이름표를 붙였고, CSS에서도 정확히 같은 이름인 `.warning`을 찾으라고 적었기 때문에 연결되는 것입니다.

예를 들어 HTML은 `warning`인데 CSS를 이렇게 쓰면,

```css
.warn {
  color: red;
}
```

아무 일도 일어나지 않을 수 있습니다. `warning`과 `warn`은 사람 눈에는 비슷해 보여도 컴퓨터에게는 **서로 다른 이름**입니다.

### `#`은 또 무엇일까?

가끔 이런 코드도 보게 됩니다.

```html
<form id="record-form">
```

```css
#record-form {
  background: white;
}
```

`id`도 이름표처럼 대상을 알아보게 해 주는 표시입니다. 초보 단계에서는 이렇게 구별하면 충분합니다.

- `class="warning"` → 같은 종류 여러 곳에 붙일 수 있는 이름표
- `id="record-form"` → 보통 한 페이지에서 특정 하나를 구별할 때 쓰는 이름표
- CSS에서 class를 찾을 때 → 앞에 `.`
- CSS에서 id를 찾을 때 → 앞에 `#`

지금 당장 어떤 경우에 class와 id를 완벽하게 골라야 하는 것은 아닙니다. **점이 붙으면 class 이름표를 찾는구나, 샵(#)이 붙으면 id 이름표를 찾는구나** 정도부터 익히면 됩니다.

### 연습 4-2. 이름표가 왜 연결되지 않았을까?

HTML에는 이렇게 적혀 있습니다.

```html
<p class="warning">시간을 확인해 주세요.</p>
```

그런데 CSS는 이렇게 적었습니다.

```css
.warn {
  color: red;
}
```

글자가 빨갛게 바뀌지 않았습니다. 가장 먼저 어디를 확인해야 할까요?

### 풀이 4-2

HTML의 이름표는 `warning`이고 CSS에서 찾는 이름표는 `warn`입니다. 서로 다릅니다.

CSS를 다음처럼 고치면 연결됩니다.

```css
.warning {
  color: red;
}
```

이 문제에서 중요한 습관은 **“안 되니까 더 센 명령을 넣자”가 아니라 “내가 고른 대상이 진짜 맞나?”부터 확인하는 것**입니다.

## 4.3 글자 크기와 색을 바꾸는 가장 기본적인 네 가지

CSS에는 정말 많은 기능이 있습니다. 하지만 처음부터 수십 개를 외울 필요는 없습니다. 우선 눈에 바로 보이는 네 가지만 익혀 보겠습니다.

```css
body {
  color: #222222;
  background: #f5f5f5;
  font-size: 18px;
  line-height: 1.7;
}
```

여기서 `body`는 웹페이지의 큰 몸통 부분이라고 생각하면 됩니다. 보통 화면에 보이는 내용 대부분이 이 안에 들어갑니다.

이제 하나씩 사람 말로 바꿔 보겠습니다.

### `color` — 글자색

```css
color: #222222;
```

`color`는 여기에서 **글자의 색**입니다.

`#222222` 같은 표시는 색을 숫자와 문자로 적는 한 가지 방법입니다. 처음 보면 암호처럼 보이지만 외울 필요 없습니다. 색상 선택 도구나 AI가 이런 값을 만들어 줄 수 있습니다.

초보자에게 더 중요한 것은 **`color`가 글자색이라는 것**입니다.

### `background` — 뒤쪽 바탕색

```css
background: #f5f5f5;
```

`background`는 **배경**, 즉 뒤에 깔리는 색이나 그림을 뜻합니다.

예를 들어 글자는 검은색이고 배경은 아주 밝은 회색으로 할 수 있습니다.

### `font-size` — 글자 크기

```css
font-size: 18px;
```

`font-size`는 말 그대로 **글자 크기**입니다.

여기서 `px`라는 단위가 나옵니다. `px`는 웹 화면의 길이나 크기를 정할 때 많이 쓰는 단위입니다. 처음에는 다음 정도로 생각해도 됩니다.

- `14px` → 비교적 작은 글자
- `18px` → 조금 더 읽기 편한 글자
- `24px` → 더 큰 글자

기기에 따라 실제로 느껴지는 크기는 달라질 수 있기 때문에 “18px은 무조건 실제 자로 몇 mm다”라고 외우지는 않습니다.

### `line-height` — 줄과 줄 사이의 숨 쉴 공간

```css
line-height: 1.7;
```

`line-height`는 글 한 줄이 차지하는 높이를 정하는 데 쓰입니다.

어렵게 생각하지 말고 **“줄 사이를 너무 붙이지 않도록 숨 쉴 공간을 준다”**고 생각하면 됩니다.

예를 들어 이런 글이 있다고 합시다.

> 오늘은 CSS를 배웠습니다.  
> 글자색과 크기를 바꿨습니다.  
> 이름표로 원하는 부분만 골랐습니다.

줄 사이가 너무 붙으면 읽기 힘듭니다. 그래서 본문에서는 적당한 `line-height`가 읽기 편하게 만드는 데 도움이 됩니다.

### 한꺼번에 읽어 보기

```css
body {
  color: #222222;
  background: #f5f5f5;
  font-size: 18px;
  line-height: 1.7;
}
```

이제 이 코드를 이렇게 읽을 수 있습니다.

> “페이지의 기본 글자는 어두운 색으로, 배경은 밝게, 글자는 18px 정도로, 줄 사이는 넉넉하게 해라.”

이렇게 읽을 수 있으면 충분합니다.

### `rem`이라는 단위는 지금 외워야 할까?

나중에 이런 코드도 보게 됩니다.

```css
h1 {
  font-size: 2rem;
}
```

`rem`도 크기를 나타내는 단위입니다. 다만 기준이 고정 숫자 하나가 아니라 **페이지의 기본 글자 크기를 기준으로 배수처럼 계산되는 단위**입니다.

예를 들어 기본 글자 크기가 16px인 상황에서 `2rem`은 보통 32px에 해당합니다.

하지만 지금 이 계산을 외울 필요는 없습니다. 지금은 다음만 기억하세요.

> **px도 크기 단위이고, rem도 크기 단위다. rem은 기본 글자 크기를 기준으로 움직인다.**

실제로 코드를 수정할 때 다시 찾아보면 됩니다.

### 연습 4-3. 무엇을 고쳐야 할까?

본문 글자가 너무 작고, 줄과 줄이 너무 붙어 있습니다. 다음 중 어떤 두 속성을 먼저 살펴보는 것이 좋을까요?

- `font-size`
- `line-height`
- `background`
- `color`

### 풀이 4-3

먼저 `font-size`와 `line-height`를 봅니다.

- `font-size` → 글자 자체의 크기
- `line-height` → 한 줄이 차지하는 높이, 즉 줄 사이의 여유와 관련

배경색과 글자색도 읽기 쉬움에 영향을 주지만, 문제에서 말한 “글자가 작다”와 “줄이 붙었다”에 가장 직접적으로 연결된 것은 위 두 가지입니다.

## 4.4 부모에게 준 글자색을 안쪽 글자가 따라가는 이유

이제 조금 더 신기한 현상을 보겠습니다.

HTML이 이렇게 생겼다고 합시다.

```html
<div class="card">
  <h2>오늘의 공부</h2>
  <p>CSS 30분</p>
</div>
```

`div` 안에 `h2`와 `p`가 들어 있습니다.

상자 안에 다른 상자가 들어 있는 모양을 생각해 보면 됩니다.

- 바깥 상자 → `div class="card"`
- 안쪽 제목 → `h2`
- 안쪽 문단 → `p`

웹에서는 바깥쪽 요소와 안쪽 요소의 관계를 말할 때 **부모(parent)**와 **자식(child)**이라는 표현을 자주 씁니다.

이 말도 가족 이야기를 하려는 것이 아닙니다. 단순히 **“바깥에 감싸고 있는 쪽”과 “그 안에 들어 있는 쪽”**을 구별하는 이름입니다.

이제 CSS를 이렇게 적어 보겠습니다.

```css
.card {
  color: darkgreen;
}
```

그러면 안쪽의 `h2`와 `p` 글자도 초록색 계열로 보일 수 있습니다.

왜 그럴까요?

일부 CSS 속성은 바깥 요소에 정해 두면 안쪽 요소가 그 값을 이어받습니다. 이 현상을 **상속(inheritance)**이라고 부릅니다.

상속이라는 어려운 단어를 먼저 외우지 말고 이렇게 생각하세요.

> **“부모 상자에 기본 글자색을 정했더니 안쪽 글자도 그 기본값을 따라갔다.”**

이 현상의 이름이 상속입니다.

하지만 **모든 것이 다 상속되는 것은 아닙니다.**

예를 들어 바깥 상자에 테두리를 그렸다고 해서 안쪽의 제목과 문단 각각에 테두리가 자동으로 생기지는 않습니다.

```css
.card {
  color: darkgreen;
  border: 1px solid gray;
}
```

여기서는 `.card`라는 바깥 상자에 테두리가 하나 생깁니다. 안쪽의 `h2`, `p`가 각각 테두리를 하나씩 물려받는 것은 아닙니다.

처음에는 이 정도만 기억하면 충분합니다.

- 글자색, 글꼴 같은 일부 값 → 안쪽 요소가 따라갈 수 있음
- 테두리, 여백 같은 많은 값 → 똑같이 자동 전달되지 않음

### 버튼 글꼴이 혼자 다르게 보이는 경우

가끔 본문 글꼴을 바꿨는데 버튼 글자는 다른 글꼴처럼 보일 수 있습니다.

```css
body {
  font-family: Arial, sans-serif;
}
```

브라우저가 버튼이나 입력칸에 자기 기본 스타일을 갖고 있을 수 있기 때문입니다. 이럴 때 다음처럼 주변 글꼴을 따라가게 할 수 있습니다.

```css
button,
input {
  font: inherit;
}
```

`inherit`는 **“위에서 정한 값을 이어받아라”**라는 뜻입니다.

이 코드도 외우기보다 뜻을 읽어 보세요.

> “버튼과 입력칸의 글꼴 설정은 바깥쪽에서 정한 것을 따라가라.”

### 연습 4-4. 상속은 모든 것을 복사할까?

다음 코드가 있습니다.

```css
.card {
  color: blue;
  border: 2px solid black;
}
```

`.card` 안에 제목과 문단이 있습니다. 제목과 문단의 글자가 파란색이 될 수 있다고 해서, 제목과 문단 각각에 검은 테두리도 자동으로 생긴다고 생각해도 될까요?

### 풀이 4-4

그렇게 생각하면 안 됩니다.

CSS에는 안쪽 요소가 이어받는 속성과 그렇지 않은 속성이 있습니다. 글자색은 상속되는 대표적인 속성이고, 테두리는 보통 부모의 테두리가 자식마다 똑같이 복제되는 식으로 작동하지 않습니다.

그러므로 **“부모에 썼으니 자식에게 전부 그대로 복사된다”**라고 외우면 안 됩니다.

## 4.5 같은 글자에 서로 다른 명령이 두 개 오면 누가 이길까?

이제 CSS에서 초보자가 자주 만나는 상황을 보겠습니다.

HTML이 이렇게 있습니다.

```html
<p class="message">저장이 완료되었습니다.</p>
```

CSS는 이렇게 적었습니다.

```css
p {
  color: red;
}

.message {
  color: blue;
}
```

한 문장에 빨간색 명령과 파란색 명령이 동시에 걸린 것처럼 보입니다.

브라우저는 둘 중 하나를 골라야 합니다.

이걸 이해하기 위해 사람에게 하는 지시를 생각해 봅시다.

> “모든 직원은 흰 셔츠를 입으세요.”

그리고 이어서

> “영업팀 직원은 파란 셔츠를 입으세요.”

라고 했다고 합시다.

두 번째 말은 **대상을 더 딱 집어서 말했습니다.** “모든 직원”보다 “영업팀 직원”이 더 구체적입니다.

CSS에도 비슷한 생각이 있습니다.

`p`는 모든 문단을 넓게 고릅니다.

`.message`는 `message`라는 이름표가 붙은 것만 더 좁게 고릅니다.

이렇게 **얼마나 딱 집어서 고르는가**를 개발자들은 **구체성(specificity)**이라고 부릅니다.

어려운 단어지만 뜻은 간단합니다.

> **구체성 = 얼마나 구체적으로 대상을 찍어서 말했는가**

위 예제에서는 `.message`가 `p`보다 더 구체적으로 고르기 때문에 파란색 규칙이 적용되는 상황이 생깁니다.

### “아래에 쓴 것이 무조건 이긴다”는 말이 왜 위험할까?

이런 코드가 있다고 합시다.

```css
.message {
  color: blue;
}

p {
  color: red;
}
```

빨간색 규칙이 더 아래에 있다고 해서 항상 빨간색이 되는 것은 아닙니다. 어떤 대상을 얼마나 구체적으로 골랐는지도 봐야 합니다.

반대로 다음처럼 **똑같은 정도로 고른 규칙**이 두 번 나오면,

```css
.message {
  color: blue;
}

.message {
  color: red;
}
```

이런 단순한 상황에서는 뒤에 나온 빨간색 규칙이 적용됩니다.

CSS에는 이런 규칙이 겹쳤을 때 최종 결과를 정하는 전체 방식이 있습니다. 이를 **캐스케이드(cascade)**라고 부릅니다.

이 단어도 지금 깊게 외울 필요 없습니다.

> **캐스케이드 = CSS 규칙이 여러 개 겹쳤을 때 최종적으로 무엇을 적용할지 정하는 전체 규칙**

정도로 이해하면 됩니다.

나중에는 규칙이 어디에서 왔는지, `!important`가 있는지, 별도 계층이 있는지 등 더 많은 조건을 배우게 됩니다. 하지만 생기초 단계에서는 먼저 아래 순서로 확인하면 됩니다.

1. 내가 진짜 원하는 대상을 골랐는가?
2. 같은 대상에 다른 CSS가 또 걸려 있는가?
3. 더 구체적인 규칙이 있는가?
4. 비슷한 조건이라면 더 뒤의 규칙이 적용되는가?

### `!important`는 만능 버튼이 아니다

검색하다 보면 이런 코드를 볼 수 있습니다.

```css
color: red !important;
```

초보자는 “안 되면 `!important` 붙이면 되는구나”라고 생각하기 쉽습니다.

하지만 이렇게 강한 규칙을 여기저기 계속 붙이면 나중에는 무엇이 왜 적용되는지 더 알아보기 어려워질 수 있습니다.

처음에는 `!important`로 밀어붙이기보다 **대상을 제대로 골랐는지, 다른 규칙이 겹쳤는지 먼저 확인하는 습관**이 좋습니다.

### 연습 4-5. 왜 파란색일까?

다음 코드에서 글자가 파란색으로 보인다고 합시다.

```html
<p class="message">확인해 주세요.</p>
```

```css
.message {
  color: blue;
}

p {
  color: red;
}
```

왜 맨 아래의 `p { color: red; }`가 무조건 이기지 않는지 쉬운 말로 설명해 보세요.

### 풀이 4-5

`p`는 모든 문단을 넓게 고르고, `.message`는 `message`라는 이름표가 붙은 문단을 더 구체적으로 고릅니다.

이 예제처럼 다른 중요한 조건이 같다면 `.message` 쪽이 더 구체적으로 대상을 지정했기 때문에 파란색 규칙이 적용될 수 있습니다.

핵심은 **“맨 아래가 무조건 이긴다”가 아니라 “먼저 누가 더 정확하게 대상을 골랐는지 봐야 한다”**는 것입니다.

## 4.6 CSS 파일을 만들었는데 왜 아무 변화가 없을까?

이제 아주 현실적인 문제를 보겠습니다.

`style.css`라는 파일에 열심히 CSS를 적었습니다.

```css
body {
  background: beige;
}
```

그런데 웹페이지를 열어 보니 아무 변화가 없습니다.

코드가 틀린 걸까요?

그럴 수도 있지만, 먼저 더 간단한 것을 확인해야 합니다.

**HTML이 CSS 파일을 실제로 불러오고 있는지** 봐야 합니다.

보통 HTML의 `head` 안에 이런 코드가 있습니다.

```html
<link rel="stylesheet" href="style.css">
```

이 코드를 사람 말로 바꿔 보면,

> “이 HTML 페이지에서 `style.css`라는 스타일 파일을 사용하겠다.”

라는 뜻입니다.

여기서 `href="style.css"`는 CSS 파일이 어디 있는지 알려 줍니다.

파일이 있는 위치를 가리키는 문자열을 개발자들은 **경로(path)**라고 자주 부릅니다.

**경로(path)**는 어려운 개념이 아니라 **“그 파일을 어디에서 찾을지 적은 주소”**라고 생각하면 됩니다.

예를 들어 파일 구조가 이렇게 생겼다면,

```text
my-app/
  index.html
  style.css
```

둘이 같은 폴더에 있으므로 `href="style.css"`라고 적을 수 있습니다.

그런데 실제 파일은 이렇게 들어 있다면,

```text
my-app/
  index.html
  css/
    style.css
```

`style.css`가 `css` 폴더 안에 있으므로 경로가 달라집니다.

```html
<link rel="stylesheet" href="css/style.css">
```

그래서 CSS가 전혀 먹지 않을 때는 어려운 문제부터 의심하지 말고 다음을 확인하세요.

1. CSS 파일을 만들었는가?
2. HTML에서 그 CSS 파일을 연결했는가?
3. 파일 이름이 정확히 같은가?
4. 폴더 위치에 맞는 경로를 적었는가?

### 연습 4-6. 파일은 있는데 왜 적용되지 않을까?

파일 구조가 다음과 같습니다.

```text
project/
  index.html
  styles/
    style.css
```

그런데 HTML에는 이렇게 적혀 있습니다.

```html
<link rel="stylesheet" href="style.css">
```

무엇을 고쳐야 할까요?

### 풀이 4-6

`style.css`는 `index.html`과 같은 위치에 있지 않고 `styles` 폴더 안에 있습니다.

따라서 다음처럼 적어야 합니다.

```html
<link rel="stylesheet" href="styles/style.css">
```

이 문제는 CSS 문법의 문제가 아니라 **파일을 찾는 주소가 틀린 문제**입니다.

## 4.7 이제 실제 기록장 화면에 옷을 입혀 보자

앞 장에서 만든 기록장 화면이 있다고 합시다.

```html
<h1>나의 학습 기록장</h1>

<p class="intro">오늘 공부한 내용을 남겨 보세요.</p>

<label for="topic">공부한 내용</label>
<input id="topic" type="text">

<button>기록 저장</button>
```

아직 기본 화면이라 조금 밋밋합니다.

이번 장에서 배운 것만 이용해 차근차근 바꿔 보겠습니다.

### 1단계: 페이지 전체 기본 모양 정하기

```css
body {
  color: #222222;
  background: #f6f2e9;
  font-size: 18px;
  line-height: 1.7;
}
```

사람 말로 읽으면 다음과 같습니다.

> “페이지 글자는 어두운색으로 하고, 배경은 밝은 베이지색으로 하고, 기본 글자는 너무 작지 않게 하고, 줄 사이는 조금 넉넉하게 해라.”

### 2단계: 제목만 더 크게 하기

```css
h1 {
  font-size: 32px;
}
```

`h1`은 큰 제목입니다. 여기서는 제목만 크게 만듭니다.

### 3단계: 안내 문장만 조금 다르게 하기

HTML에서 이미 `class="intro"`라는 이름표를 붙였기 때문에 이렇게 고를 수 있습니다.

```css
.intro {
  color: #555555;
}
```

이제 일반 글자보다 조금 부드러운 색으로 보이게 할 수 있습니다.

### 4단계: 버튼에 배경색 넣기

```css
button {
  color: white;
  background: #28584f;
}
```

여기서 `color`는 버튼 **안의 글자색**, `background`는 버튼 **뒤의 배경색**입니다.

이 둘을 헷갈리기 쉽습니다.

```css
button {
  color: white;
  background: #28584f;
}
```

사람 말로 읽으면,

> “버튼의 글자는 흰색, 버튼 바탕은 짙은 초록색.”

입니다.

### 5단계: 입력칸과 버튼 글꼴을 주변과 맞추기

```css
input,
button {
  font: inherit;
}
```

`input, button`처럼 쉼표로 나열하면 **input에도 적용하고 button에도 적용하라**는 뜻입니다.

`font: inherit`는 앞에서 설명했듯이 바깥의 글꼴 설정을 따라가라는 뜻입니다.

이제 전체 CSS를 한 번에 보겠습니다.

```css
body {
  color: #222222;
  background: #f6f2e9;
  font-size: 18px;
  line-height: 1.7;
}

h1 {
  font-size: 32px;
}

.intro {
  color: #555555;
}

input,
button {
  font: inherit;
}

button {
  color: white;
  background: #28584f;
}
```

처음 봤을 때는 길어 보이지만 한 줄씩 사람 말로 읽으면 전부 이미 배운 내용입니다.

- `body` → 페이지 전체 기본 모양
- `h1` → 큰 제목
- `.intro` → intro 이름표가 붙은 안내 문장
- `input, button` → 입력칸과 버튼
- `button` → 버튼만 따로 추가 꾸미기

### 연습 4-7. 버튼이 이상하게 안 보인다

다음 CSS가 있습니다.

```css
button {
  color: #222222;
  background: #222222;
}
```

버튼의 글자가 거의 안 보입니다. 왜 그런지 설명하고, 어떤 식으로 고칠 수 있을지 말해 보세요.

### 풀이 4-7

글자색(`color`)과 배경색(`background`)이 둘 다 거의 같은 어두운 색이기 때문입니다.

글자와 배경이 충분히 구별되어야 읽을 수 있습니다. 예를 들어 다음처럼 바꿀 수 있습니다.

```css
button {
  color: white;
  background: #222222;
}
```

중요한 것은 “다크 모드니까 무조건 검은색을 많이 쓰면 된다”가 아닙니다. **글자와 배경이 서로 구별되어 읽히는지**를 함께 봐야 합니다.

## 4.8 CSS가 안 먹을 때는 이 순서로 확인하자

CSS가 적용되지 않으면 초보자는 코드 전체를 뜯어고치고 싶어집니다. 하지만 실제로는 작은 실수 하나인 경우가 많습니다.

다음 순서로 확인하면 문제 범위를 줄이기 쉽습니다.

### 1. CSS 파일이 연결되어 있는가?

HTML에 다음과 같은 연결 코드가 있는지 봅니다.

```html
<link rel="stylesheet" href="style.css">
```

### 2. 파일 이름과 위치가 맞는가?

실제 파일이 `style.css`인지, `styles.css`인지 확인합니다.

사람 눈에는 비슷하지만 컴퓨터는 다른 이름으로 봅니다.

### 3. 내가 꾸미려는 대상을 제대로 골랐는가?

HTML이 이렇게 되어 있는데,

```html
<p class="warning">주의</p>
```

CSS가 이렇게 되어 있다면,

```css
.warn {
  color: red;
}
```

대상을 못 찾습니다.

### 4. 속성 이름을 잘못 적지는 않았는가?

예를 들어,

```css
font-szie: 20px;
```

처럼 철자가 틀리면 브라우저가 그 줄을 제대로 적용하지 못할 수 있습니다.

정확한 이름은 `font-size`입니다.

### 5. 다른 규칙이 덮고 있지는 않은가?

같은 요소에 여러 CSS 규칙이 걸려 있으면 우리가 생각한 것과 다른 규칙이 적용될 수 있습니다.

이때 앞에서 배운 **구체성**과 **규칙의 순서**를 확인합니다.

### 6. 한 번에 하나씩 고친다

이게 매우 중요합니다.

CSS가 안 된다고 다섯 군데를 동시에 바꾸면 무엇 때문에 해결됐는지 알기 어렵습니다.

예를 들어 다음처럼 해 보세요.

1. class 이름 하나 고침
2. 다시 확인
3. 아직 안 되면 파일 경로 확인
4. 다시 확인
5. 그래도 안 되면 겹친 규칙 확인

하나씩 확인하면 원인을 배우게 됩니다.

### 개발자 도구라는 것도 있다

PC 브라우저에는 웹페이지가 실제로 어떤 CSS를 적용받고 있는지 살펴볼 수 있는 **개발자 도구(Developer Tools)**가 있습니다.

지금 이 장에서는 사용법을 외울 필요 없습니다. 의미만 알아 두세요.

나중에 디버깅 장에서 다시 사용합니다.

## 4.9 어려운 용어를 다시 쉬운 말로 정리하기

이번 장에서 전문용어가 몇 개 나왔습니다. 용어부터 외우지 말고 **뜻을 먼저 기억한 뒤 이름을 붙여** 봅시다.

| 전문용어 | 쉬운 뜻 |
|---|---|
| CSS | 웹페이지의 모양을 정하는 꾸미기 규칙 |
| 선택자(selector) | 누구를 바꿀지 고르는 부분 |
| 속성(property) | 무엇을 바꿀지 적는 이름 |
| 값(value) | 어떻게 바꿀지 적는 내용 |
| class | 여러 요소에 붙일 수 있는 분류 이름표 |
| id | 특정 요소를 구별하기 위한 이름표 |
| 상속(inheritance) | 바깥 요소의 일부 꾸미기 값을 안쪽 요소가 이어받는 현상 |
| 구체성(specificity) | 대상을 얼마나 딱 집어서 고르는지 |
| 캐스케이드(cascade) | 여러 CSS 규칙이 겹칠 때 최종 결과를 정하는 전체 방식 |
| 경로(path) | 파일을 어디에서 찾을지 적은 주소 |

이 표를 한 번에 암기할 필요는 없습니다.

예를 들어 `선택자`라는 말을 잊어버렸어도,

> “아, 맨 앞에서 누구를 바꿀지 고르는 부분 말이지?”

라고 이해하면 이미 중요한 부분은 알고 있는 것입니다.
