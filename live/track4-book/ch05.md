# 5장. 박스·Flexbox·Grid로 화면 배치하기

글자의 색과 크기를 바꾸고 나면 다음 문제가 나타납니다. 입력창이 화면 밖으로 나가고, 버튼 사이가 붙어 있으며, 가운데 정렬했다고 생각한 제목이 한쪽으로 밀립니다. 이때 요소의 위치를 숫자로 조금씩 밀어 맞추면 현재 화면에서는 그럴듯해 보일 수 있습니다. 그러나 화면 너비가 바뀌거나 문장이 길어지면 다시 무너집니다.

배치를 안정적으로 다루려면 브라우저가 각 요소의 공간을 어떻게 계산하는지 이해해야 합니다. 이 장에서는 먼저 요소를 둘러싼 박스를 읽습니다. 그다음 기본 배치 흐름을 보고, 한 방향으로 놓는 Flexbox와 행·열을 다루는 Grid를 연결합니다. 세 가지를 한꺼번에 외우는 것이 아니라 같은 기록장이 왜 밀려나는지 설명하는 도구로 차례로 사용하겠습니다.

## 5.1 글자 주위에는 서로 다른 공간이 있다

입력창이나 문단에는 내용이 들어가는 영역이 있습니다. 그 바깥으로 안쪽 여백인 padding, 테두리인 border, 바깥 간격인 margin을 생각할 수 있습니다. 이 관계를 박스 모델이라고 부릅니다. 이름은 모두 공간과 관련되지만 위치와 역할이 다릅니다.[1][2][4][5]

```text
바깥 간격 margin
  테두리 border
    안쪽 여백 padding
      내용 content
    안쪽 여백 padding
  테두리 border
바깥 간격 margin
```

버튼 안의 글자와 테두리가 너무 가까우면 안쪽 여백을 늘릴 수 있습니다. 버튼과 옆 버튼이 붙어 있으면 요소 사이 간격을 조정해야 합니다. 이때 padding만 늘리면 버튼 자체가 커지지만 두 버튼 사이의 목적한 간격과는 다르게 느껴질 수 있습니다. ‘무언가를 떨어뜨린다’라는 말만으로 두 속성을 같은 것으로 생각하지 않아야 합니다.

다음은 버튼의 일부 스타일입니다.

```css
button {
  padding: 12px 18px;
  border: 1px solid #294d43;
  margin-top: 8px;
}
```

`padding`에 두 값을 주면 첫 값은 위아래, 둘째 값은 좌우에 적용됩니다. 여기서는 글자 주위 위아래로 12px, 좌우로 18px의 안쪽 여백을 줍니다. `margin-top`은 버튼 박스 바깥의 위쪽 간격입니다. 테두리는 굵기 1px, 실선, 지정한 색입니다. 한 선언 안에 여러 값이 있는 이유는 여러 관련 속성을 짧게 쓰는 표현이기 때문입니다.

### 연습 5-1. 어느 여백을 바꿀까?

버튼끼리 충분히 떨어져 있지만 버튼 글자가 테두리에 붙어 보입니다. 반대로 다른 화면에서는 글자 주위는 넉넉한데 두 버튼이 서로 붙어 있습니다. 두 상황에서 먼저 볼 대상을 각각 정해 보세요.

### 풀이 5-1

첫 상황에서는 안쪽 여백인 padding을 먼저 봅니다. 둘째 상황에서는 버튼 사이의 간격을 봅니다. 부모가 Flexbox나 Grid라면 뒤에서 배울 `gap`을 사용할 수 있고, 상황에 맞게 margin을 쓸 수도 있습니다. 문제의 위치가 박스 안인지 박스 바깥인지 구별하는 것입니다.

두 상황을 모두 ‘버튼을 10px 키우면 된다’라고 처리하면 의도하지 않은 폭과 높이 변화가 생깁니다. 공간의 어느 부분을 바꾸는지 먼저 말로 설명하면 수정도 작아집니다.

## 5.2 width가 전체 너비라는 뜻은 아닐 수 있다

다음 코드를 보겠습니다.

```css
.entry {
  width: 240px;
  padding: 16px;
  border: 2px solid #707a84;
}
```

기본적인 `content-box` 계산에서 `width: 240px`는 내용 영역의 너비입니다. 좌우 padding 16px씩, 좌우 테두리 2px씩이 더해지므로 테두리 바깥까지의 너비는 276px이 됩니다. 계산은 `240 + 16 + 16 + 2 + 2`입니다. margin은 이 테두리 박스 바깥의 간격으로 따로 생각합니다.

‘너비를 240으로 정했는데 왜 240짜리 공간에 안 들어가지?’라는 의문은 여기서 생길 수 있습니다. 숫자를 잘못 더한 것이 아니라, width가 어느 영역을 가리키는지 다르게 생각한 것입니다. `box-sizing: border-box`를 사용하면 지정한 너비 안에 내용, padding, border가 포함되도록 계산할 수 있습니다.

```css
.entry {
  box-sizing: border-box;
  width: 240px;
  padding: 16px;
  border: 2px solid #707a84;
}
```

이 경우에는 테두리를 포함한 너비가 240px입니다. 내용 영역은 좌우 여백과 테두리를 제외한 204px입니다. padding이나 border가 사라지는 것이 아니라 그만큼 내용 공간이 줄어듭니다. 화면을 유연하게 만들 때 이 계산이 편리해 자주 사용합니다. 기록장에서는 기본값으로 다음 규칙을 두겠습니다.

```css
*, *::before, *::after {
  box-sizing: border-box;
}
```

`*`는 모든 요소를 선택합니다. `::before`, `::after`는 뒤에서 장식 등을 만들 때 사용하는 의사 요소이며, 여기서는 같은 박스 계산을 적용하기 위해 함께 적었습니다. 이 줄을 외우는 것보다 ‘너비 계산을 프로젝트 전체에서 일관되게 맞춘다’라는 의도를 이해하면 됩니다.

### 연습 5-2. 실제 너비 계산하기

내용 기준 너비가 180px이고, 좌우 padding은 각각 10px, 좌우 border는 각각 1px입니다. 기본 content-box에서는 테두리를 포함해 얼마인가요? 같은 값에 border-box를 적용하면 테두리를 포함한 너비와 내용 너비는 각각 얼마인가요?

### 풀이 5-2

content-box에서는 `180 + 10 + 10 + 1 + 1`, 즉 202px입니다. border-box에서는 테두리를 포함한 너비가 180px이고, 내용 너비는 `180 - 10 - 10 - 1 - 1`, 즉 158px입니다. margin은 이 계산에서 테두리 바깥 간격으로 따로 봅니다.

이 문제의 목적은 암산 속도가 아닙니다. width의 기준과 박스의 각 부분을 연결하는 것입니다. 눈으로 보이는 전체 폭과 코드의 숫자가 다를 때도 바로 브라우저 오류라고 판단하지 않게 됩니다.

## 5.3 기본 흐름을 이해하면 억지 배치가 줄어든다

특별한 배치 규칙을 주지 않은 문서에서 문단과 주요 구역은 보통 위에서 아래로 놓입니다. `a`나 `span` 같은 요소는 문장 안에서 이어질 수 있습니다. CSS의 block과 inline이라는 배치 성격을 여기서 만나게 됩니다. 자세한 계산은 더 복잡하지만, 처음에는 ‘새 줄을 차지하며 쌓이는가’, ‘문장 흐름 안에 이어지는가’를 구분하면 됩니다.[4]

다음처럼 label과 input에 `display: block`을 주면 각각 줄을 차지하도록 할 수 있습니다.

```css
label, input {
  display: block;
}

input {
  width: 100%;
}
```

`width: 100%`는 이 요소가 놓인 기준 공간의 너비를 사용한다는 의미로 읽을 수 있습니다. 모든 경우에서 기기 화면 전체 너비를 가리키는 것은 아닙니다. 좁은 폼 안에 있으면 그 폼의 너비를 기준으로 합니다. 앞서 border-box를 적용했다면 padding과 border 때문에 같은 이유로 더 넓어지는 문제를 줄일 수 있습니다.

margin에는 단순히 다 더해지지 않는 경우도 있습니다. 일반적인 블록 흐름에서 위아래 margin이 맞닿으면 겹침 현상이 나타날 수 있습니다. 두 문단에 각각20px 간격을 줬다고 사이가 항상40px이 되는 것은 아닙니다. 이 장에서 모든 경우를 외우지는 않겠습니다. 다만 예상보다 간격이 작다고 똑같은 margin 선언을 반복 추가하기 전에 이런 규칙이 있는지 확인할 필요가 있습니다. Flexbox와 Grid의 `gap`은 요소 사이의 간격을 명시적으로 관리할 때 편리합니다.

요소를 `position: absolute`로 놓으면 일반적인 흐름과 다른 방식으로 위치를 정할 수 있습니다. 겹치는 배지나 특정 장식에는 필요할 수 있습니다. 하지만 폼과 본문 전체를 좌표로 밀어 맞추는 기본 수단으로 사용하면 긴 글자와 작은 화면에서 겹치기 쉽습니다. 먼저 자연스러운 흐름으로 해결할 수 있는지 보는 편이 좋습니다.

### 연습 5-3. 높이를 고정해 놓은 설명문

설명 구역에 `height: 40px`를 주었습니다. 짧은 문장에서는 괜찮지만 글자 크기를 키우자 두 번째 줄이 잘립니다. 내용이 여러 줄이 될 수 있다면 어떤 방향의 수정이 적절할까요?

### 풀이 5-3

내용에 맞춰 높이가 늘어날 수 있도록 불필요한 고정 높이를 제거하는 방향을 고려합니다. 최소 높이가 필요하다면 `min-height`를 검토할 수 있습니다. 그다음 다른 요소가 자연스럽게 아래로 밀려나는지 확인합니다. 텍스트를 더 작게 강제하여40px 안에 가두는 것은 사용자가 글자를 크게 보려는 목적을 훼손할 수 있습니다.

## 5.4 Flexbox는 부모가 자식의 한 방향 배치를 맡는다

‘추가’와 ‘지우기’ 버튼을 나란히 놓고 싶습니다. 각 버튼의 왼쪽 위치를 계산하는 대신 부모에게 배치 방식을 줄 수 있습니다.

```html
<div class="actions">
  <button type="button">기록 추가</button>
  <button type="button">입력 지우기</button>
</div>
```

```css
.actions {
  display: flex;
  gap: 12px;
  flex-wrap: wrap;
  align-items: center;
}
```

`display: flex`는 이 부모의 직접 자식들을 Flexbox로 배치하도록 합니다. 자식 버튼마다 `display: flex`를 붙여야 형제 버튼들이 나란히 되는 것은 아닙니다. 배치를 책임지는 부모와 배치되는 자식을 구별하는 것이 첫 번째 요점입니다.

기본적인 행 방향에서는 자식이 가로로 이어집니다. `gap`은 항목 사이의 간격입니다. `flex-wrap: wrap`은 공간이 부족할 때 다음 줄로 넘어갈 수 있도록 합니다. `align-items: center`는 교차 방향에서 항목을 가운데 맞춥니다. ‘교차 방향’이라는 말은 주된 배치 방향과 직각인 방향이라는 뜻입니다.

`flex-direction: row`라면 이 예제의 주축은 가로, 교차축은 세로입니다. `column`으로 바꾸면 주축은 세로가 됩니다. 따라서 `justify-content`는 무조건 가로 정렬이고 `align-items`는 무조건 세로 정렬이라고 외우지 않아야 합니다. 주축이 바뀌면 두 속성을 읽는 방향도 함께 바뀝니다.[3][5]

```css
.actions {
  display: flex;
  flex-direction: column;
  align-items: stretch;
  gap: 12px;
}
```

이렇게 바꾸면 버튼이 세로로 놓이는 구성을 만들 수 있습니다. 같은 HTML을 유지하고 배치 규칙만 바꾼 것입니다. 다만 CSS로 화면 순서만 뒤집으면 키보드 이동이나 문서 읽기 순서와 시각적 순서가 달라질 수 있습니다. 의미 있는 순서 자체는 HTML에서 먼저 맞추는 편이 이해하기 쉽습니다.

### 연습 5-4. 부모인가 자식인가?

버튼 두 개를 나란히 놓으려고 각 버튼에 `display: flex`를 주었지만 버튼끼리의 배치가 기대와 다릅니다. 먼저 어느 요소에 규칙을 주어야 할까요?

### 풀이 5-4

두 버튼을 직접 자식으로 가진 공통 부모에 `display: flex`를 줍니다. 각 버튼 내부의 글자나 아이콘을 정렬하는 일과 버튼 두 개의 관계를 정렬하는 일은 다릅니다. 둘 다 Flexbox를 사용할 수 있지만 적용할 부모가 달라집니다.

이 구별은 Grid에도 이어집니다. CSS 규칙의 이름만 알면 되는 것이 아니라, 어떤 관계의 부모에게 적용하는지 알아야 합니다.

## 5.5 Grid는 행과 열의 관계를 드러낸다

기록장에 공부한 내용 입력과 시간 입력을 두 칸으로 나란히 놓으려 합니다. 한 칸은 넓게, 다른 칸은 좁게 두는 구성을 생각할 수 있습니다. 이때 Grid의 열 정의를 사용할 수 있습니다.

```css
.fields {
  display: grid;
  grid-template-columns: minmax(0, 2fr) minmax(0, 1fr);
  gap: 16px;
}
```

`grid-template-columns`는 열 구성을 정합니다. 이 예제에서는 사용할 수 있는 공간을 두 부분과 한 부분 비율로 나눕니다. `fr`은 Grid의 남는 공간을 비율로 나누는 단위입니다. 단순히 전체 화면의 절대 비율이라고 생각하기보다 Grid 안에서 간격과 제약을 고려한 남는 공간을 나누는 것으로 읽습니다.

`minmax(0, 2fr)`는 최소를0으로 두고 나머지 공간에서2비율을 사용하도록 하는 표현입니다. 왜0이 등장하는지 의아할 수 있습니다. 긴 내용이 칸을 줄어들지 못하게 하여 넘치는 경우가 있어서, 이 예제에서는 줄어들 수 있는 최소를 명시한 것입니다. 그렇다고 이 줄이 어떤 긴 콘텐츠도 무조건 잘 처리해 주는 만능 해결책은 아닙니다. 내부 텍스트의 줄바꿈과 입력의 폭도 함께 확인해야 합니다.

Flexbox와 Grid 중 하나가 항상 더 좋은 것은 아닙니다. 버튼 몇 개를 한 방향으로 놓을 때는 Flexbox가 간단하고, 행과 열을 분명하게 정할 때는 Grid가 읽기 쉬울 수 있습니다. 기록장에서는 입력 구역에 Grid, 버튼 묶음에 Flexbox를 사용할 수 있습니다. 서로 경쟁해서 하나만 선택해야 하는 도구가 아닙니다.

### 연습 5-5. 도구를 목적에 맞춰 고르기

A구역은 버튼 세 개를 내용 길이에 맞춰 나란히 놓되 좁아지면 줄을 바꾸려 합니다. B구역은 통계 네 개를 두 행·두 열로 배치하려 합니다. 어떤 도구를 먼저 고려할지와 이유를 적어 보세요.

### 풀이 5-5

A에서는 Flexbox와 줄바꿈을 먼저 고려할 수 있습니다. 한 방향의 항목 흐름을 다루기 때문입니다. B에서는 Grid로 두 열을 정하는 방식을 먼저 고려할 수 있습니다. 행과 열의 관계를 드러내기 쉽기 때문입니다. 다른 방식으로 구현할 수 없다는 뜻은 아닙니다. 읽고 수정할 때 의도가 잘 보이는 구조를 고르는 연습입니다.

## 5.6 기록장의 폭과 간격을 한 번에 연결하기

다음은 기존 스타일에 더할 수 있는 배치 규칙입니다. `main`은 화면의 주된 내용이고, `.fields`는 입력 묶음, `.actions`는 버튼 묶음이라는 HTML 관계가 준비되어 있어야 합니다. 클래스가 없는 문서에 CSS만 추가해도 자동으로 그 묶음이 생기지는 않습니다.

```css
main {
  width: min(100% - 32px, 720px);
  margin: 24px auto;
}

.fields {
  display: grid;
  grid-template-columns: 1fr;
  gap: 16px;
}

.field {
  min-width: 0;
}

label {
  display: block;
  margin-bottom: 6px;
}

input {
  display: block;
  width: 100%;
  padding: 10px 12px;
  border: 1px solid #7e8790;
  border-radius: 8px;
}

.actions {
  display: flex;
  flex-wrap: wrap;
  gap: 12px;
  margin-top: 18px;
}
```

`min(100% - 32px, 720px)`는 사용 가능한 너비에서32px을 뺀 값과720px 중 더 작은 것을 선택합니다. 넓은 화면에서도 본문이 끝없이 퍼지지 않게 하고, 좁은 화면에서는 양옆에 공간을 남기려는 의도입니다. `margin`의 좌우 값을 `auto`로 주면 이처럼 폭이 제한된 블록을 수평으로 가운데 놓는 데 사용할 수 있습니다.

입력 구역은 우선 한 열로 둡니다. 좁은 화면에서도 기본적으로 읽을 수 있는 배치부터 만드는 것입니다. 다음 장에서 공간이 충분할 때 두 열로 바꾸겠습니다. 처음부터 태블릿의 넓은 화면만 기준으로 만들고 휴대폰에서 글자를 억지로 줄이는 순서를 피하려는 설계입니다.

### 연습 5-6. 세 개의 숫자를 설명하기

위 코드의 `32px`, `720px`, `gap: 16px`는 각각 어떤 공간과 관련되나요? 셋 다 ‘여백’이라고만 답하지 말고 기준을 구별해 보세요.

### 풀이 5-6

32px은 main의 유연한 너비를 계산할 때 기준 공간에서 빼는 양입니다. 좌우에 남길 총 공간의 의도와 연결됩니다. 720px은 main이 지나치게 넓어지지 않도록 하는 상한입니다. 16px은 입력 Grid의 항목 사이 간격입니다. 같은 길이 단위라도 적용되는 대상과 관계가 다릅니다.

레이아웃을 읽는다는 것은 좌표 숫자를 외우는 것이 아닙니다. 요소가 누구 안에 있고, 그 부모가 어떤 배치 규칙을 가지고 있으며, 자식의 내용이 늘어날 때 어느 공간이 변하는지 설명하는 것입니다. 다음 장에서는 이 구조를 화면 크기와 글자 크기가 바뀌는 상황에 놓아 보겠습니다.
