# 8장. 버튼을 누르면 무슨 일이 생길까? — DOM과 이벤트

JavaScript로 숫자를 더하고 배열을 읽는 법을 배웠습니다. 이제 공부 시간을 입력하고 추가 버튼을 누르면 실제 화면에 기록이 나타나게 만들 차례입니다. 여기에는 세 가지 연결이 필요합니다. 어떤 화면 요소를 사용할지 찾고, 어느 행동이 일어났을 때 실행할지 정하고, 그 순간의 값을 읽어 결과를 화면에 넣어야 합니다.

‘버튼을 누르면 실행한다’라는 말은 짧지만, 처음 배우는 사람에게는 많은 단계가 생략되어 있습니다. 함수를 만들기만 하면 되는지, 괄호를 붙여야 하는지, 사용자가 나중에 적을 값을 지금 읽어도 되는지 모두 다릅니다. 이 장에서는 단순한 클릭부터 시작해 폼 제출로 넘어가면서 그 시간 관계를 풀어 보겠습니다.

## 8.1 DOM은 HTML 문자열 자체와 다르다

브라우저가 HTML을 읽으면 문서를 프로그램으로 다룰 수 있는 구조를 만듭니다. 이를 DOM이라고 부릅니다. Document Object Model의 줄임말이지만, 지금은 ‘브라우저가 문서의 각 요소를 찾아 읽고 바꿀 수 있도록 만든 구조’라고 이해하면 됩니다. HTML 원문을 읽는 것과 그 원문으로 만들어진 요소를 JavaScript에서 다루는 것을 연결하는 개념입니다.[1][2][3]

다음 HTML이 있다고 합시다.

```html
<p id="status">아직 기록이 없습니다.</p>
```

JavaScript에서 이 문단을 찾을 수 있습니다.

```javascript
const status = document.querySelector("#status");
status.textContent = "첫 기록을 작성했습니다.";
```

`document`는 현재 문서를 다루는 대상으로 생각할 수 있습니다. `querySelector`는 선택자와 일치하는 첫 요소를 찾는 기능입니다. `"#status"`는 id가 status인 요소를 찾겠다는 문자열입니다. CSS에서 id 앞에#을 붙였던 표기와 연결됩니다.

첫 줄을 실행한 뒤 status에는 ‘아직 기록이 없습니다’라는 글자 자체가 들어가는 것이 아닙니다. 그 문단 요소를 다룰 수 있는 값이 들어갑니다. 둘째 줄의 `textContent`에 새 문자열을 대입하면 그 요소의 텍스트 내용이 바뀝니다. 변수 이름status, 선택자문자열#status, HTML의 id값status가 예제에서 비슷하게 쓰였지만, 각각 다른 자리에 있다는 점을 구별해야 합니다.

```javascript
const messageElement = document.querySelector("#status");
messageElement.textContent = "다른 변수 이름으로도 같은 요소를 바꿉니다.";
```

이렇게 변수 이름을 바꿔도 같은 선택자를 사용하면 같은 요소를 찾습니다. 반대로 변수 이름을 status라고 해 놓고 선택자에 `#other`를 적으면 다른 대상을 찾습니다. 컴퓨터는 변수 이름의 뜻이 아니라 실제 코드의 연결을 따릅니다.

### 연습 8-1. 무엇이 변수에 들어 있을까?

`const title = document.querySelector("#page-title");`를 실행했습니다. title에 들어 있는 것은 제목 글자 자체일까요, 제목 요소를 다룰 수 있는 값일까요? 글자를 읽으려면 무엇을 더 확인해야 할까요?

### 풀이 8-1

선택한 요소를 다룰 수 있는 값입니다. 제목의 텍스트를 읽으려면 `title.textContent`를 볼 수 있습니다. 선택에 실패하면 title은 null일 수 있으므로, 대상이 실제로 있는지도 확인해야 합니다. 선택하는 기능과 그 요소에서 어떤 속성을 읽는 기능은 별개입니다.

## 8.2 찾지 못했다는 결과도 값이다

선택자가 맞지 않으면 `querySelector`는 null을 돌려줄 수 있습니다. 없는 요소의 textContent를 바꾸려 하면 오류가 생깁니다. 이런 상황에서 무조건 `textContent`라는 기능이 잘못됐다고 결론 내리면 원인을 놓칩니다.

```javascript
const status = document.querySelector("#status");
if (status !== null) {
  status.textContent = "요소를 찾았습니다.";
}
```

이 코드는 요소가 있는지 검사한 뒤 바꿉니다. 다만 필요한 요소를 못 찾았는데 아무 말 없이 넘어가기만 하는 것도 좋은 최종 해결이 아닐 수 있습니다. 반드시 있어야 할 문단이라면 id 철자, 실제 HTML, 스크립트 실행 시점을 확인해야 합니다. 오류를 감추는 것과 원인을 고치는 것은 다릅니다.

외부 일반 스크립트를 HTML의 head에서 연결할 때 `defer`를 쓰는 이유가 여기서 나타납니다. 문서의 요소가 준비되기 전에 스크립트가 실행되면 아직 없는 요소를 찾을 수 있습니다. 이 책의 파일 분리 예제에서는 다음 연결을 유지합니다.

```html
<script src="app.js" defer></script>
```

다른 방법으로 script를 필요한 HTML 뒤쪽에 놓을 수도 있습니다. 어떤 방법을 사용하든 ‘찾으려는 요소가 만들어진 뒤 실행되는가’라는 조건을 이해하는 것이 중요합니다. 잘못된 id를 고치지 않은 채 defer만 붙이는 것은 해결이 아니고, 실행 시점이 문제인데 id 이름만 계속 바꾸는 것도 해결이 아닙니다.

### 연습 8-2. null 오류의 후보 나누기

`Cannot set properties of null` 같은 오류를 만났습니다. 필요한 문단을 선택해 글자를 바꾸는 코드입니다. 가능한 원인 두 가지와 확인할 위치를 적어 보세요.

### 풀이 8-2

선택자와 HTML의 id가 일치하지 않을 수 있으므로 두 문자열을 대조합니다. 또는 요소가 만들어지기 전에 실행됐을 수 있으므로 script 위치와 로딩 방식을 확인합니다. 실제로 다른 HTML 파일을 열고 있는 경우도 있습니다. 오류 문장에 나온 마지막 속성만 보지 말고 그 왼쪽 대상이 어떻게 만들어졌는지 따라가야 합니다.

## 8.3 지금 실행하는 함수와 나중에 실행하도록 맡기는 함수

다음은 버튼을 누를 때 문구를 바꾸는 전체 문서입니다. 아래 script는 버튼과 문단을 적은 뒤에 있으므로 앞의 요소를 찾을 수 있습니다.

```html demo
<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>클릭과 함수</title>
</head>
<body>
  <button id="change" type="button">문구 바꾸기</button>
  <p id="status">아직 누르지 않았습니다.</p>
  <script>
    const button = document.querySelector("#change");
    const status = document.querySelector("#status");

    function changeMessage() {
      status.textContent = "버튼을 눌렀습니다.";
    }

    button.addEventListener("click", changeMessage);
  </script>
</body>
</html>
```

`addEventListener`는 어떤 일이 일어났을 때 실행할 함수를 연결하는 기능입니다. 첫 인수 `"click"`은 감지할 사건의 종류이고, 두 번째 인수 `changeMessage`는 그때 사용할 함수입니다. 사건을 이벤트라고 부르고, 이벤트가 발생했을 때 처리하는 함수를 이벤트 처리 함수라고 부릅니다.[2][3][4]

여기서 `changeMessage` 뒤에 괄호가 없다는 점이 중요합니다. `changeMessage()`라고 쓰면 그 표현을 평가하는 지금 함수를 호출합니다. 반면 함수 자체를 인수로 전달하면 브라우저가 나중에 클릭이 발생했을 때 호출할 수 있습니다. ‘괄호가 없으니 함수가 아니다’가 아니라 ‘지금 호출하는 대신 호출할 대상을 전달한다’라고 읽어야 합니다.

```text
문서를 열 때: 버튼과 문단을 찾는다
문서를 열 때: changeMessage 함수를 준비한다
문서를 열 때: 클릭하면 그 함수를 쓰도록 연결한다
사용자가 클릭할 때: changeMessage의 본문이 실행된다
그 함수 안에서: 문단의 textContent가 바뀐다
```

이 흐름은 앞에서 배운 위에서 아래로 실행과 모순되지 않습니다. 초기 설정을 위에서 아래로 실행한 뒤, 등록한 사건이 발생하면 관련 함수를 실행하는 것입니다. 프로그램 전체를 한 번 읽고 끝내는 상황과 사용자 입력을 기다리는 상황이 이어져 있습니다.

### 연습 8-3. 클릭하기 전에 문구가 바뀌었다

연결 줄을 `button.addEventListener("click", changeMessage());`로 바꾸었습니다. 페이지를 열자마자 문구가 바뀌고 클릭 연결도 기대와 다릅니다. 어느 부분이 시간을 바꾸었나요?

### 풀이 8-3

`changeMessage()`의 괄호가 지금 함수 호출을 수행하게 했습니다. 호출 결과를 이벤트 처리 함수 자리로 넘기게 되어 의도와 어긋납니다. 이 예제에서는 `changeMessage`라는 함수 자체를 전달해야 합니다. 괄호를 붙이느냐는 장식의 차이가 아니라 실행 시점과 전달할 값의 차이입니다.

## 8.4 입력값은 사용자가 제출한 순간에 읽는다

입력창은 처음에는 비어 있습니다. 문서를 처음 열 때 value를 읽어 변수에 저장하고, 나중에 그 변수만 사용하면 사용자가 새로 적은 내용이 반영되지 않을 수 있습니다. 우리는 제출이 일어난 순간의 현재 값을 읽어야 합니다.

```javascript
const topicInput = document.querySelector("#topic");

function readCurrentTopic() {
  const topic = topicInput.value.trim();
  console.log(topic);
}
```

topicInput에는 입력 요소가 들어 있고, 함수가 호출될 때 그 요소의 현재 value를 읽습니다. `trim()`은 그 문자열의 앞뒤 공백을 정리합니다. 변수 topic에는 이번 호출에서 읽은 문자열이 들어갑니다. 입력 요소와 그 순간 복사해 읽은 문자열은 같은 것이 아닙니다. 이후 사용자가 글자를 바꾸면 요소의 value는 달라질 수 있지만 이미 읽어 둔 문자열이 저절로 바뀌는 것은 아닙니다.

글자 입력은 `.value`로 읽습니다. 체크박스 선택 여부는 `.checked`를 사용합니다. 체크박스의 value와 선택 여부를 같은 것으로 생각하면 체크하지 않았는데도 선택된 것으로 처리할 수 있습니다. 현재 어떤 종류의 입력 요소를 다루는지 먼저 확인해야 합니다.

### 연습 8-4. 항상 빈 문자열이 출력되는 경우

문서를 열 때 `const topic = topicInput.value;`를 한 번 실행했습니다. 클릭 처리 함수에서는 `console.log(topic)`만 합니다. 사용자가 입력해도 빈 문자열이 나옵니다. 어떻게 수정해야 할까요?

### 풀이 8-4

클릭이나 제출을 처리하는 함수 안에서 `topicInput.value`를 읽어야 합니다. 처음 빈 입력창에서 읽어 둔 문자열은 이후 입력을 따라 변하는 연결이 아닙니다. 입력 요소를 찾아 두는 일과 현재 값을 읽는 일을 서로 다른 시점에 둘 수 있다는 점을 이해해야 합니다.

## 8.5 폼의 제출을 받아 목록에 넣기

버튼의 클릭만 처리하는 대신 폼의 submit 이벤트를 사용하겠습니다. 이렇게 하면 사용자가 제출 버튼을 누르는 경로와 Enter로 제출하는 경로를 한곳에서 다루기 쉽습니다. 처리 함수는 사건에 관한 객체를 인수로 받을 수 있습니다. 이 예제에서는 그 인수를 event라고 부르겠습니다. 이름은 사람이 정한 것이며, 실제 전달되는 값은 브라우저의 이벤트 객체입니다.

`event.preventDefault()`는 이 이벤트의 기본 동작을 막습니다. 여기서는 폼 제출로 다른 주소로 이동하거나 현재 문서를 다시 불러오는 기본 흐름 대신 JavaScript로 목록을 바꾸려는 목적입니다. 모든 이벤트 전달을 멈추거나 데이터를 자동 저장하는 기능은 아닙니다.

다음은 입력값 검사와 화면 추가까지 연결한 전체 문서입니다. 아직 새로고침 뒤의 저장은 없습니다. 학습 기록이 화면에 추가되는 것과 영구 저장이 다르다는 것을 확인하는 예제로 사용합니다.

```html demo
<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>기록을 화면에 추가하기</title>
</head>
<body>
  <main>
    <h1>나의 학습 기록장</h1>
    <form id="record-form">
      <label for="topic">공부한 내용</label>
      <input id="topic" name="topic" required maxlength="80">
      <label for="minutes">공부한 시간(분)</label>
      <input id="minutes" name="minutes" type="number"
             required min="1" max="600" step="1">
      <button type="submit">기록 추가</button>
    </form>
    <p id="message" role="status"></p>
    <ul id="records"></ul>
  </main>
  <script>
    const form = document.querySelector("#record-form");
    const topicInput = document.querySelector("#topic");
    const minutesInput = document.querySelector("#minutes");
    const message = document.querySelector("#message");
    const list = document.querySelector("#records");

    function handleSubmit(event) {
      event.preventDefault();
      const topic = topicInput.value.trim();
      const rawMinutes = minutesInput.value.trim();
      const minutes = Number(rawMinutes);

      if (topic === "" || topic.length > 80) {
        message.textContent = "공부한 내용을 1~80자 범위로 적어 주세요.";
        return;
      }
      if (rawMinutes === "" || !Number.isInteger(minutes)
          || minutes < 1 || minutes > 600) {
        message.textContent = "시간은 1~600분의 정수로 적어 주세요.";
        return;
      }

      const item = document.createElement("li");
      item.textContent = topic + " · " + minutes + "분";
      list.append(item);
      message.textContent = "화면에 기록을 추가했습니다. 아직 영구 저장은 아닙니다.";
      form.reset();
      topicInput.focus();
    }

    form.addEventListener("submit", handleSubmit);
  </script>
</body>
</html>
```

앞부분은 요소를 찾아 둡니다. 사용자가 제출하면 함수 안에서 지금 입력값을 읽습니다. 조건이 맞지 않으면 이유를 표시하고 return으로 이번 처리를 끝냅니다. 아래의 항목 생성까지 계속 진행하지 않습니다. 이때 return은 오류 메시지를 자동으로 띄우는 기능이 아닙니다. 메시지를 바꾸는 줄과 실행을 끝내는 줄이 따로 있습니다.

검사를 통과하면 `document.createElement("li")`로 새 목록 항목 요소를 만듭니다. 이것만으로 화면에 바로 붙는 것은 아닙니다. 먼저 item의 글자를 정하고, `list.append(item)`으로 실제 목록 안에 넣습니다. 데이터의 문자열, 새로 만든 요소, 문서에 연결된 요소라는 단계를 구별해서 보세요.

`form.reset()`은 폼을 초기 상태로 되돌립니다. 이 예제에서는 기본값이 없으므로 입력이 비워집니다. 저장된 기록을 지우는 명령이 아닙니다. 마지막 `focus()`는 다음 기록을 쉽게 입력하도록 주제 입력창으로 초점을 옮깁니다. `role="status"`는 상태 메시지가 바뀌었다는 정보를 보조 기술에 전달하는 데 도움을 주는 의미입니다. 입력 오류의 모든 접근성 처리가 이 속성 하나로 끝난다는 뜻은 아닙니다.

### 연습 8-5. 두 번째 기록은 어디에 붙을까?

위 예제에서 ‘HTML,20’과 ‘CSS,30’을 차례로 제출하면 목록에는 무엇이 보일까요? `list.append(item)` 대신 `list.textContent = item.textContent`를 사용하면 차이는 무엇인가요?

### 풀이 8-5

append를 사용하면 새 li가 기존 목록 뒤에 추가되어 두 항목이 남습니다. 반면 list의 textContent에 문자열을 새로 대입하면 목록 내부의 기존 내용을 해당 문자열로 바꿉니다. 마지막 기록만 보이고 li 구조도 사라집니다. ‘추가’와 ‘전체 내용 대체’는 같은 동작이 아닙니다.

## 8.6 사용자의 글자를 문서 코드로 취급하지 않기

사용자가 주제에 `<b>중요</b>`라고 입력했다고 생각해 봅시다. 위 예제는 textContent를 사용하므로 그 입력을 글자로 표시합니다. 브라우저에게 태그로 해석해 새 구조를 만들라고 하지 않습니다.

`innerHTML`은 문자열을 HTML로 해석하여 요소 안에 넣을 수 있는 기능입니다. 작성자가 통제한 문서 조각을 다루는 상황에서는 쓰일 수 있지만, 사용자가 입력한 글자를 그대로 넣으면 의도하지 않은 HTML이 해석될 위험이 있습니다. 이 기록장에서 필요한 것은 공부한 내용을 글자로 보여 주는 일이지 사용자의 HTML을 실행하는 일이 아닙니다. 따라서 textContent를 기본으로 사용합니다.[2][3]

### 연습 8-6. 굵게 보이면 더 좋다는 제안

AI가 ‘사용자가 입력한 태그가 멋지게 보이도록’ item.textContent를 item.innerHTML로 바꾸자고 제안합니다. 기록장이 일반 텍스트 주제를 받는 목적이라면 무엇을 먼저 판단해야 할까요?

### 풀이 8-6

사용자에게 HTML 작성 기능을 제공하려는 요구가 있는지부터 확인해야 합니다. 그런 요구가 없다면 텍스트로 표시하는 현재 동작이 목적에 맞습니다. 기능을 하나 더 허용하면 입력 처리와 보안 검증 범위도 달라집니다. 예쁘게 보이는 샘플 하나만 보고 해석 방식을 넓히지 않는 것이 중요합니다.

지금은 화면에 기록을 추가할 수 있습니다. 그러나 새로고침하면 사라집니다. 브라우저가 이상한 것이 아니라 추가한 요소와 값이 현재 실행 중인 문서 안에만 있기 때문입니다. 다음 장에서는 목록의 기준이 되는 상태를 따로 두고, 상태를 화면으로 만드는 함수와 상태를 저장하는 과정을 나누겠습니다.
