# 챗북 1.2 연결형 교재 업그레이드

대상은 챗북 전용 브랜치와 기존 운영 사이트다. 앱 1.0.3, 제작 규칙/모듈 1.2.0, 파이썬 교재 v3.

## 달라진 제작 방식

분석 구간과 독서의 장을 분리했다. 원문은 변경 없이 보존하고, 한국어 기준본 다음에 필요한 구간만 쉽게 편집한다. 동일한 뜻/이유/실수/응용 카드나 분량 목표를 강제하지 않는다. 전체 책을 다시 요약하는 단계는 추가하지 않았다.

readingPlan으로 인접한 분석 구간을 개념상의 장으로 묶는다. 같은 장의 집필은 앞 초고를 참고하지만, 전달하는 연결 문맥은 최대 4KB다. 다른 장의 작업은 기존 동시성 제한 안에서 독립 진행할 수 있다. 최종 조립은 문단을 그대로 잇는 결정적 처리이며, 문체를 자동으로 완벽하게 고쳐주는 AI가 아니다. 연결성 검토는 기존 review 단계에 포함되므로 새 모델 호출 단계는 없다.

외부 지식과 추가 예제는 explanation과 확인한 출처 메타데이터로 구분한다. 출처 문자열이 있다는 이유만으로 내용이 맞는 것은 아니다. 검수 기록에 보충 내용의 확인 근거가 필요하다. 원문을 못 얻은 부분을 외부 지식으로 채워 원문 확인 완료로 처리하지 않는다.

장 계획이 변경되거나 앞 초고가 변경되면 관련 연결 검수 승인을 해제한다. 최종 장 계획 해시가 승인과 다르면 내보내기를 막는다. 원문·초고는 그대로 남기며, 기존 비용 예약·재시도 제한·불확실 호출 보류·영구 체크포인트를 유지한다.

## 제작자가 사용하는 경로

기존 prepare 다음 원문 구조를 파악해 `node engine/cli.mjs plan JOB_DIR READING_PLAN_JSON`을 실행한다. JSON 예: `[{"id":"chapter-input","title":"입력을 계산에 사용하기","chunkIds":["c001","c002"]}]`. 실제 작업의 모든 구간을 원래 순서로 정확히 한 번 연결해야 한다. task/submit/review/approve/export는 기존 경로를 사용한다. 외부 자동 API 호출은 기본 OFF, 추가 API 예산은 0달러다.

## 이번 책에서 실제 수정한 범위

파이썬 책 14장, 기존 문단/이미지 식별자 191개, 이미지 10개, 퀴즈 36개를 유지했다. 연결형 설명·코드·출력으로 본문을 보강했다. 대입과 비교, int(input()) 순서, 음수 나눗셈과 int의 차이, 조건 순서, while 탈출, range 경계, 리스트 삭제 뒤 인덱스 변화, 튜플 재대입, 세트 순서의 의미를 보강했다. 과거 PyCharm 설치 설명에는 공식 문서로 확인한 현재 제품 구분을 별도 보충했다.

39개 학습용 코드는 로컬 Python에서 실행했으며, 그중 4개는 의도한 오류 종류를 확인하는 예제다. 원 강의 화면을 추출한 코드 캡처라고 표시하지 않는다. 나머지 12권과 영어 전사 바이트의 해시가 유지된다.

코드와 출력은 본문에 전용 텍스트 레이아웃으로 표시하고, 들여쓰기를 보존한다. 일반 p 블록에 `_format` 메타데이터를 사용하므로 구형 책 구조와 호환한다. 메모/책갈피 저장 구조는 바꾸지 않았다. 기존 ID는 유지했지만 글 자체가 편집되어 과거 선택 구절이 본문과 완전히 같은 문자열로 남는다고 보장하지 않는다.

## 검증 범위 및 한계

Node 단위/계약 검사 109개 통과. 실제 책 보존·코드 재실행 검사 통과. 로컬 Chromium 렌더 47개 검사 통과: 360/412/768/1366px, 코드 들여쓰기, 가로 넘침, 독서 모드, 재진입 책갈피/위치, 가져오기 형식, 실제 앱 PDF 생성 포함. 로컬 환경은 일반 URL 탐색이 차단되어 동일 소스의 자체 포함 HTML로 렌더했으며, 물리 Galaxy 검사나 실제 HTTPS 저장 검사는 아니다. 운영 검사는 별도 CI 결과를 따른다.

앱 전체 PDF는 46쪽으로 실제 생성했다. 모바일 페이지 수와 다른 출력 레이아웃의 수치이며 분량 목표가 아니다. 39개의 코드 결과 검사가 강의 원음·화면 전체의 검증을 뜻하지 않는다. 이번 수정은 저장된 영어 전사의 주제·예제와 본문을 비교한 수동 편집이며, 과거 원고를 새 의미단위 검수의 완전 통과로 소급 인증하지 않는다. 실제 2~3시간 새 영상의 모델 생성·과금·처리시간은 측정하지 않았다.
