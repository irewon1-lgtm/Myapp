# 설계 판단과 연구 근거

작성일: 2026-09-23. 아래는 외부 문서에서 확인한 제약이며, 교재 원문을 대체하는 지식이 아니다.

## 확인한 외부 제약

1. Netlify 함수: 동기 실행 60초, 백그라운드 15분, 요청 크기 한도가 있다.
   https://docs.netlify.com/build/functions/configuration/
2. Netlify background 함수는 실패 후 자동 재시도할 수 있다. 앱 수준 중복 방지 없이 긴 생성을 통째로 던지면 중복 요청 위험이 생긴다.
   https://docs.netlify.com/build/functions/background-functions/
3. Gemini는 공개 YouTube URL 입력을 지원하지만 실제 이미지 파일을 내려받는 프레임 추출 API와 같은 기능은 아니다.
   기본 영상 샘플링은 빠른 화면 변화/작은 글자를 놓칠 수 있다. 원문/영상 확보 실패와 모델 분석 실패를 구분해야 한다.
   https://ai.google.dev/gemini-api/docs/video-understanding
4. YouTube Data API의 captions.download는 영상 편집 권한을 요구한다. 다른 사람이 올린 모든 공개 영상 자막을 공식 API로 무조건 가져올 수 있다는 전제는 틀리다.
   https://developers.google.com/youtube/v3/docs/captions/download
5. 실제 로컬 프레임 추출에는 FFmpeg의 seek와 frames 옵션을 사용한다. 화면 내용 판독/선정은 별도 검토다.
   https://ffmpeg.org/ffmpeg.html

## 실험 모델의 범위

구간 길이 120/240/360/480초, 동시작업 1/2/3/4, 13/30/60/120분의 합성 전사, 각 조건 100개 시드.
모델 응답은 실제 제공자를 부르지 않는다. 본문 생성량과 공용 출력 대역폭 가정으로 대기 시간을 비교한다.
기본값인 240초·동시 2개는 실패한 작업을 작게 제한하면서 공용 대역폭을 활용하는 보수적인 선택이다.
다른 공급자/과금/출력 길이/강의 밀도에서는 최적점이 달라질 수 있으므로 전역 최적이나 완료시간 보장을 하지 않는다.

## 이전 설명의 정정

- 병렬 처리해도 전체 영상 길이가 늘면 전체 읽기/쓰기/검증 작업량은 늘어난다.
- 동일 모델의 다른 역할은 독립된 실제 초보자 실험을 대신하지 않는다.
- 원문 시간 참조가 있다는 사실과 의미가 충실하다는 것은 별개다.
- 중간 전사를 처음부터 짧게 요약하면 빠진 설명을 2차 단계가 안전하게 복원할 수 없다.
- 타임스탬프를 모르는 대표 썸네일은 실제 필요한 장면을 검토한 스크린샷이 아니다.
- 원본이 틀렸다면 보존과 사실 정확성은 충돌할 수 있다. 원문과 다른 수정은 별도 근거/표시 없이는 넣지 않는다.
