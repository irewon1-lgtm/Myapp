# TRACK 05 · 권한과 터미널 첫걸음

이번 TRACK은 `검은 창에 명령어를 치는 것`을 무서워하지 않게 만드는 과정이다.

하지만 목표는 명령어를 많이 외우는 것이 아니다.

목표는:

> 명령을 실행하기 전에 **내가 어디에 있고, 무엇을 대상으로, 어떤 일을 시키는지** 이해하는 것

이다.

---

## BLOCK 01 · 터미널은 무엇인가

### LESSON 01 · 글자로 컴퓨터와 대화하는 창

컴퓨터에서는 버튼과 아이콘을 눌러 작업할 수도 있고, 글자로 명령을 입력해 작업할 수도 있다.

글자로 명령을 입력하고 결과를 보는 프로그램을 흔히 **터미널(terminal)**이라고 부른다.

한 줄 뜻:

> 터미널 = 명령을 글자로 입력하고 그 결과를 볼 수 있는 프로그램 창

### LESSON 02 · 터미널 자체가 명령을 모두 이해하는 것은 아니다

터미널은 글자를 입력하고 보여 주는 창 역할을 한다.

실제로 명령을 해석하는 프로그램이 따로 있을 수 있다.

그 프로그램을 **셸(shell)**이라고 부른다.

---

## BLOCK 02 · 셸이란 무엇인가

### LESSON 01 · 명령을 읽고 실행을 연결하는 프로그램

**셸(shell)**은 사용자가 입력한 명령을 해석해서 필요한 프로그램을 실행하도록 연결하는 프로그램이다.

예:

```text
PowerShell
cmd
bash
zsh
```

각 셸은 문법과 기능이 조금씩 다르다.

### LESSON 02 · 인터넷에서 본 명령을 그대로 복사하면 위험한 이유

명령은 셸마다 다르게 해석될 수 있다.

그리고 명령 하나가 파일 삭제, 권한 변경, 프로그램 설치 같은 큰 변화를 만들 수 있다.

따라서 인터넷이나 AI가 준 명령을 실행하기 전에 반드시:

```text
어떤 셸용인가?
현재 위치는 어디인가?
어떤 파일이 바뀌는가?
되돌릴 수 있는가?
```

를 확인한다.

---

## BLOCK 03 · 프롬프트란 무엇인가

### LESSON 01 · 명령을 입력할 차례라는 표시

터미널을 열면 다음처럼 보일 수 있다.

```text
C:\Users\min>
```

또는:

```text
min@pc:~/study$
```

이처럼 셸이 `지금 명령을 입력할 수 있습니다`라고 보여 주는 부분을 **프롬프트(prompt)**라고 부른다.

프롬프트에는 현재 위치나 사용자 이름이 표시되기도 한다.

---

## BLOCK 04 · 현재 작업 폴더

### LESSON 01 · 명령도 어디에서 실행하는지가 중요하다

터미널은 보통 어떤 폴더를 현재 기준 위치로 사용한다.

이를 **현재 작업 디렉터리(current working directory)**라고 부른다.

`directory`는 여기서 폴더라고 생각하면 된다.

한 줄 뜻:

> 현재 작업 디렉터리 = 지금 명령이 위치 기준으로 삼고 있는 폴더

### LESSON 02 · 왜 확인해야 하나

다음 명령이 있다고 하자.

```text
python app.py
```

현재 폴더에 `app.py`가 없으면 파일을 찾지 못할 수 있다.

따라서 오류가 나면 `파일이 없다`고 단정하기 전에 **현재 위치가 맞는지** 확인한다.

---

## BLOCK 05 · 현재 위치 확인하기

### LESSON 01 · pwd

Linux나 macOS의 많은 셸에서는:

```bash
pwd
```

로 현재 폴더 경로를 볼 수 있다.

`pwd`는 `print working directory`의 줄임말이다.

### LESSON 02 · Windows PowerShell

PowerShell에서는:

```powershell
Get-Location
```

으로 현재 위치를 확인할 수 있다.

명령 이름 자체보다 **명령 실행 전 위치 확인 습관**이 중요하다.

---

## BLOCK 06 · 폴더 안의 내용 보기

### LESSON 01 · ls

Linux, macOS, PowerShell에서는 상황에 따라:

```bash
ls
```

로 현재 폴더의 파일과 폴더 목록을 볼 수 있다.

### LESSON 02 · dir

Windows cmd에서는:

```cmd
dir
```

을 자주 사용한다.

PowerShell에서도 `dir` 별칭을 사용할 수 있다.

### LESSON 03 · 확인하고 움직이기

안전한 기본 흐름:

```text
현재 위치 확인
↓
목록 확인
↓
대상 파일 확인
↓
그 다음 작업
```

## BLOCK 07 · 폴더 이동

### LESSON 01 · cd

현재 작업 폴더를 바꾸는 데 `cd`를 자주 사용한다.

```bash
cd Documents
```

사람말:

```text
현재 위치를 Documents 폴더로 바꾼다.
```

### LESSON 02 · 상위 폴더

```bash
cd ..
```

은 보통 한 단계 위 폴더로 이동하는 뜻이다.

`..`는 상대 경로에서 상위 폴더를 나타내는 특별한 표현이다.

---

## BLOCK 08 · 명령과 인자

### LESSON 01 · 명령 뒤에 추가 정보를 주기

다음 예를 보자.

```bash
cd Documents
```

`cd`는 무엇을 할지 나타내고 `Documents`는 어디로 이동할지 알려준다.

프로그램이나 명령에 넘겨주는 이런 추가 값을 **인자(argument)**라고 부른다.

한 줄 뜻:

> argument = 명령이나 프로그램에 넘겨 주는 추가 값

### LESSON 02 · 공백의 의미

셸에서는 보통 공백이 명령과 인자를 나누는 역할을 한다.

그래서 파일 이름에 공백이 있다면 따옴표로 묶어야 하는 경우가 있다.

```bash
cd "My Documents"
```

따옴표는 여러 글자를 하나의 인자로 묶는 데 도움을 준다.

---

## BLOCK 09 · 옵션이란 무엇인가

### LESSON 01 · 명령의 동작을 바꾸는 설정

명령에 추가 설정을 전달할 수 있다.

이런 설정을 **옵션(option)** 또는 **플래그(flag)**라고 부른다.

예:

```bash
ls -l
```

`-l`은 출력 방식을 바꾸는 옵션이다.

### LESSON 02 · 옵션은 꼭 이해하고 실행한다

특히 삭제, 덮어쓰기, 강제 실행을 의미하는 옵션은 위험할 수 있다.

명령을 받았을 때:

```text
명령 이름은 무엇인가?
각 옵션은 무엇을 바꾸는가?
대상 경로는 무엇인가?
```

를 따로 읽는다.

## BLOCK 10 · 도움말 보는 법

### LESSON 01 · --help

많은 명령은 다음 형태의 도움말을 제공한다.

```bash
some-command --help
```

실제 옵션 의미를 확인할 때 유용하다.

### LESSON 02 · man

Linux나 macOS에서는:

```bash
man ls
```

처럼 **매뉴얼(manual)** 페이지를 볼 수 있다.

명령을 모르면 검색 전에 공식 도움말을 보는 습관도 좋다.

---

## BLOCK 11 · 표준 출력

### LESSON 01 · 프로그램이 정상 결과를 내보내는 길

명령 프로그램이 일반적인 결과를 글자로 내보내는 통로를 **표준 출력(standard output)**이라고 부른다.

영어 줄임말로 **stdout**이라고 한다.

예:

```python
print("hello")
```

이 출력이 터미널에 나타날 수 있다.

### LESSON 02 · 화면에 보이는 것과 출력 통로

터미널은 프로그램의 stdout을 받아 화면에 보여 줄 수 있다.

하지만 stdout을 파일로 보낼 수도 있다.

곧 `리다이렉션`에서 배운다.

---

## BLOCK 12 · 표준 오류

### LESSON 01 · 오류 메시지를 따로 보내는 길

프로그램은 정상 결과와 오류 메시지를 구분해서 내보낼 수 있다.

오류 메시지용 통로를 **표준 오류(standard error)**라고 부르고 **stderr**라고 줄여 쓴다.

```text
stdout = 정상 출력용
stderr = 오류 메시지용
```

### LESSON 02 · 왜 구분하나

정상 결과는 파일에 저장하면서 오류는 화면에서 보고 싶을 수 있다.

두 통로가 나뉘어 있으면 이런 처리가 가능하다.

---

## BLOCK 13 · 종료 코드

### LESSON 01 · 프로그램이 성공했는지 숫자로 남기기

명령줄 프로그램은 끝날 때 **종료 코드(exit code)**라는 숫자를 운영체제에 돌려줄 수 있다.

관례적으로:

```text
0 = 성공
0이 아닌 값 = 어떤 오류나 특별한 상태
```

로 쓰는 프로그램이 많다.

### LESSON 02 · 자동화에서 중요하다

자동 스크립트는 화면 글자를 사람처럼 읽지 않고 종료 코드를 보고 다음 작업을 진행할지 결정할 수 있다.

따라서 명령이 글자 몇 줄을 출력했다고 성공이라고 단정하지 않는다.

---

## BLOCK 14 · 리다이렉션

### LESSON 01 · 출력이 가는 곳을 바꾸기

프로그램 출력이 기본적으로 터미널에 나타나지만 다른 곳으로 보낼 수 있다.

이처럼 입력이나 출력의 방향을 바꾸는 것을 **리다이렉션(redirection)**이라고 부른다.

예:

```bash
some-command > result.txt
```

많은 셸에서 `>`는 stdout을 파일로 보내는 의미로 사용된다.

### LESSON 02 · 덮어쓰기 주의

`>`는 기존 파일 내용을 덮어쓸 수 있다.

따라서 중요한 파일에 사용하기 전에 대상 경로를 꼭 확인한다.

`>>`처럼 뒤에 추가하는 연산자도 있지만 셸마다 세부 규칙을 확인해야 한다.

---

## BLOCK 15 · 파이프

### LESSON 01 · 한 프로그램 출력을 다음 프로그램 입력으로

한 명령의 결과를 다른 명령에게 바로 넘길 수 있다.

많은 셸에서 `|` 기호를 사용한다.

```bash
command1 | command2
```

이 연결을 **파이프(pipe)**라고 부른다.

한 줄 뜻:

> pipe = 앞 프로그램의 출력을 뒤 프로그램의 입력으로 연결하는 방식

### LESSON 02 · 작은 도구를 이어 붙이기

한 프로그램이 모든 일을 하지 않아도 된다.

```text
데이터 만들기
→ 필요한 줄 고르기
→ 정렬하기
→ 파일로 저장하기
```

처럼 작은 도구를 연결할 수 있다.

---

## BLOCK 16 · 환경변수

### LESSON 01 · 프로그램 밖에서 설정값 전달하기

프로그램은 실행되는 환경에서 이름과 값 형태의 설정을 받을 수 있다.

이런 값을 **환경변수(environment variable)**라고 부른다.

예:

```text
APP_MODE=development
```

### LESSON 02 · 코드에 설정을 박아 넣지 않는 이유

개발 환경과 운영 환경에서 서버 주소가 다를 수 있다.

코드를 매번 고치는 대신 환경변수로 값을 바꿀 수 있다.

환경변수는 설정 분리를 돕는다.

하지만 환경변수에 비밀값을 넣는다고 자동으로 완벽하게 안전해지는 것은 아니다.

---

## BLOCK 17 · PATH

### LESSON 01 · 명령 이름만 쳐도 프로그램을 찾는 이유

터미널에서:

```bash
python
```

처럼 프로그램 이름만 입력했는데 실행될 수 있다.

셸은 어디에서 그 프로그램을 찾아야 할까?

**PATH**라는 환경변수에 프로그램을 찾을 폴더 목록이 들어 있는 경우가 많다.

한 줄 뜻:

> PATH = 명령 이름으로 실행 파일을 찾을 때 검색할 폴더 목록

### LESSON 02 · 'command not found'

프로그램이 설치되어 있어도 PATH에 위치가 없거나 현재 셸이 갱신된 설정을 모르면 명령을 찾지 못할 수 있다.

따라서:

```text
설치 안 됨
```

과

```text
설치됨 + PATH에서 못 찾음
```

을 구분한다.

---

## BLOCK 18 · 사용자 계정과 권한

### LESSON 01 · 모든 사용자가 모든 파일을 바꾸면 위험하다

한 컴퓨터를 여러 프로그램과 사용자가 쓴다.

중요한 시스템 파일을 아무 프로그램이나 바꾸게 하면 위험하다.

그래서 운영체제는 **사용자(user)**와 **권한(permission)**을 이용해 접근을 제한한다.

### LESSON 02 · 읽기, 쓰기, 실행

파일 권한에서 자주 만나는 기본 행동은:

```text
read = 읽기
write = 수정/쓰기
execute = 실행
```

이다.

운영체제마다 권한 모델은 다르지만 `누가 무엇을 할 수 있는가`라는 기본 생각은 같다.

---

## BLOCK 19 · 관리자 권한

### LESSON 01 · 더 큰 권한

시스템 설정을 바꾸거나 보호된 파일을 수정하려면 일반 사용자보다 높은 권한이 필요할 수 있다.

Windows에서는 `관리자(Administrator)` 권한을 볼 수 있고, Unix 계열에서는 `root` 사용자를 볼 수 있다.

### LESSON 02 · 관리자 권한은 해결 버튼이 아니다

권한 오류가 날 때 무조건 관리자 권한으로 실행하면 보안 사고 위험이 커질 수 있다.

먼저:

```text
정말 이 작업에 높은 권한이 필요한가?
대상은 맞는가?
명령은 신뢰할 수 있는가?
```

를 확인한다.

---

## BLOCK 20 · sudo

### LESSON 01 · Unix 계열에서 높은 권한으로 명령 실행하기

Linux와 macOS에서는 상황에 따라 `sudo`를 사용해 다른 사용자, 흔히 관리자 권한으로 명령을 실행할 수 있다.

예:

```bash
sudo some-command
```

### LESSON 02 · 복사해서 바로 실행하지 않기

`sudo`가 붙은 명령은 시스템 전체에 영향을 줄 수 있다.

명령 뒤의 내용이 무엇인지 이해하지 못했다면 실행하지 않는다.

특히 인터넷에서 받은 `sudo ...` 명령은 각 부분의 의미를 먼저 확인한다.

---

## BLOCK 21 · 비밀값

### LESSON 01 · 코드에 그대로 올리면 안 되는 정보

API 키, 비밀번호, 개인키처럼 다른 사람이 알면 위험한 값을 **비밀값(secret)**이라고 부른다.

한 줄 뜻:

> secret = 외부에 노출되면 안 되는 인증·보안 관련 값

### LESSON 02 · Git에 올리는 실수

코드 안에:

```text
API_KEY = "실제비밀키"
```

를 적고 공개 저장소에 올리면 키가 노출될 수 있다.

나중에 파일에서 삭제해도 Git 과거 기록에 남아 있을 수 있다.

따라서 비밀값은 처음부터 코드와 분리하는 것이 중요하다.

## BLOCK 22 · .env 파일

### LESSON 01 · 환경변수 설정을 파일로 관리하기

개발 도구에서는 `.env` 같은 파일에 환경변수 값을 적어 사용하는 경우가 있다.

예:

```text
API_URL=https://example.com
API_KEY=example-secret
```

### LESSON 02 · .env라고 자동으로 안전하지 않다

`.env` 파일도 그냥 파일이다.

Git에 포함하면 비밀이 노출될 수 있다.

그래서 `.gitignore`에 추가하거나 비밀 관리 도구를 사용하는 등 별도 보호가 필요하다.

---

## BLOCK 23 · 명령 치환과 변수 확장 맛보기

### LESSON 01 · 셸은 입력 글자를 그대로만 전달하지 않는다

셸은 명령을 실행하기 전에 변수나 특수 기호를 해석할 수 있다.

예를 들어 Unix 계열 셸에서:

```bash
echo "$HOME"
```

은 `HOME` 환경변수의 값을 보여 줄 수 있다.

### LESSON 02 · 따옴표가 중요한 이유

큰따옴표와 작은따옴표가 변수를 해석하는 방식에 영향을 줄 수 있다.

셸마다 세부 규칙이 다르다.

따라서 경로나 사용자 입력을 명령 문자열에 넣을 때는 **인용(quoting)** 규칙을 정확히 이해해야 한다.

보안에서는 잘못된 문자열 결합이 명령 주입 공격으로 이어질 수 있다.

---

## BLOCK 24 · 명령 주입을 맛보기

### LESSON 01 · 사용자 입력을 명령으로 그대로 붙이면 위험하다

프로그램이 사용자가 입력한 파일 이름을 그대로 셸 명령 문자열에 붙인다고 하자.

공격자가 셸 특수문자를 섞으면 의도하지 않은 명령이 실행될 수 있다.

이런 공격을 **명령 주입(command injection)**이라고 부른다.

한 줄 뜻:

> command injection = 사용자 입력이 셸 명령으로 해석되어 원하지 않은 명령이 실행되는 보안 문제

### LESSON 02 · 기본 원칙

가능하면 셸 명령 문자열을 직접 이어 붙이지 말고, 실행 API가 제공하는 **인자 배열** 방식 등을 사용해 데이터와 명령을 분리한다.

보안 TRACK에서 더 깊게 다룬다.

---

## BLOCK 25 · 위험한 명령의 공통점

### LESSON 01 · 삭제, 덮어쓰기, 권한 변경

다음 종류의 작업은 특별히 주의한다.

```text
파일 삭제
폴더 전체 삭제
파일 덮어쓰기
디스크 포맷
권한 변경
패키지 설치/삭제
시스템 설정 변경
```

명령 이름을 외우는 것이 아니라 **변경이 되돌릴 수 있는지**를 먼저 생각한다.

### LESSON 02 · 안전한 실행 순서

```text
1. 읽기 전용 명령으로 현재 상태 확인
2. 대상 경로 확인
3. 변경될 항목 목록 확인
4. 백업 또는 복구 방법 확인
5. 가장 작은 범위에서 실행
6. 결과 확인
```

## BLOCK 26 · 와일드카드

### LESSON 01 · 여러 파일 이름을 한꺼번에 표현하기

셸에서는 `*` 같은 **와일드카드(wildcard)**를 사용해 여러 파일 이름을 한꺼번에 지정할 수 있다.

예:

```text
*.txt
```

는 `.txt`로 끝나는 여러 파일과 맞을 수 있다.

### LESSON 02 · 삭제 명령과 함께 쓰면 위험할 수 있다

`*`는 생각보다 많은 파일에 맞을 수 있다.

특히 삭제나 이동 명령과 함께 사용할 때는 먼저 어떤 파일이 선택되는지 목록을 확인한다.

---

## BLOCK 27 · 스크립트란 무엇인가

### LESSON 01 · 여러 명령을 파일에 모으기

반복해서 실행할 여러 명령을 파일에 적어 자동 실행할 수 있다.

이런 파일을 **스크립트(script)**라고 부른다.

예:

```bash
#!/bin/bash
echo "start"
pwd
ls
```

### LESSON 02 · 자동화는 실수도 자동화한다

스크립트가 잘못되어 있으면 같은 실수를 빠르게 여러 번 실행할 수 있다.

따라서 자동화할수록:

```text
대상 검증
오류 처리
로그
재실행 안전성
```

이 중요해진다.

---

## BLOCK 28 · 재실행 안전성

### LESSON 01 · 같은 명령을 두 번 실행하면 어떻게 되나

자동화는 실패 후 다시 실행될 수 있다.

같은 작업을 여러 번 실행해도 결과가 망가지지 않도록 만드는 성질을 **멱등성(idempotency)**이라고 부른다.

초보 한 줄:

> 멱등성 = 같은 작업을 여러 번 실행해도 의도하지 않은 중복 결과가 생기지 않게 만드는 성질

### LESSON 02 · 예시

`폴더가 없으면 만든다`는 작업은 여러 번 실행해도 같은 폴더 하나가 유지되도록 만들 수 있다.

반대로 `실행할 때마다 결제를 한 번 더 한다`는 작업은 재실행하면 큰 문제가 된다.

## BLOCK 29 · 터미널 오류 읽기

### LESSON 01 · 명령을 찾지 못함

```text
command not found
```

같은 메시지는 셸이 실행할 프로그램을 찾지 못했다는 뜻일 수 있다.

후보:

```text
프로그램 설치 안 됨
PATH 문제
명령 철자 틀림
```

### LESSON 02 · permission denied

```text
permission denied
```

는 권한 때문에 작업을 거부했다는 뜻일 수 있다.

바로 관리자 권한으로 실행하지 말고 어떤 파일과 어떤 권한이 필요한지 확인한다.

### LESSON 03 · no such file or directory

파일이나 폴더를 찾지 못했다는 뜻이다.

후보:

```text
경로 오타
현재 작업 폴더가 다름
파일이 실제로 없음
```

## BLOCK 30 · TRACK 05 핵심 용어 사전

| 용어 | 아주 쉬운 뜻 |
|---|---|
| 터미널 | 글자로 명령을 입력하고 결과를 보는 프로그램 창 |
| 셸 | 사용자가 입력한 명령을 해석해 프로그램 실행을 연결하는 프로그램 |
| 프롬프트 | 명령 입력을 기다리는 표시 |
| 현재 작업 디렉터리 | 지금 명령의 위치 기준이 되는 폴더 |
| argument | 명령에 넘기는 추가 값 |
| option/flag | 명령 동작을 바꾸는 설정 |
| stdout | 프로그램의 일반적인 정상 출력 통로 |
| stderr | 오류 메시지용 출력 통로 |
| exit code | 프로그램 종료 상태를 나타내는 숫자 |
| redirection | 입력이나 출력이 가는 곳을 바꾸는 것 |
| pipe | 앞 프로그램 출력을 뒤 프로그램 입력으로 연결하는 것 |
| environment variable | 실행 환경에서 프로그램에 전달되는 이름-값 설정 |
| PATH | 명령 이름으로 실행 파일을 찾을 폴더 목록 |
| permission | 누가 어떤 행동을 할 수 있는지 정한 규칙 |
| Administrator/root | 시스템에 더 큰 권한을 가진 관리자 계정 |
| sudo | Unix 계열에서 다른 사용자 권한으로 명령을 실행하는 도구 |
| secret | 외부에 노출되면 안 되는 보안 관련 값 |
| quoting | 셸에서 글자와 특수문자를 안전하게 묶어 해석시키는 규칙 |
| command injection | 사용자 입력이 명령으로 해석되어 원하지 않은 명령이 실행되는 문제 |
| wildcard | 여러 파일 이름을 한꺼번에 표현하는 특수 패턴 |
| script | 여러 명령을 파일에 모아 자동 실행하는 프로그램 |
| idempotency | 같은 작업을 반복해도 의도하지 않은 중복 결과가 생기지 않는 성질 |

## BLOCK 32 · TRACK 05 완료 기준

다음을 할 수 있어야 한다.

- 터미널과 셸의 차이를 설명한다.
- 현재 작업 폴더를 확인할 이유를 설명한다.
- 명령, 인자, 옵션을 구분한다.
- stdout과 stderr가 왜 나뉘는지 설명한다.
- exit code가 자동화에서 왜 중요한지 설명한다.
- redirection과 pipe의 차이를 설명한다.
- 환경변수와 PATH가 무엇인지 설명한다.
- 관리자 권한을 무조건 쓰면 안 되는 이유를 말한다.
- secret을 코드에 직접 넣으면 왜 위험한지 설명한다.
- wildcard가 삭제 명령에서 왜 위험할 수 있는지 설명한다.
- idempotency가 자동화에서 왜 중요한지 설명한다.
- AI가 만든 명령을 각 부분으로 나눠 검토할 수 있다.

### TRACK 끝 미니 프로젝트 · 안전한 진단 스크립트

파일을 삭제하거나 수정하지 않는 **읽기 전용 진단 스크립트**를 만든다.

스크립트가 다음을 보여 주게 한다.

```text
현재 작업 폴더
현재 폴더의 파일 목록
사용 중인 Python 또는 Node 버전
중요 환경변수의 존재 여부(비밀값 자체는 출력 금지)
```

마지막 조건이 중요하다.

예를 들어 API 키를 검사할 때:

```text
API_KEY exists: yes
```

정도만 출력하고 실제 키 문자열은 로그에 남기지 않는다.

이 프로젝트를 통해 `명령 실행`과 `안전한 운영`이 함께 가야 한다는 것을 배운다.
