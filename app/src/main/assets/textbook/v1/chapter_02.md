## V1-C02. 파일과 폴더를 처음부터 — 저장·경로·형식을 제대로 이해하기

**이 장의 대상:** 파일을 다운로드하고 열어본 적은 있지만 `경로`, `확장자`, `MIME`, `해시`가 무엇인지 모르는 사람.

**이 장의 목표:** 파일 문제를 “안 열려요” 한 문장으로 끝내지 않고 **어디에 있는지 → 실제로 존재하는지 → 어떤 형식인지 → 읽을 권한이 있는지 → 내용이 같은지** 순서로 확인할 수 있게 된다.

---

### 1. 파일은 무엇일까?

Chapter 1에서 파일을 “저장장치에 보관하는 데이터 묶음”이라고 배웠다.

이번 장에서는 그 말을 실제로 사용할 수 있을 정도까지 자세히 배운다.

사진 한 장, 메모 하나, 엑셀 자료, 앱 설치파일 모두 파일일 수 있다.

예:

```text
photo.jpg
memo.txt
stocks.csv
app-release.apk
source.zip
```

사람에게는 이름과 아이콘이 먼저 보이지만 컴퓨터에게 중요한 것은 **그 안에 들어 있는 실제 데이터**다.

> **파일 = 이름만 있는 것이 아니라 실제 데이터를 저장한 묶음**

---

### 2. 폴더는 무엇일까?

파일이 많아지면 정리가 필요하다.

그래서 파일을 폴더(folder)에 넣는다.

```text
Download/
  photo.jpg
  stocks.csv
```

폴더 안에 다시 폴더를 만들 수도 있다.

```text
MyApp/
  images/
    logo.png
  data/
    stocks.csv
  docs/
    readme.txt
```

컴퓨터 프로젝트도 이런 식으로 여러 폴더에 파일을 나누어 놓는다.

초보자는 파일 이름만 보지 말고 **어느 폴더 안에 있는가**까지 같이 보는 습관을 가져야 한다.

---

### 3. 경로는 파일의 주소다

**경로(path)**는 파일이 어디에 있는지 표현한 주소다.

```text
MyApp/data/stocks.csv
```

이 경로를 사람말로 읽으면:

```text
MyApp 폴더 안의
data 폴더 안의
stocks.csv 파일
```

이다.

처음에는 `/`가 무엇인지 몰라도 된다. 폴더 단계를 나누는 표시라고 생각하면 된다.

#### 경로를 읽는 연습

```text
school/homework/math.txt
```

뜻:

```text
school
└─ homework
   └─ math.txt
```

이렇게 경로를 트리처럼 그려보면 훨씬 쉽게 이해된다.

---

### 4. 같은 이름의 파일이 여러 개 있을 수 있다

`config.json`이라는 파일 이름이 하나뿐이라고 생각하면 안 된다.

```text
projectA/config.json
projectB/config.json
backup/config.json
```

세 파일은 이름은 같지만 위치가 다르다.

그래서 개발할 때 “config.json 고쳐줘”라고만 말하면 모호할 수 있다.

더 정확하게는:

```text
app/config/config.json
```

처럼 경로까지 지정해야 한다.

이 원칙은 AI에게 파일 수정을 맡길 때도 중요하다.

> **파일 이름이 같아도 경로가 다르면 다른 파일일 수 있다.**

---

### 5. 절대경로와 상대경로

경로에는 대표적으로 두 가지 생각법이 있다.

#### 절대경로

처음부터 전체 위치를 적는다.

예를 들어 Android나 Linux 계열 환경에서는 다음과 비슷한 모양을 볼 수 있다.

```text
/storage/emulated/0/Download/report.csv
```

처음부터 위치를 길게 적었으므로 어디인지 비교적 명확하다.

이를 **절대경로(absolute path)**라고 한다.

> **절대경로 = 시작 지점부터 전체 위치를 적은 주소**

#### 상대경로

현재 내가 서 있는 위치를 기준으로 적는다.

예:

```text
data/report.csv
```

이를 **상대경로(relative path)**라고 한다.

> **상대경로 = 현재 위치를 기준으로 적은 주소**

---

### 6. “현재 위치”가 왜 중요할까?

다음 코드가 있다고 하자.

```python
path = "data/report.csv"
```

이 경로는 무조건 같은 파일을 뜻하지 않는다.

프로그램이 어느 폴더를 기준으로 실행되는지에 따라 달라질 수 있다.

예를 들어 현재 위치가:

```text
MyApp/
```

이라면:

```text
MyApp/data/report.csv
```

를 찾을 수 있다.

하지만 현재 위치가:

```text
MyApp/tools/
```

이라면 프로그램은:

```text
MyApp/tools/data/report.csv
```

를 찾으려 할 수 있다.

이때 “파일이 있는데 왜 못 찾지?”라는 문제가 생긴다.

#### 꼭 기억하기

> 상대경로 문제에서는 **프로그램의 현재 작업 위치**를 확인해야 한다.

영어로는 `working directory`라고 부른다.

처음에는 다음처럼만 기억하면 된다.

> **working directory = 프로그램이 지금 경로 계산의 기준으로 삼고 있는 폴더**

---

### 7. `.`과 `..`는 무엇일까?

경로에서 다음 기호를 볼 수 있다.

```text
.
..
```

일반적으로:

```text
.  = 현재 폴더
.. = 한 단계 위 폴더
```

라고 이해하면 된다.

예:

```text
./data/report.csv
```

은 “현재 폴더 아래 data 폴더의 report.csv”라는 뜻으로 자주 쓰인다.

```text
../data/report.csv
```

은 “한 단계 위로 올라간 뒤 data 폴더의 report.csv”라는 뜻이 될 수 있다.

운영체제와 환경에 따라 세부 표현은 달라질 수 있지만 기본 개념은 같다.

---

### 8. 확장자는 무엇일까?

파일 이름 끝에 붙는 `.jpg`, `.txt`, `.csv` 같은 부분을 **확장자(extension)**라고 한다.

```text
photo.jpg
memo.txt
report.csv
```

보통 확장자는 사람이 파일 종류를 알아보기 쉽게 한다.

예:

```text
.txt  → 텍스트 파일인 경우가 많음
.jpg  → JPEG 이미지인 경우가 많음
.png  → PNG 이미지인 경우가 많음
.csv  → 표 형태 데이터를 담는 텍스트 파일인 경우가 많음
.zip  → 여러 파일을 묶거나 압축한 파일인 경우가 많음
.apk  → Android 앱 설치 패키지
```

하지만 매우 중요한 사실이 있다.

> **확장자는 파일 이름의 일부일 뿐, 실제 내용 자체를 바꾸지는 않는다.**

---

### 9. 이름만 바꾼다고 파일 종류가 바뀌지 않는다

`photo.png`라는 파일이 있다고 하자.

이름만:

```text
photo.jpg
```

로 바꾸었다.

그렇다고 실제 PNG 데이터가 JPEG 데이터로 변환되는 것은 아니다.

이것은 초보자가 자주 하는 오해다.

```text
이름 변경 ≠ 형식 변환
```

실제 형식 변환은 프로그램이 원본 데이터를 읽고 다른 형식으로 다시 저장해야 한다.

#### 비유

물병에 “우유”라고 스티커를 붙였다고 물이 우유가 되지 않는다.

파일 확장자도 비슷하다.

---

### 10. 텍스트 파일과 바이너리 파일

파일은 크게 생각하면 **텍스트로 읽기 쉬운 파일**과 **특정 프로그램 규칙으로 해석해야 하는 파일**로 나눠 볼 수 있다.

#### 텍스트 파일

사람이 글자로 읽을 수 있는 데이터가 중심이다.

예:

```text
hello.txt
stocks.csv
config.json
```

#### 바이너리 파일

이미지, 압축파일, 실행파일처럼 내부 구조가 단순한 글자 줄이 아닌 경우가 많다.

예:

```text
photo.jpg
archive.zip
app.apk
```

**바이너리(binary)**라는 영어가 처음 나온다.

> **바이너리 파일 = 전용 규칙으로 읽어야 하는 바이트 데이터 중심 파일**

텍스트 편집기로 ZIP을 열었는데 이상한 글자가 보인다고 해서 ZIP이 반드시 깨진 것은 아니다.

잘못된 도구로 열었기 때문에 사람이 읽기 어려운 것일 수 있다.

---

### 11. 문자 인코딩을 다시 이해하기

텍스트 파일도 결국 바이트로 저장된다.

그 바이트를 어떤 문자로 읽을지 정하는 규칙이 필요하다.

Chapter 1에서 `UTF-8`을 아주 간단히 배웠다.

다시 정리하면:

> **인코딩(encoding) = 문자를 바이트로 표현하는 규칙**

예를 들어 파일은 정상인데 프로그램이 다른 인코딩으로 읽으면 한글이 깨질 수 있다.

```text
원래: 안녕하세요
깨짐: ì•ˆë…•í•˜ì„¸ìš”
```

초보자가 해야 할 첫 확인은:

1. 파일이 어떤 문자 인코딩으로 저장되었는가?
2. 읽는 프로그램은 어떤 인코딩으로 해석하고 있는가?

이다.

---

### 12. CSV는 무엇일까?

**CSV**는 표 형태의 데이터를 텍스트로 저장할 때 자주 쓰는 형식이다.

예:

```csv
name,price,qty
AAPL,200,3
MSFT,450,2
```

첫 줄은 열 이름이다.

```text
name | price | qty
```

두 번째 줄은 한 행의 데이터다.

```text
AAPL | 200 | 3
```

CSV는 보통 쉼표를 구분자로 사용하지만 환경에 따라 다른 구분자를 사용하는 경우도 있다.

처음에는 다음만 기억하면 된다.

> **CSV = 표 데이터를 글자 형태로 저장하는 간단한 파일 형식**

엑셀에서 열 수 있다고 해서 CSV 자체가 엑셀 전용 파일이라는 뜻은 아니다.

---

### 13. JSON 파일은 무엇일까?

Chapter 1에서 JSON을 “이름과 값을 규칙적으로 정리한 데이터 표현 방식”이라고 배웠다.

JSON을 파일로 저장할 수도 있다.

예:

```json
{
  "name": "AAPL",
  "price": 200
}
```

파일 이름은 보통 다음처럼 끝날 수 있다.

```text
stock.json
```

하지만 `.json`이라는 이름만 보고 실제 내용이 항상 올바른 JSON이라고 확정할 수는 없다.

파일 내용 자체가 JSON 문법에 맞아야 한다.

---

### 14. MIME이라는 말은 왜 있을까?

인터넷이나 앱 사이에서 파일을 전달할 때 “이 데이터가 어떤 종류인지” 알려주는 정보가 필요할 수 있다.

이때 **MIME type**이라는 표현을 자주 본다.

처음에는 긴 영어를 외우지 말고 다음처럼 이해하자.

> **MIME type = 이 데이터가 어떤 종류인지 알려주는 표지판**

예:

```text
text/plain
image/png
image/jpeg
application/json
```

파일 확장자와 MIME은 서로 관련될 수 있지만 완전히 같은 것은 아니다.

예를 들어 이름은 `.jpg`인데 서버가 실제 데이터와 맞지 않는 타입으로 처리하면 업로드나 표시가 실패할 수 있다.

---

### 15. 압축은 무엇일까?

파일이 크거나 여러 개일 때 하나로 묶고 크기를 줄이기 위해 압축을 사용할 수 있다.

대표적으로 ZIP을 많이 본다.

```text
source/
  app/
  docs/
  data/
```

를:

```text
source.zip
```

하나로 묶을 수 있다.

**압축(compression)**은 데이터를 더 효율적으로 표현해 크기를 줄이는 것이 주목적이다.

> **압축 = 데이터를 더 작게 보관하거나 전달하기 위한 변환**

---

### 16. ZIP은 앱 설치파일과 다르다

초보자가 자주 헷갈리는 부분이다.

```text
app.apk
source.zip
```

둘 다 하나의 파일처럼 보이지만 목적이 다르다.

`APK`는 Android 앱 설치에 사용되는 패키지다.

`ZIP`은 여러 파일을 묶거나 압축한 자료일 수 있다.

따라서:

> ZIP 파일을 받았다고 바로 Android 앱을 설치할 수 있는 것은 아니다.

ZIP 안에 소스코드가 있을 수도 있고, APK가 들어 있을 수도 있다.

먼저 무엇이 들어 있는지 확인해야 한다.

---

### 17. 압축과 인코딩과 암호화는 다르다

세 용어는 모두 “데이터를 다른 모양으로 바꾼다”는 점 때문에 헷갈린다.

#### 압축

목적: 크기를 줄이기.

예: ZIP, GZIP.

#### 인코딩

목적: 데이터를 특정 규칙으로 표현하기.

예: UTF-8, Base64.

#### 암호화

목적: 권한 없는 사람이 내용을 이해하기 어렵게 만들기.

영어로는 `encryption`이라고 한다.

```text
압축     = 작게 만들기
인코딩   = 표현 규칙 바꾸기
암호화   = 비밀 보호하기
```

Base64로 바꾸었다고 데이터가 안전하게 암호화된 것이 아니다.

이 차이는 보안에서 다시 깊게 배운다.

---

### 18. 파일을 복사한다는 것은 무엇일까?

**복사(copy)**는 원본을 남겨두고 다른 위치에 같은 내용을 하나 더 만드는 것이다.

```text
원본: Download/report.csv
복사: Backup/report.csv
```

복사 과정에서 중요한 것은 “같은 이름인지”보다 **실제 내용이 같은지**다.

이때 나중에 해시를 사용할 수 있다.

---

### 19. 파일을 이동한다는 것은 무엇일까?

**이동(move)**은 파일 위치를 바꾸는 것이다.

```text
Download/report.csv
↓
Documents/report.csv
```

프로그램이 이전 경로를 계속 찾고 있다면 이동 후 파일을 못 찾을 수 있다.

즉 코드가 틀린 것이 아니라 **파일 위치가 바뀌었기 때문**일 수 있다.

---

### 20. 파일 이름 변경과 이동을 구분하기

**이름 변경(rename)**은 같은 위치에서 이름을 바꾸는 것이다.

```text
report-old.csv
↓
report.csv
```

이동과 이름 변경이 동시에 일어날 수도 있다.

초보자는 “파일이 사라졌다”라고 느낄 수 있지만 실제로는 위치나 이름만 달라진 경우가 있다.

그래서 파일 문제에서는:

```text
존재 여부
경로
파일 이름
```

세 가지를 나눠 확인한다.

---

### 21. 삭제는 왜 조심해야 할까?

파일 삭제는 되돌리기 어려울 수 있다.

특히 터미널 명령이나 자동화 코드로 많은 파일을 삭제할 때는 매우 조심해야 한다.

삭제 전에는 최소한 다음을 확인한다.

1. 어느 폴더에서 실행하는가?
2. 어떤 파일이 대상인가?
3. 하위 폴더까지 포함되는가?
4. 백업이 있는가?
5. 복구 방법이 있는가?

AI가 만든 명령이라도 그대로 실행하지 않는다.

> **삭제 명령은 실행 전에 대상 경로를 눈으로 확인한다.**

---

### 22. 파일 권한은 무엇일까?

파일이 존재해도 프로그램이 읽지 못할 수 있다.

왜냐하면 운영체제가 접근 권한을 제한할 수 있기 때문이다.

**권한(permission)**은 누가 어떤 행동을 할 수 있는지 정하는 규칙이다.

예:

```text
읽기 가능
쓰기 가능
실행 가능
```

따라서:

```text
파일 있음
```

과:

```text
현재 프로그램이 파일을 읽을 수 있음
```

은 다른 말이다.

---

### 23. URI라는 낯선 주소를 볼 때

Android에서 파일을 선택하면 이런 형태를 볼 수 있다.

```text
content://...
```

처음 보면 일반 파일 경로와 달라서 당황할 수 있다.

Android에서는 앱이 다른 앱이나 문서 선택기를 통해 파일을 받을 때 **URI**라는 식별자를 사용하는 경우가 많다.

지금은 세부 구조를 외우지 않는다.

> **URI = 파일이나 자원을 가리키는 주소 역할을 할 수 있는 식별자**

Android의 저장소 보안과 함께 Chapter 9에서 더 자세히 배운다.

---

### 24. 파일이 같은지 어떻게 확인할까?

파일 이름과 크기가 같아도 실제 내용이 다를 수 있다.

반대로 이름이 달라도 내용이 완전히 같을 수 있다.

내용을 비교하는 강력한 방법 중 하나가 **해시(hash)**다.

해시는 파일 데이터를 계산해 고정된 길이의 값으로 만든다.

대표적으로 **SHA-256**이라는 해시 함수를 많이 사용한다.

예시 모양:

```text
9f86d081884c7d659a2feaa0c55ad015...
```

처음에는 긴 값을 읽을 필요 없다.

> **해시 = 파일 내용의 지문처럼 비교에 사용할 수 있는 값**

---

### 25. SHA-256이 같으면 무엇을 알 수 있을까?

두 파일의 SHA-256이 같다면 실무적으로 같은 바이트 내용이라고 판단하는 데 매우 강한 근거가 된다.

그래서:

- 다운로드 전후 파일 비교
- APK 배포 파일 확인
- 백업 파일 확인
- 빌드 산출물 식별

등에 사용할 수 있다.

하지만 주의해야 한다.

> 해시가 있다고 파일이 “안전한 파일”이라는 뜻은 아니다.

악성 파일도 해시를 가질 수 있다.

해시는 **같은 내용인지**를 비교하는 도구다.

신뢰할 수 있는 출처인지는 별도 문제다.

---

### 26. 파일이 손상되었다는 말은 무엇일까?

파일 손상은 여러 상황을 포함할 수 있다.

```text
다운로드 중 일부 바이트가 빠짐
저장 도중 중단됨
잘못된 프로그램으로 다시 저장함
파일 형식 구조가 깨짐
```

초보자는 이런 상황을 전부 “파일이 안 열려요”라고 말하기 쉽다.

하지만 실제 진단에서는 다음을 나눈다.

```text
파일이 존재하는가?
↓
읽을 권한이 있는가?
↓
크기와 내용이 예상과 맞는가?
↓
형식이 올바른가?
↓
해시가 기준과 맞는가?
```

---

### 27. 다운로드 파일을 안전하게 확인하는 순서

앱 APK를 다운로드했다고 하자.

바로 설치하기 전에 최소한 다음을 확인할 수 있다.

1. 다운로드한 위치
2. 파일 이름
3. 확장자
4. 파일 크기
5. 제공자가 공개한 해시가 있다면 SHA-256 비교
6. 앱 서명 검증이 필요한 환경이라면 서명 확인

초보자에게 가장 중요한 것은 **내가 지금 어떤 파일을 실행하고 있는지 정확히 아는 것**이다.

---

### 28. 실제 예제 — APK와 ZIP을 헷갈림

상황:

```text
FutureTech.zip
FutureTech.apk
```

두 파일이 다운로드 폴더에 있다.

사용자는 “둘 다 앱 파일인가?”라고 생각할 수 있다.

정답은 아니다.

```text
APK = Android 설치 패키지
ZIP = 압축 묶음
```

ZIP 안에 소스코드가 들어 있을 수 있다.

따라서 파일 목적을 먼저 확인해야 한다.

---

### 29. 실제 예제 — CSV 한글 깨짐

`hospitals.csv`를 열었는데 한글이 깨졌다.

파일 이름을 `.xlsx`로 바꾸는 것은 해결이 아니다.

확인 순서:

1. 원본 파일이 어떤 인코딩으로 저장됐는가?
2. 여는 프로그램이 어떤 인코딩으로 읽는가?
3. 구분자(쉼표 등)가 올바른가?
4. 파일 자체가 손상된 것은 아닌가?

핵심은 **이름이 아니라 실제 형식과 해석 규칙**을 보는 것이다.

---

### 30. 실제 예제 — 상대경로 때문에 파일을 못 찾음

코드:

```python
path = "data/report.csv"
```

터미널에서는 잘 되는데 IDE에서 실행하면 실패한다.

가능한 이유:

```text
터미널 실행 기준 폴더 ≠ IDE 실행 기준 폴더
```

따라서 다음을 출력하거나 확인한다.

```text
현재 작업 폴더
프로그램이 계산한 실제 전체 경로
파일 존재 여부
```

무작정 파일을 복사해 여러 폴더에 뿌리는 것은 좋은 해결이 아니다.

---

### 31. 실제 예제 — 같은 이름인데 다른 파일

폴더 구조:

```text
prod/config.json
test/config.json
```

운영 환경에서 잘못해서 `test/config.json`을 읽으면 전혀 다른 설정으로 실행될 수 있다.

이런 문제는 이름만 보고는 찾기 어렵다.

그래서 로그에 실제 경로를 기록하는 습관이 도움이 된다.

---

### 32. 파일 문제 6단계 진단법

앞으로 파일 문제가 생기면 다음 순서로 확인한다.

```text
1. 존재하는가?
2. 경로가 맞는가?
3. 권한이 있는가?
4. 파일 형식이 맞는가?
5. 내용이 손상되지 않았는가?
6. 내가 신뢰하는 출처의 파일인가?
```

이 여섯 질문을 외우기보다 **앞에서부터 하나씩 확인하는 습관**을 만든다.

---

### 33. 간단한 Python 파일 경로 맛보기

아직 Python 파일 입출력을 배우는 장은 아니다.

다만 경로가 코드에서 문자열로 다뤄질 수 있다는 것만 보자.

```python
folder = "Download"
file_name = "report.csv"
path = folder + "/" + file_name
print(path)
```

실행 결과:

```text
Download/report.csv
```

한 줄씩 해석하면:

1. `folder`에 폴더 이름 저장
2. `file_name`에 파일 이름 저장
3. 둘을 `/`로 연결
4. 결과 출력

이 코드를 이해하는 데 파일 API 지식은 필요 없다.

---

### 34. 직접 수정해보기

아래 코드를 실행한다.

```python
folder = "images"
file_name = "logo.png"
print(folder + "/" + file_name)
```

결과를 예상한다.

```text
images/logo.png
```

이제 `images`를 `photos`로 바꿔본다.

이 작은 수정은 **경로도 결국 문자열 데이터로 만들어질 수 있다**는 감각을 준다.

---

### 35. 고장난 예제 찾기

```python
folder = "Download"
file_name = "report.csv"
path = folder + file_name
print(path)
```

출력:

```text
Downloadreport.csv
```

문제는 폴더와 파일 사이 구분자가 없다는 것이다.

수정:

```python
path = folder + "/" + file_name
```

결과:

```text
Download/report.csv
```

초보자는 이처럼 **기대 결과와 실제 결과를 비교**하며 오류를 찾는 연습을 한다.

### 36. 확장자와 실제 형식 확인 문제

다음 중 맞는 설명은?

2. 확장자는 종류를 추측하는 힌트이고 실제 내용은 별도로 확인해야 한다.

정답: **2**

### 37. 압축·인코딩·암호화 확인 문제

다음 설명을 연결해보자.

```text
ZIP      → 여러 파일을 묶거나 크기를 줄임
UTF-8    → 문자를 바이트로 표현하는 규칙
암호화   → 허가받지 않은 사람이 내용을 이해하기 어렵게 함
```

이 셋을 같은 것으로 생각하지 않는다.

### 38. 용어사전

| 쉬운 말 | 영어 | 뜻 |
|---|---|---|
| 파일 | file | 저장장치에 보관하는 데이터 묶음 |
| 폴더 | folder/directory | 파일을 정리하는 공간 |
| 경로 | path | 파일 위치를 나타내는 주소 |
| 절대경로 | absolute path | 시작 지점부터 전체 위치를 적은 경로 |
| 상대경로 | relative path | 현재 위치를 기준으로 적은 경로 |
| 현재 작업 폴더 | working directory | 상대경로 계산의 기준이 되는 현재 폴더 |
| 확장자 | extension | 파일 이름 끝에 붙어 종류를 추측하게 하는 부분 |
| 텍스트 | text | 문자로 읽는 데이터 |
| 바이너리 | binary | 특정 형식 규칙으로 해석하는 바이트 중심 데이터 |
| 인코딩 | encoding | 데이터를 정해진 방식으로 표현하는 규칙 |
| MIME type | MIME type | 데이터 종류를 알려주는 표지 |
| 압축 | compression | 데이터 크기를 줄이거나 묶는 변환 |
| 암호화 | encryption | 내용을 보호하기 위한 변환 |
| 권한 | permission | 누가 읽고 쓰고 실행할 수 있는지 정한 규칙 |
| URI | URI | 파일이나 자원을 가리키는 식별자/주소 역할 |
| 해시 | hash | 내용을 비교하기 위한 고정 길이 지문 같은 값 |
| SHA-256 | SHA-256 | 널리 쓰이는 해시 함수 중 하나 |

### 39. 이 장의 종합 미션

다음 상황을 진단해보자.

> 친구가 `myapp.apk`를 보내줬다. 그런데 설치가 안 된다.

무조건 “APK가 깨졌다”고 단정하지 않는다.

확인 질문:

1. 파일이 실제로 다운로드되었는가?
2. 다운로드 위치는 어디인가?
3. 이름만 `.apk`인 것은 아닌가?
4. 실제 파일 크기가 정상인가?
5. 전송 전후 해시를 비교할 수 있는가?
6. Android가 이 파일 설치를 허용하는가?
7. 앱 서명이나 버전 문제는 없는가?

뒤쪽 질문은 아직 완전히 이해하지 못해도 괜찮다.

중요한 것은 **문제를 단계로 나누는 사고방식**이다.

### 40. 한 장 요약

1. 파일은 이름이 아니라 실제 데이터를 가진 저장 묶음이다.
2. 폴더는 파일을 정리한다.
3. 경로는 파일 위치를 나타낸다.
4. 상대경로는 현재 작업 위치에 따라 다른 파일을 가리킬 수 있다.
5. 확장자는 실제 파일 형식을 자동으로 바꾸지 않는다.
6. 텍스트와 바이너리는 읽는 방식이 다르다.
7. 인코딩이 다르면 글자가 깨질 수 있다.
8. MIME은 데이터 종류를 알려주는 표지 역할을 한다.
9. 압축, 인코딩, 암호화는 목적이 다르다.
10. APK와 ZIP은 같은 종류가 아니다.
11. 파일 존재와 읽기 권한은 다른 문제다.
12. 해시는 파일 내용 비교에 강력한 도구다.
13. 해시가 같다고 안전한 출처가 보장되는 것은 아니다.
14. 파일 문제는 존재→경로→권한→형식→무결성→신뢰 순서로 좁힌다.

다음 장에서는 **파일로 저장된 프로그램을 실제로 실행하면 무슨 일이 생기는지**, 즉 프로그램과 프로세스, 작업 순서와 동시에 여러 일을 하는 문제를 처음부터 배운다.
