# TRACK 04 · 컴퓨터가 실제로 일하는 곳

TRACK 01에서는 CPU, RAM, 저장장치를 아주 짧게 배웠다.

이번 TRACK에서는 `앱이 느리다`, `메모리가 부족하다`, `저장공간이 꽉 찼다`, `CPU 사용률이 높다` 같은 말을 실제로 구분할 수 있을 정도까지 내려간다.

처음 보는 단어는 반드시 먼저 뜻을 만든다.

---

## BLOCK 01 · 컴퓨터 안에도 역할 분담이 있다

### LESSON 01 · 한 부품이 모든 일을 하지 않는다

컴퓨터 안에는 서로 다른 역할을 가진 부품과 소프트웨어가 함께 일한다.

아주 크게 보면:

```text
명령을 계산하는 곳
지금 쓸 정보를 올려두는 곳
오래 저장하는 곳
다른 장치와 데이터를 주고받는 곳
```

이 역할을 구분하면 성능 문제를 볼 때 `컴퓨터가 느리다`라는 말에서 한 단계 더 들어갈 수 있다.

---

## BLOCK 02 · CPU 다시 보기

### LESSON 01 · 명령을 처리하는 핵심 부품

**CPU(Central Processing Unit)**는 프로그램의 명령을 읽고 계산과 판단을 수행하는 핵심 부품이다.

한 줄 뜻:

> CPU = 프로그램의 명령을 실제로 계산하고 처리하는 핵심 장치

### LESSON 02 · CPU가 모든 것을 혼자 하는 것은 아니다

CPU가 일을 하려면 명령과 데이터가 필요하다.

그 데이터는 메모리에서 가져올 수 있고, 저장장치에서 읽어 와야 할 수도 있다.

화면을 그리는 일에는 GPU가 큰 역할을 할 수 있다.

즉 CPU가 중요하다고 해서 모든 성능 문제의 원인이 CPU라는 뜻은 아니다.

---

## BLOCK 03 · 코어란 무엇인가

### LESSON 01 · CPU 안의 실행 핵심

현대 CPU에는 여러 개의 **코어(core)**가 들어 있는 경우가 많다.

코어는 CPU 안에서 명령을 처리할 수 있는 실행 핵심이라고 이해하면 된다.

```text
4코어 CPU
= 명령을 처리할 수 있는 핵심 실행 단위가 4개인 CPU
```

### LESSON 02 · 코어가 두 배면 항상 두 배 빠른가

아니다.

프로그램이 일을 여러 부분으로 나눌 수 있어야 여러 코어를 잘 활용할 수 있다.

한 작업이 앞 작업 결과를 계속 기다려야 한다면 코어가 많아도 완벽하게 동시에 나눌 수 없다.

따라서:

```text
코어 수 두 배 = 모든 프로그램 속도 두 배
```

는 틀린 공식이다.

---

## BLOCK 04 · 클럭이라는 말

### LESSON 01 · CPU가 움직이는 기본 박자

CPU 설명에서 `GHz` 같은 숫자를 본 적이 있을 수 있다.

CPU의 **클럭(clock)**은 내부 동작을 맞추는 주기적인 신호와 관련된 개념이다.

GHz는 1초에 수십억 번 수준의 주기를 나타낸다.

초보 단계에서는:

> 클럭 = CPU 내부 동작 속도를 나타내는 중요한 요소 중 하나

정도로 이해한다.

### LESSON 02 · GHz가 높으면 무조건 더 빠른가

아니다.

CPU 설계, 한 번의 주기에서 처리하는 일, 코어 수, 메모리, 냉각, 프로그램 구조 등 여러 요소가 성능에 영향을 준다.

다른 CPU를 단순히 GHz 숫자 하나만 보고 비교하면 틀릴 수 있다.

---

## BLOCK 05 · 명령어라는 말

### LESSON 01 · CPU가 직접 처리할 수 있는 아주 낮은 수준의 명령

우리가 Python으로:

```python
total = a + b
```

라고 쓰더라도 CPU가 Python 글자를 사람처럼 읽는 것은 아니다.

프로그램 실행 과정에서 더 낮은 수준의 명령으로 바뀌어 처리된다.

CPU가 직접 이해하고 실행하도록 정의된 이런 낮은 수준의 명령들을 **기계 명령어(machine instruction)**라고 부른다.

### LESSON 02 · 고급 언어가 필요한 이유

사람이 모든 기계 명령을 직접 적는 것은 매우 어렵다.

그래서 Python, JavaScript, Kotlin처럼 사람이 더 읽기 쉬운 **고급 프로그래밍 언어**를 사용하고, 실행 환경이 CPU가 처리할 형태로 바꾸는 과정을 맡는다.

---

## BLOCK 06 · RAM을 더 정확히

### LESSON 01 · 실행 중인 프로그램이 빠르게 쓰는 공간

RAM은 실행 중인 프로그램의 코드와 데이터가 올라와 CPU가 빠르게 접근할 수 있게 하는 메모리다.

한 줄 뜻:

> RAM = 실행 중인 프로그램이 빠르게 사용할 코드와 데이터를 두는 주기억장치

### LESSON 02 · RAM이 꽉 차면

프로그램이 너무 많은 메모리를 사용하면 여유 RAM이 줄어든다.

운영체제는 사용하지 않는 앱을 종료하거나, 저장장치 일부를 보조 메모리처럼 이용할 수 있다.

이런 상황에서는 프로그램 전환이 느려지거나 앱이 종료될 수 있다.

---

## BLOCK 07 · 메모리 주소

### LESSON 01 · RAM 안에서도 위치가 필요하다

RAM에 데이터가 많으면 CPU는 필요한 데이터가 어디 있는지 알아야 한다.

메모리 안의 위치를 구분하기 위해 **메모리 주소(memory address)**라는 개념을 사용한다.

한 줄 뜻:

> 메모리 주소 = 메모리 안에서 특정 데이터 위치를 가리키는 번호

### LESSON 02 · 변수와 메모리 주소는 완전히 같은 말이 아니다

코드에서:

```python
score = 100
```

이라고 쓴 `score`는 프로그래머가 사용하는 이름이다.

실제 실행 과정에서는 언어와 실행 환경이 이 값을 메모리에 배치하고 관리한다.

초보자는 `변수 이름 = 실제 물리 메모리 주소`라고 단순하게 외우지 않는 것이 좋다.

---

## BLOCK 08 · 저장장치

### LESSON 01 · 오래 남기는 공간

SSD 같은 저장장치는 프로그램 파일, 사진, 문서 등을 오래 보관한다.

RAM보다 일반적으로 느리지만 전원을 꺼도 데이터가 남는다.

### LESSON 02 · 저장공간이 부족하면

저장공간이 거의 꽉 차면:

- 새 파일을 저장하지 못할 수 있다.
- 앱 업데이트가 실패할 수 있다.
- 임시 파일을 만들지 못할 수 있다.
- 운영체제 성능에 영향을 줄 수 있다.

`RAM 부족`과 `저장공간 부족`은 다른 문제다.

---

## BLOCK 09 · SSD와 HDD

### LESSON 01 · 저장장치 종류

**HDD**는 회전하는 자기 디스크를 사용하는 저장장치다.

**SSD**는 움직이는 디스크 없이 반도체 메모리를 사용한다.

일반적으로 SSD가 데이터 접근 속도가 훨씬 빠르다.

### LESSON 02 · 저장장치 속도도 하나의 숫자가 아니다

큰 파일을 순서대로 읽는 속도와 작은 파일을 여기저기 읽는 속도는 다를 수 있다.

그래서 제품의 `최대 MB/s` 숫자 하나만으로 실제 앱 성능을 모두 설명할 수 없다.

---

## BLOCK 10 · I/O란 무엇인가

### LESSON 01 · 입력과 출력의 줄임말

**I/O**는 `Input/Output`, 즉 입력과 출력을 줄여 부르는 말이다.

컴퓨터에서 I/O라고 할 때는 CPU와 다른 장치 사이에서 데이터를 주고받는 일을 넓게 가리킬 수 있다.

예:

```text
SSD에서 파일 읽기
네트워크에서 데이터 받기
키보드 입력 받기
화면으로 결과 보내기
```

### LESSON 02 · I/O 기다림

CPU는 매우 빠르게 계산할 수 있는데 저장장치나 네트워크에서 데이터가 오기를 기다리는 시간이 길 수 있다.

이때 프로그램이 느린 원인은 계산량이 아니라 **I/O 기다림**일 수 있다.

---

## BLOCK 11 · CPU-bound와 I/O-bound

### LESSON 01 · CPU-bound

프로그램 속도가 주로 CPU 계산량 때문에 제한되는 상황을 **CPU-bound**라고 부른다.

예:

```text
큰 수학 계산
영상 인코딩
복잡한 데이터 처리
```

### LESSON 02 · I/O-bound

속도가 주로 파일, 네트워크, 데이터베이스 같은 입출력 기다림 때문에 제한되는 상황을 **I/O-bound**라고 부른다.

예:

```text
서버 응답을 기다림
큰 파일을 디스크에서 읽음
```

이 구분은 성능 문제를 고칠 때 매우 중요하다.

CPU-bound인데 네트워크를 고쳐도 해결되지 않을 수 있다.

---

## BLOCK 12 · 캐시란 무엇인가

### LESSON 01 · 자주 쓰는 것을 가까이 두기

**캐시(cache)**는 자주 쓰거나 다시 만들기 비싼 데이터를 더 빠르게 꺼낼 수 있는 곳에 임시로 보관하는 방식이다.

일상 비유:

매번 창고까지 가기 싫어서 자주 쓰는 물건을 책상 서랍에 두는 것과 비슷하다.

### LESSON 02 · CPU 캐시

CPU에는 RAM보다 훨씬 작지만 더 빠른 캐시 메모리가 있다.

자주 필요한 데이터와 명령을 가까이 두어 메모리 접근 시간을 줄인다.

### LESSON 03 · 앱 캐시도 있다

앱도 인터넷에서 받은 이미지나 데이터를 캐시에 저장할 수 있다.

따라서 `캐시`는 CPU 안에만 있는 것이 아니다.

공통 생각은:

> 자주 다시 쓸 것을 더 빠른 곳에 보관해 반복 비용을 줄인다.

---

## BLOCK 13 · 캐시가 항상 좋은가

### LESSON 01 · 오래된 데이터 문제

캐시에 예전 데이터가 남아 있으면 서버의 최신 값과 다를 수 있다.

```text
서버 최신 가격 = 200
캐시 가격 = 180
화면 = 180
```

캐시 때문에 빠르게 보이지만 오래된 값을 보여 주는 문제가 생길 수 있다.

### LESSON 02 · 캐시 무효화

캐시에 있는 데이터가 더 이상 유효하지 않다고 판단해 버리거나 새로 받는 일을 **캐시 무효화(cache invalidation)**라고 부른다.

캐시에서 가장 어려운 문제 중 하나가 `언제 버릴 것인가`다.

---

## BLOCK 14 · GPU란 무엇인가

### LESSON 01 · 많은 계산을 나란히 처리하는 데 강한 장치

**GPU(Graphics Processing Unit)**는 원래 화면 그래픽 처리를 위해 발전한 연산 장치다.

많은 비슷한 계산을 병렬로 처리하는 데 강점이 있어 오늘날에는 그래픽뿐 아니라 AI 계산과 과학 계산에도 널리 사용된다.

### LESSON 02 · CPU와 GPU

아주 단순화하면:

```text
CPU = 다양한 일반 작업과 복잡한 제어에 강함
GPU = 많은 비슷한 계산을 대량 병렬 처리하는 데 강함
```

둘 중 하나가 무조건 더 좋은 것이 아니다.

작업 종류가 다르다.

---

## BLOCK 15 · NPU란 무엇인가

### LESSON 01 · AI 계산에 특화된 장치

**NPU(Neural Processing Unit)**는 신경망 기반 AI 계산을 효율적으로 처리하도록 설계된 연산 장치를 가리키는 말이다.

스마트폰과 PC에도 NPU가 들어가는 경우가 늘었다.

### LESSON 02 · NPU가 있다고 모든 AI가 자동으로 빨라지는가

아니다.

앱과 AI 모델이 해당 NPU를 지원하는 실행 환경과 형식으로 동작해야 한다.

하드웨어가 존재하는 것과 소프트웨어가 실제로 활용하는 것은 다른 문제다.

---

## BLOCK 16 · 버스와 데이터 이동

### LESSON 01 · 부품끼리 정보를 주고받아야 한다

CPU, RAM, 저장장치는 서로 떨어진 역할을 한다.

이 장치들은 데이터를 주고받을 연결 통로가 필요하다.

컴퓨터 구조에서 이런 통신 경로를 설명할 때 **버스(bus)**라는 말을 사용한다.

한 줄 뜻:

> 버스 = 컴퓨터 내부 부품 사이에서 데이터와 제어 정보를 전달하는 통로

### LESSON 02 · 계산만 빠르면 끝이 아니다

CPU가 아무리 빠르더라도 필요한 데이터를 메모리에서 충분히 빠르게 가져오지 못하면 기다릴 수 있다.

성능은 **계산 속도 + 데이터 이동 속도**를 함께 봐야 한다.

---

## BLOCK 17 · 메모리 대역폭

### LESSON 01 · 한 번에 얼마나 많이 옮길 수 있나

**대역폭(bandwidth)**은 일정 시간 동안 얼마나 많은 데이터를 전달할 수 있는지를 나타내는 개념이다.

메모리 대역폭이 높으면 CPU나 GPU가 메모리와 더 많은 데이터를 빠르게 주고받을 수 있다.

### LESSON 02 · 지연시간과 대역폭은 다르다

**지연시간(latency)**은 요청한 뒤 결과가 오기까지 걸리는 시간을 뜻한다.

**대역폭**은 일정 시간에 얼마나 많은 양을 전달할 수 있는지다.

비유:

```text
지연시간 = 첫 차가 목적지까지 도착하는 데 걸리는 시간
대역폭 = 한 시간에 통과할 수 있는 차의 수
```

둘은 관련 있지만 같은 숫자가 아니다.

---

## BLOCK 18 · 가상 메모리

### LESSON 01 · RAM보다 큰 공간이 필요한 경우

운영체제는 프로그램마다 자신만의 큰 메모리 공간을 사용하는 것처럼 보이게 관리한다.

이런 메모리 주소 체계를 **가상 메모리(virtual memory)**라고 부른다.

### LESSON 02 · 저장장치를 보조로 사용하는 경우

RAM이 부족하면 운영체제가 당장 덜 쓰는 메모리 내용을 저장장치 쪽으로 옮겼다가 다시 가져올 수 있다.

Windows에서는 페이지 파일, Linux에서는 swap 같은 이름을 볼 수 있다.

저장장치는 RAM보다 훨씬 느리기 때문에 이런 이동이 잦으면 성능이 크게 떨어질 수 있다.

---

## BLOCK 19 · 메모리 누수

### LESSON 01 · 더 이상 필요 없는 메모리를 계속 잡고 있다면

프로그램이 메모리를 사용한 뒤 더 이상 필요하지 않은데도 계속 놓아주지 않는 문제가 생길 수 있다.

이런 현상을 **메모리 누수(memory leak)**라고 부른다.

한 줄 뜻:

> 메모리 누수 = 필요 없어진 메모리가 계속 점유되어 사용량이 점점 늘어나는 문제

### LESSON 02 · 증상

메모리 누수가 있으면:

```text
앱을 오래 쓸수록 메모리 사용량 증가
점점 느려짐
결국 강제 종료
```

같은 증상이 나타날 수 있다.

하지만 메모리 사용량이 증가했다고 무조건 누수라고 단정하지 않는다. 캐시나 정상 데이터 증가일 수도 있다.

---

## BLOCK 20 · 운영체제 커널

### LESSON 01 · 하드웨어와 프로그램 사이의 핵심 관리자

운영체제에서 가장 핵심적인 부분을 **커널(kernel)**이라고 부른다.

커널은 CPU 시간, 메모리, 장치, 프로세스 같은 중요한 자원을 관리한다.

한 줄 뜻:

> 커널 = 운영체제에서 하드웨어와 실행 중인 프로그램의 핵심 자원을 관리하는 중심 부분

### LESSON 02 · 앱이 하드웨어를 마음대로 만지는 것이 아니다

일반 앱은 보통 운영체제가 제공하는 방법을 통해 파일, 네트워크, 카메라 같은 기능을 사용한다.

이 구조가 보안과 안정성에 중요하다.

---

## BLOCK 21 · 시스템 콜

### LESSON 01 · 프로그램이 운영체제에 일을 요청하는 방법

프로그램이 파일을 읽거나 네트워크 통신을 시작하려면 운영체제 기능이 필요하다.

사용자 프로그램이 커널 기능을 요청하는 정해진 진입 방법을 **시스템 콜(system call)**이라고 부른다.

한 줄 뜻:

> 시스템 콜 = 프로그램이 운영체제 커널의 기능을 사용하기 위해 요청하는 정해진 방법

### LESSON 02 · 고급 언어에서는 직접 보이지 않을 수 있다

Python에서 `open()`으로 파일을 열면 내부적으로 운영체제의 파일 기능을 사용한다.

프로그래머가 매번 시스템 콜을 직접 적지 않아도 라이브러리와 실행 환경이 중간을 연결한다.

---

## BLOCK 22 · 컨텍스트 스위칭

### LESSON 01 · CPU가 다른 작업으로 바꾸기

CPU 코어 하나가 여러 프로세스와 스레드를 번갈아 실행할 수 있다.

한 작업의 실행 상태를 저장하고 다른 작업의 상태를 불러와 실행하는 것을 **컨텍스트 스위칭(context switching)**이라고 부른다.

한 줄 뜻:

> 컨텍스트 스위칭 = CPU가 실행하던 작업을 멈추고 다른 작업으로 전환하기 위해 상태를 바꾸는 과정

### LESSON 02 · 전환도 공짜는 아니다

작업을 바꾸려면 상태를 저장하고 복원하는 비용이 든다.

스레드를 무조건 많이 만들면 더 빨라지는 것이 아닌 이유 중 하나다.

---

## BLOCK 23 · 온도와 쓰로틀링

### LESSON 01 · 빠르게 일하면 열이 난다

CPU와 GPU가 높은 성능으로 오래 일하면 열이 발생한다.

온도가 너무 높아지면 하드웨어를 보호하기 위해 동작 속도를 낮출 수 있다.

이를 **열 쓰로틀링(thermal throttling)**이라고 부른다.

한 줄 뜻:

> thermal throttling = 온도가 너무 높을 때 장치를 보호하려고 성능을 낮추는 동작

### LESSON 02 · 처음엔 빠른데 나중에 느려지는 이유

같은 작업을 반복할 때 처음에는 빠르다가 시간이 지나면서 느려진다면 열에 따른 성능 제한도 후보가 될 수 있다.

하지만 반드시 온도 문제라고 단정하지 않고 측정해야 한다.

---

## BLOCK 24 · 병목이란 무엇인가

### LESSON 01 · 가장 느린 부분이 전체 속도를 제한한다

공장에 여러 공정이 있다고 하자.

```text
A: 1초
B: 10초
C: 1초
```

전체 생산 속도는 B 공정 때문에 크게 제한된다.

이렇게 전체 성능을 제한하는 부분을 **병목(bottleneck)**이라고 부른다.

### LESSON 02 · 컴퓨터의 병목 후보

병목은 여러 곳에 있을 수 있다.

```text
CPU 계산
RAM 부족
저장장치 I/O
네트워크
GPU
데이터베이스
락 대기
```

따라서 `느리다 → CPU 업그레이드`처럼 바로 결론 내리면 안 된다.

---

## BLOCK 25 · 측정하지 않으면 추측이다

### LESSON 01 · baseline

수정 전의 기준 성능을 **baseline(기준값)**이라고 부른다.

예:

```text
검색 완료 평균 3.2초
CPU 35%
메모리 420MB
```

수정 후 같은 조건으로 다시 측정해야 정말 좋아졌는지 알 수 있다.

### LESSON 02 · 프로파일링

프로그램이 어느 함수에서 시간을 많이 쓰고 메모리를 얼마나 쓰는지 측정하는 작업을 **프로파일링(profiling)**이라고 부른다.

한 줄 뜻:

> profiling = 프로그램이 실제로 어디에서 시간과 자원을 쓰는지 측정하는 일

## BLOCK 26 · 성능 문제를 찾는 기본 순서

### LESSON 01 · 증상을 숫자로 바꾸기

나쁜 기록:

```text
앱이 느림
```

좋은 기록:

```text
앱 시작 후 첫 화면까지 평균 5.4초
검색 버튼 후 결과 표시까지 3.8초
```

### LESSON 02 · 자원을 나눠 본다

다음 후보를 각각 확인한다.

```text
CPU 사용률은 높은가?
메모리가 계속 늘어나는가?
저장장치 읽기/쓰기가 긴가?
네트워크 응답이 늦은가?
화면 렌더링이 느린가?
```

한 번에 하나씩 증거를 모은다.

## BLOCK 27 · TRACK 04 핵심 용어 사전

| 용어 | 아주 쉬운 뜻 |
|---|---|
| CPU | 프로그램 명령을 계산하고 처리하는 핵심 장치 |
| 코어 | CPU 안에서 명령을 처리할 수 있는 실행 핵심 |
| 클럭 | CPU 내부 동작 속도를 나타내는 요소 중 하나 |
| RAM | 실행 중인 프로그램이 빠르게 사용하는 메모리 |
| 메모리 주소 | 메모리 안의 위치를 가리키는 번호 |
| 저장장치 | 데이터를 오래 보관하는 장치 |
| I/O | 장치 사이의 입력과 출력 |
| CPU-bound | CPU 계산이 속도를 주로 제한하는 상태 |
| I/O-bound | 입출력 기다림이 속도를 주로 제한하는 상태 |
| 캐시 | 자주 쓸 데이터를 더 빠른 곳에 임시 저장하는 방식 |
| GPU | 많은 비슷한 계산을 병렬 처리하는 데 강한 연산 장치 |
| NPU | 신경망 AI 계산에 특화된 연산 장치 |
| 버스 | 컴퓨터 내부 부품 사이의 데이터 통로 |
| bandwidth | 일정 시간 동안 전달할 수 있는 데이터 양 |
| latency | 요청 후 결과가 오기까지 걸리는 시간 |
| 가상 메모리 | 프로그램마다 독립된 메모리 공간처럼 보이게 관리하는 체계 |
| 메모리 누수 | 필요 없는 메모리가 계속 점유되어 늘어나는 문제 |
| 커널 | 운영체제의 핵심 자원 관리 부분 |
| 시스템 콜 | 프로그램이 커널 기능을 요청하는 방법 |
| 컨텍스트 스위칭 | CPU가 실행 작업을 바꾸며 상태를 전환하는 과정 |
| thermal throttling | 과열을 막기 위해 성능을 낮추는 동작 |
| 병목 | 전체 속도를 가장 크게 제한하는 부분 |
| baseline | 수정 전 비교 기준값 |
| profiling | 실제 시간과 자원 사용 위치를 측정하는 일 |

## BLOCK 28 · TRACK 04 종합 훈련

### LESSON 01 · RAM과 저장공간 구분

상황 A:

```text
휴대폰 저장공간 256GB 중 255GB 사용
RAM은 충분
```

상황 B:

```text
저장공간 100GB 여유
RAM은 거의 가득 참
```

두 상황에서 어떤 문제가 생길 수 있는지 각각 설명한다.

### LESSON 02 · 병목 후보 찾기

동영상 변환 프로그램이 CPU 100%를 쓰면서 오래 걸린다.

→ CPU-bound 가능성이 높다.

웹 API 호출 프로그램이 CPU 5%인데 응답 하나에 10초 걸린다.

→ 네트워크 또는 서버 I/O 기다림을 먼저 의심할 수 있다.

### LESSON 03 · 캐시 오류

서버에는 최신 데이터가 있는데 앱 화면에는 옛날 값이 나온다.

다음 질문을 적는다.

```text
앱이 캐시를 읽고 있는가?
캐시 생성 시각은 언제인가?
언제 무효화되는가?
새 요청은 실제로 나갔는가?
```

## BLOCK 29 · TRACK 04 완료 기준

다음을 자기 말로 설명할 수 있어야 한다.

- CPU, RAM, 저장장치의 역할 차이
- 코어가 많다고 모든 프로그램이 정확히 그 배수로 빨라지지 않는 이유
- CPU-bound와 I/O-bound의 차이
- 캐시가 왜 빠르게 만들 수 있고 동시에 오래된 값 문제도 만들 수 있는지
- GPU와 CPU의 큰 역할 차이
- 대역폭과 지연시간의 차이
- 가상 메모리가 왜 필요한지
- 메모리 누수가 무엇인지
- 커널과 시스템 콜이 무엇인지
- 컨텍스트 스위칭이 왜 비용이 있는지
- 열 쓰로틀링이 무엇인지
- 병목을 측정 없이 단정하면 안 되는 이유

### TRACK 끝 미니 프로젝트 · 내 컴퓨터 성능 진단표

실제 기기에서 한 작업을 고른다.

예:

```text
앱 실행
큰 파일 압축
사진 100장 열기
웹페이지 로딩
```

수정하기 전에 다음을 기록한다.

```text
작업 시간:
CPU 사용률:
메모리 사용량:
저장장치 활동:
네트워크 사용 여부:
온도/발열 느낌 또는 측정값:
```

그 다음 가장 가능성이 높은 병목 후보를 하나만 고르고 근거를 적는다.

추측이 아니라 측정값으로 설명할 수 있어야 이 TRACK을 통과한다.
