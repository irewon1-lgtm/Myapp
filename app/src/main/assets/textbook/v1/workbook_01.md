# 1장 실전 훈련편 — 값·상태·JSON·파싱·캐시

이 훈련편은 본문 설명을 반복하지 않는다. 직접 결과를 예상하고, 데이터를 고치고, 오류 원인을 좁히는 데만 사용한다.

## 훈련 A. 타입을 눈으로 구분하지 말고 동작으로 확인하기

다음 네 값의 타입을 먼저 적는다.

```text
1200
"1200"
true
null
```

그 다음 아래 코드를 실행한다.

```python
values = [1200, "1200", True, None]
for value in values:
    print(value, type(value))
```

### 변형 1

아래 코드의 결과를 실행 전에 적는다.

```python
print(100 + 20)
print("100" + "20")
print(str(100) + "20")
print(int("100") + 20)
```

실행 후 틀린 예상이 있으면 왜 틀렸는지 한 문장으로 적는다.

### 변형 2 — 실패까지 확인

```python
print(int("백"))
```

실행해 오류 종류를 확인한다. 목표는 오류 이름 암기가 아니라 **모든 문자열을 숫자로 변환할 수 있는 것은 아니다**라는 사실을 실행으로 확인하는 것이다.

## 훈련 B. 데이터가 “보인다”와 “계산 가능하다” 구분하기

다음 두 응답을 비교한다.

```json
{"symbol":"AAA","price":1200}
```

```json
{"symbol":"AAA","price":"1200"}
```

두 응답 모두 화면에는 `1,200`이라고 표시할 수 있다.

아래 Python 코드에서 각각 어떤 일이 생기는지 확인한다.

```python
price = 1200
print(price + 100)
```

```python
price = "1200"
print(price + 100)
```

두 번째 코드가 실패하면, 화면 표시 테스트만으로 데이터 타입 정상 여부를 검증할 수 없는 이유를 적는다.

## 훈련 C. JSON 경로 찾기 8문제

아래 JSON을 사용한다.

```json
{
  "company": {
    "name": "Alpha",
    "listed": true,
    "quote": {
      "price": 15200,
      "currency": "KRW",
      "change": -300
    },
    "financials": {
      "revenue": 5000000,
      "operatingMargin": 0.123,
      "fcf": null
    },
    "tags": ["AI", "software", "KOSDAQ"]
  }
}
```

답을 `company → ...` 형식으로 적는다.

1. 회사 이름 경로
2. 현재가격 경로
3. 통화 경로
4. 영업이익률 경로
5. FCF 경로
6. tags는 객체인가 배열인가
7. listed는 문자열인가 참/거짓 값인가
8. fcf가 `null`이면 숫자 0으로 계산해도 되는가

정답 확인 전에 직접 JSON 구조를 손가락이나 펜으로 따라간다.

## 훈련 E. `null`, 0, 빈 문자열을 같은 값으로 취급하면 생기는 문제

재무 데이터 세 개를 보자.

```json
[
  {"company":"A","profit":0},
  {"company":"B","profit":null},
  {"company":"C","profit":""}
]
```

각 값의 의미를 구분한다.

- `0`: 실제 값이 0일 수 있음
- `null`: 값 없음/제공 안 됨일 수 있음
- `""`: 빈 문자열. 잘못된 데이터 계약일 수도 있음

다음 규칙 중 어떤 것이 위험한지 고른다.

```text
모든 null을 0으로 바꾼다.
모든 빈 문자열을 0으로 바꾼다.
원본 상태를 보존하고 계산 가능 여부를 별도로 판정한다.
```

마지막 방식이 왜 더 안전한지 데이터 분석 관점으로 설명한다.

## 훈련 F. 파싱 성공과 검증 성공 분리하기

다음 응답은 JSON 문법상 정상이다.

```json
{
  "symbol": "AAA",
  "price": -500,
  "asOfDate": "2099-01-01"
}
```

파싱은 성공한다. 하지만 현재 주가 데이터라고 가정하면 다음을 검증해야 한다.

```text
price가 허용되는 범위인가?
asOfDate가 미래가 아닌가?
symbol이 요청한 종목과 같은가?
필수 필드가 빠지지 않았는가?
```

### 직접 검증 코드

```python
from datetime import date

record = {
    "symbol": "AAA",
    "price": -500,
    "asOfDate": "2099-01-01"
}

errors = []
if record["price"] < 0:
    errors.append("negative price")
if record["asOfDate"] > str(date.today()):
    errors.append("future date")

print(errors)
```

오류 조건을 하나 더 추가해본다.

## 훈련 H. 퍼센트 표시 오류

원본 API:

```json
{"operatingMargin":0.153}
```

정의:

```text
0.153 = 비율(ratio)
화면에는 15.3%로 표시
```

다음 코드 중 맞는 것을 찾는다.

```python
value = 0.153
print(f"{value}%")
```

```python
value = 0.153
print(f"{value * 100:.1f}%")
```

그 다음 다음 상황의 원인을 분류한다.

```text
원본 0.153
파싱 0.153
DB 0.153
화면 0.153%
```

원본 수집 문제가 아니라 표시 변환 문제다.

## 디버깅 미션 1 — 문자열 정렬

코드:

```python
prices = ["9", "100", "20"]
print(sorted(prices))
```

먼저 결과를 예상하고 실행한다.

원하는 것은 숫자 오름차순이다. 최소 수정으로 고친다.

한 가지 방법:

```python
prices = ["9", "100", "20"]
print(sorted(prices, key=int))
```

이 코드가 원본 값을 문자열 상태로 유지하면서 정렬 기준만 숫자로 쓰는 이유를 설명한다.

---

## 디버깅 미션 2 — 결측값 평균

데이터:

```python
values = [10, None, 20, None, 30]
```

다음 코드는 실패한다.

```python
print(sum(values) / len(values))
```

원하는 정책은 `None`을 제외한 실제 숫자 평균이다.

직접 수정한다.

```python
valid = [v for v in values if v is not None]
print(sum(valid) / len(valid))
```

그 다음 질문에 답한다.

- `None`을 0으로 바꾸면 평균은 어떻게 왜곡되는가?
- valid가 빈 리스트라면 무엇을 해야 하는가?

# 1장 훈련 완료 기준

다음은 암기시험이 아니다. 실제로 할 수 있는지 본다.

- 숫자와 문자열 오류를 코드 실행으로 재현할 수 있다.
- 중첩 JSON에서 원하는 필드 경로를 찾는다.
- JSON 문법 성공과 데이터 검증 성공을 구분한다.
- `null`, 0, 빈 문자열을 같은 값으로 처리하지 않는다.
- 원본→파싱→상태→UI 중 값이 처음 달라지는 위치를 찾는다.
- 캐시/표시 오류를 API 오류와 구분한다.
- AI의 과도한 결론을 단계별 증거로 반박한다.
- 작은 데이터 계약을 직접 설계한다.
