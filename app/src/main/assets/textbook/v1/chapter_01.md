## V1-C01. 컴퓨터와 코드의 첫 지도 — 화면 뒤에서 무슨 일이 일어날까?

**이 장의 대상:** 코딩을 한 번도 배운 적이 없는 사람. `JSON`, `API`, `서버`, `바이트` 같은 말을 처음 듣는 사람.

**이 장의 약속:** 어려운 영어를 먼저 던지지 않는다. 새 용어는 반드시 **쉬운 한국어 → 영어 이름 → 실제 예 → 짧은 코드 → 직접 확인** 순서로 설명한다.

**이 장에서 꼭 기억할 한 문장:** 컴퓨터 프로그램은 **입력을 받고 → 규칙대로 처리하고 → 결과를 보여주는 것**이다.

---

### 1. 컴퓨터는 도대체 무슨 일을 하는 기계일까?

컴퓨터를 처음 배울 때 가장 먼저 생기는 오해는 “컴퓨터 안에는 뭔가 엄청 복잡한 일이 한꺼번에 일어난다”는 느낌이다. 실제로는 아주 단순한 일을 매우 빠르게 반복한다.

우리가 컴퓨터에게 하는 일은 크게 세 단계로 생각할 수 있다.

1. **입력:** 사람이 컴퓨터에게 무엇인가를 준다.
2. **처리:** 컴퓨터가 정해진 규칙대로 일을 한다.
3. **출력:** 처리한 결과를 보여준다.

예를 들어 계산기 앱에서 `2 + 3`을 입력한다고 하자.

```text
입력: 2와 3, 그리고 + 버튼
처리: 두 수를 더한다
출력: 5
```

주식 앱에서 종목명을 검색하는 것도 같은 구조다.

```text
입력: "삼성전자"
처리: 해당 종목 데이터를 찾는다
출력: 가격과 회사 정보를 화면에 보여준다
```

카카오톡에서 메시지를 보내는 것도 마찬가지다.

```text
입력: "안녕"
처리: 메시지를 전송할 준비를 한다
출력: 내 화면에 전송된 메시지를 표시한다
```

지금 단계에서는 컴퓨터가 내부에서 정확히 어떤 전자회로를 쓰는지 몰라도 된다. 먼저 **입력 → 처리 → 출력**이라는 세 칸을 머릿속에 만들어두는 것이 중요하다.

#### 쉬운 비유

자판기를 떠올려 보자.

```text
동전을 넣는다        → 입력
음료 버튼을 누른다    → 입력
자판기가 조건을 확인한다 → 처리
음료가 나온다        → 출력
```

컴퓨터 프로그램도 비슷하다. 다만 자판기보다 훨씬 많은 규칙과 데이터를 다룰 수 있을 뿐이다.

#### 직접 확인

다음 중 입력은 무엇일까?

- 화면에 표시된 계산 결과
- 키보드로 입력한 숫자
- 프로그램이 내부에서 계산하는 과정

정답은 **키보드로 입력한 숫자**다.

다음 중 출력은 무엇일까?

- 사용자가 누른 버튼
- 계산된 결과가 화면에 나타난 것
- 프로그램 파일을 설치한 것

정답은 **계산된 결과가 화면에 나타난 것**이다.

이 구분은 나중에 버그를 찾을 때 매우 중요하다. “버튼을 눌렀는데 아무것도 안 나온다”는 말은 **입력은 들어갔는데 처리 또는 출력 중 어딘가에서 문제가 생겼다**는 뜻이 될 수 있기 때문이다.

### 2. 프로그램과 앱은 무엇일까?

**프로그램**은 컴퓨터가 따라야 할 명령을 모아 놓은 것이다.

스마트폰에서는 우리가 보통 프로그램을 **앱(application)**이라고 부른다. `application`은 영어로 “응용 프로그램”이라는 뜻이다. 지금은 영어를 외울 필요 없다. **앱 = 스마트폰에서 실행하는 프로그램**이라고 생각하면 된다.

예를 들어:

- 계산기 앱
- 카메라 앱
- 주식 앱
- 일정 앱
- 게임

모두 프로그램이다.

프로그램은 사람이 원하는 일을 컴퓨터에게 시키기 위한 **규칙 묶음**이다.

#### 코드라는 말

프로그램을 만들기 위해 사람이 적는 명령을 **코드(code)**라고 부른다.

코드는 컴퓨터에게 하는 지시를 사람이 읽을 수 있는 형태로 적은 것이다.

아주 간단한 예를 보자.

```python
print("안녕")
```

이 코드는 컴퓨터에게 다음과 같이 말하는 것과 비슷하다.

```text
화면에 "안녕"이라고 보여줘.
```

여기서 처음 보는 영어가 하나 있다.

**print(프린트)**: 값을 화면에 보여주는 명령.

아직 `print`를 외우려고 하지 말자. 지금은 **코드 한 줄이 컴퓨터에게 하나의 행동을 시킬 수 있다**는 것만 이해하면 된다.

#### 코드가 실행된다는 뜻

코드를 적는 것과 실행하는 것은 다르다.

공책에 요리법을 적어 놓았다고 음식이 자동으로 만들어지지 않는 것과 같다.

```text
코드 작성 = 요리법을 적어 놓음
코드 실행 = 실제로 요리법을 따라 요리함
```

컴퓨터가 코드를 실제로 읽고 명령을 수행하는 것을 **실행(run)**이라고 한다.

`run`은 영어지만 앱에서 자주 보게 되므로 지금부터 의미만 기억하자.

> **Run = 실행하기**

### 3. 컴퓨터는 코드를 어떤 순서로 실행할까?

초보자가 코드를 읽을 때 가장 먼저 익혀야 할 습관은 **위에서 아래로 한 줄씩 따라가는 것**이다.

```python
print("첫 번째")
print("두 번째")
print("세 번째")
```

실행 결과는 보통 다음 순서다.

```text
첫 번째
두 번째
세 번째
```

왜냐하면 프로그램이 위에서 아래로 차례대로 명령을 읽기 때문이다.

물론 나중에는 조건문, 반복문, 함수처럼 실행 순서를 바꾸는 기능도 배운다. 하지만 처음에는 **한 줄씩 순서대로 실행된다**는 감각부터 잡으면 된다.

#### 직접 예상해 보기

```python
print("A")
print("B")
```

실행 결과는 무엇일까?

```text
A
B
```

이 간단한 “실행 전에 결과를 예상하는 습관”이 나중에 코딩 실력을 크게 좌우한다.

### 4. 값이란 무엇일까?

코딩에서는 **값(value)**이라는 말을 매우 자주 쓴다.

어렵게 생각할 필요 없다.

> **값 = 프로그램이 다루는 실제 내용**

예를 들어 다음은 모두 값이다.

```text
10
1200
"안녕"
"삼성전자"
true
```

지금은 마지막 `true`는 몰라도 된다. 중요한 것은 숫자나 글자처럼 프로그램이 실제로 다루는 내용이 “값”이라는 것이다.

#### 숫자와 글자는 다르다

사람 눈에는 `1200`과 `"1200"`이 거의 똑같아 보인다.

하지만 컴퓨터는 둘을 다르게 취급할 수 있다.

```python
number = 1200
text = "1200"
```

첫 번째는 **숫자 1200**이다.

두 번째는 **글자 네 개로 이루어진 문자열 "1200"**이다.

여기서 새 용어가 나온다.

**문자열(string)**: 글자들이 이어진 값.

`string`은 영어다. 지금은 이렇게 기억하면 된다.

> **문자열 = 글자로 된 값**

예를 들어:

```text
"안녕"
"AAPL"
"1200"
"서울시 송파구"
```

모두 문자열이다.

#### 왜 숫자와 문자열을 구분해야 할까?

숫자는 계산할 수 있다.

```python
print(10 + 20)
```

결과:

```text
30
```

하지만 문자열은 글자를 이어 붙일 수 있다.

```python
print("10" + "20")
```

결과:

```text
1020
```

사람 눈에는 비슷해 보여도 컴퓨터는 **숫자 10**과 **글자 "10"**을 다르게 본다.

이 차이를 이해하지 못하면 나중에 API 데이터, 데이터베이스, 계산식에서 이상한 결과가 나왔을 때 원인을 찾기 어렵다.

#### 아주 중요한 초보자 규칙

코드에서 따옴표가 있으면 일단 **글자일 가능성이 높다**고 생각하자.

```python
100      # 숫자
"100"    # 문자열
```

지금은 이것만 구분해도 충분하다.

### 5. 변수는 무엇일까?

값을 계속 직접 적으면 불편하다.

예를 들어 병원 이름을 코드에서 여러 번 쓴다고 해보자.

```python
print("프라임내과")
print("프라임내과")
print("프라임내과")
```

이름이 바뀌면 세 군데를 모두 고쳐야 한다.

그래서 값에 이름을 붙여 저장한다.

```python
hospital = "프라임내과"
print(hospital)
```

여기서 `hospital`은 값에 붙인 이름이다.

이런 이름을 **변수(variable)**라고 한다.

영어를 먼저 외우지 말고 이렇게 기억하자.

> **변수 = 값을 기억하기 위해 붙인 이름표**

#### 상자 비유

상자를 하나 준비하고 겉에 `hospital`이라고 적는다.

그 안에 `프라임내과`라는 값을 넣는다고 생각하면 된다.

```text
┌────────────────┐
│ hospital       │  ← 이름표
│ 프라임내과       │  ← 값
└────────────────┘
```

실제로 컴퓨터 내부가 정말 상자 모양인 것은 아니다. 하지만 초보자가 변수의 역할을 이해하기에는 좋은 비유다.

#### 값은 바뀔 수 있다

```python
price = 100
price = 120
print(price)
```

처음에는 `price`에 100이 들어간다.

그 다음 줄에서 120으로 바뀐다.

따라서 마지막 결과는:

```text
120
```

이렇게 프로그램 안에서 값이 바뀌는 것을 이해하면 나중에 **상태**라는 개념을 훨씬 쉽게 배울 수 있다.

### 6. 상태란 무엇일까?

앱을 사용하다 보면 같은 버튼을 눌러도 결과가 다를 때가 있다.

예를 들어 로그인 버튼을 생각해 보자.

```text
로그인 안 됨 → 로그인 버튼을 누름 → 로그인 화면
로그인 됨    → 같은 버튼 위치를 누름 → 계정 화면
```

왜 결과가 다를까?

앱이 현재 상황을 기억하고 있기 때문이다.

이 현재 상황을 **상태(state)**라고 부른다.

> **상태 = 프로그램이 지금 기억하고 있는 현재 상황**

예를 들면:

- 로그인됨 / 로그인 안 됨
- 장바구니에 상품 0개 / 3개
- 검색어가 비어 있음 / 입력되어 있음
- 네트워크 연결됨 / 끊김
- 주가 데이터가 아직 안 옴 / 도착함

`state`라는 영어를 처음 봐도 괜찮다. 중요한 것은 **현재 값들의 조합이 프로그램의 행동을 바꾼다**는 사실이다.

#### 변수와 상태의 관계

변수 여러 개가 합쳐져 앱의 상태를 만들 수 있다.

```python
logged_in = True
cart_count = 3
```

지금은 `True` 문법을 몰라도 된다.

이 코드는 대충 다음 상황을 표현한다고 생각하면 된다.

```text
로그인 상태: 로그인됨
장바구니 상품 수: 3
```

### 7. 파일은 무엇일까?

앱을 껐다 켰는데도 어떤 정보가 남아 있는 경우가 있다.

예를 들어:

- 사진
- 다운로드한 문서
- 앱 설정
- 저장한 메모

이런 정보는 앱이 실행되는 동안만 기억하는 것이 아니라 **저장장치**에 보관될 수 있다.

그때 우리가 자주 만나는 형태가 **파일(file)**이다.

> **파일 = 저장장치에 보관하는 데이터 묶음**

파일에는 이름이 있다.

```text
photo.jpg
report.csv
memo.txt
app.apk
```

하지만 파일은 이름만 있는 것이 아니다.

실제로는 저장장치 안에 데이터가 들어 있다.

#### 폴더는 무엇일까?

파일을 정리하기 위해 **폴더(folder)**를 사용한다.

```text
Download/
  report.csv
  photo.jpg
```

`Download` 폴더 안에 두 파일이 있는 모습이다.

#### 경로는 무엇일까?

파일이 어디에 있는지 설명하는 주소를 **경로(path)**라고 한다.

예:

```text
Download/report.csv
```

지금은 절대경로, 상대경로 같은 어려운 구분을 배우지 않는다. 다음 장에서 아주 천천히 다룬다.

지금은 딱 하나만 기억하면 된다.

> **경로 = 파일이 있는 위치를 적은 주소**

### 8. 앱을 껐는데 값이 남는 이유

변수는 보통 프로그램이 실행되는 동안 값을 기억한다.

그런데 앱을 완전히 종료하면 그 값이 사라질 수 있다.

그래서 중요한 정보는 파일이나 데이터베이스 같은 **지속 저장소**에 저장한다.

“지속”이라는 말이 어렵다면 이렇게 생각하자.

```text
앱 실행 중에만 잠깐 기억 → 메모장에 잠깐 적은 것
앱을 꺼도 계속 보관      → 서랍에 문서를 넣어둔 것
```

나중에 데이터베이스를 배우기 전까지는 다음 정도로만 기억하면 된다.

> 앱이 꺼져도 남아야 하는 정보는 따로 저장해야 한다.

### 9. 인터넷은 무엇을 해주는가?

스마트폰 혼자 가지고 있는 정보만 사용한다면 인터넷이 필요하지 않을 수 있다.

하지만 주식 앱에서 최신 가격을 받아오거나, 메시지를 친구에게 보내거나, 날씨를 확인하려면 다른 컴퓨터와 정보를 주고받아야 한다.

인터넷은 여러 컴퓨터가 서로 통신할 수 있게 연결해주는 거대한 네트워크다.

**네트워크(network)**라는 말이 처음 나왔다.

> **네트워크 = 여러 기기가 서로 정보를 주고받을 수 있게 연결된 상태**

집의 Wi-Fi도 작은 네트워크다.

인터넷은 전 세계의 수많은 네트워크가 이어진 구조라고 생각하면 된다.

#### 택배 비유

내 스마트폰이 다른 컴퓨터에 정보를 요청하는 모습을 택배 주문에 비유해 보자.

```text
내 스마트폰      = 주문하는 사람
인터넷           = 도로
상대 컴퓨터       = 물건을 보내주는 가게
요청             = 주문서
응답             = 배달된 물건
```

비유는 완벽하지 않지만 처음 구조를 이해하는 데 도움이 된다.

---

### 10. 서버는 무엇일까?

앱이 인터넷을 통해 데이터를 받으려면 상대편에서 요청을 받아주는 컴퓨터나 프로그램이 필요하다.

그 역할을 하는 쪽을 흔히 **서버(server)**라고 부른다.

> **서버 = 다른 프로그램의 요청을 받아 필요한 결과를 돌려주는 쪽**

예를 들어 주식 앱이 최신 가격을 요청하면:

```text
내 앱: "AAPL 가격 알려줘"
서버: "현재 가격은 200이야"
```

이런 식으로 데이터를 주고받을 수 있다.

중요한 점은 서버가 꼭 거대한 기계 한 대라는 뜻은 아니라는 것이다. 서버라는 말은 **요청을 받아 처리하는 역할**을 뜻할 때가 많다.

하지만 지금은 여기까지만 이해하면 충분하다.

#### 클라이언트라는 말

요청을 보내는 쪽을 **클라이언트(client)**라고 부른다.

> **클라이언트 = 서버에게 요청을 보내는 쪽**

스마트폰 앱이 클라이언트가 될 수 있다.

웹 브라우저도 클라이언트가 될 수 있다.

지금은 아래 그림만 기억하자.

```text
[내 앱]  -- 요청 -->  [서버]
[내 앱]  <-- 응답 --  [서버]
```

---

### 11. 요청과 응답은 무엇일까?

**요청(request)**은 “이 일을 해줘”라고 보내는 메시지다.

**응답(response)**은 그 요청에 대한 결과다.

영어가 두 개 나왔으니 바로 번역해두자.

```text
request  = 요청
response = 응답
```

예를 들어:

```text
요청: AAPL 종목 정보 주세요.
응답: 이름은 Apple, 가격은 200입니다.
```

검색 앱에서도 같은 흐름이 있다.

```text
사용자가 검색어 입력
↓
앱이 요청을 만듦
↓
서버로 보냄
↓
서버가 결과를 찾음
↓
응답을 보냄
↓
앱이 결과를 화면에 표시
```

여기까지 이해하면 이미 “화면이 비었을 때 어디를 볼 것인가”라는 문제를 더 잘 생각할 수 있다.

예를 들어 버튼은 눌렸는데 결과가 없다면:

- 입력이 안 들어갔나?
- 요청을 안 만들었나?
- 인터넷이 끊겼나?
- 서버가 응답하지 않았나?
- 응답은 왔는데 화면 표시가 안 됐나?

처럼 문제 범위를 나눌 수 있다.

---

### 12. API는 무엇일까?

이제 `API`라는 말을 배워도 된다.

처음부터 어려운 정의를 외우지 말자.

> **API = 프로그램끼리 어떻게 요청하고 응답할지 정해 놓은 약속**

예를 들어 음식점 주문을 생각해 보자.

손님이 주방 안에 직접 들어가 요리사 냉장고를 뒤지지 않는다.

메뉴판에 있는 방식으로 주문한다.

```text
"김치찌개 1개 주세요"
```

주방은 주문을 받고 요리해서 결과를 준다.

API도 비슷하다.

앱이 서버 내부를 마음대로 건드리는 대신, 서버가 허용한 방식으로 요청한다.

```text
앱: /stocks/AAPL 정보를 주세요
서버: 허용된 형식으로 결과를 보냄
```

API는 영어 약자다.

`Application Programming Interface`라는 긴 말을 지금 외울 필요는 없다.

지금은 다음 하나만 기억하자.

> **API = 앱과 서버가 대화하는 약속된 창구**

#### API와 서버는 같은 말이 아니다

서버는 요청을 처리하는 쪽이고,

API는 그 서버와 어떤 방식으로 대화할지 정한 규칙이다.

```text
서버 = 가게
API  = 주문 창구와 주문 방법
```

---

### 13. 데이터는 어떤 모양으로 오갈까?

서버가 앱에게 여러 정보를 보내야 할 때가 있다.

예를 들어 한 종목에 대해:

```text
회사 이름: Apple
티커: AAPL
가격: 200
```

사람은 이런 문장을 이해할 수 있지만 컴퓨터끼리는 **일정한 규칙**으로 데이터를 정리하는 것이 편하다.

그때 자주 사용하는 형식 중 하나가 **JSON**이다.

여기서 가장 중요한 부분이다.

JSON을 처음 본다고 가정하고 한 글자씩 보자.

```json
{
  "name": "Apple",
  "symbol": "AAPL",
  "price": 200
}
```

처음 보면 괄호와 따옴표 때문에 복잡해 보인다.

하지만 뜻은 단순하다.

```text
name   → Apple
symbol → AAPL
price  → 200
```

#### JSON이란?

> **JSON = 이름과 값을 규칙적으로 정리해 놓은 데이터 표현 방식**

지금은 `JSON`이라는 영어 이름보다 뜻이 중요하다.

#### 중괄호 `{ }`

여러 정보를 하나로 묶었다는 표시다.

#### `"name"`

값의 이름이다.

#### `:`

이름과 값을 연결한다.

#### `"Apple"`

문자열 값이다.

#### `200`

숫자 값이다.

따라서:

```json
"price": 200
```

은 대략 이런 뜻이다.

```text
price라는 이름의 값은 숫자 200이다.
```

#### JSON은 데이터베이스가 아니다

이 차이는 매우 중요하다.

JSON은 **데이터를 표현하는 모양**이다.

데이터베이스는 **데이터를 저장하고 찾도록 관리하는 시스템**이다.

비유하면:

```text
JSON = 택배 상자 안에 물건을 정리하는 포장 방식
DB   = 물건을 오래 보관하고 찾는 창고
```

둘은 역할이 다르다.

---

### 14. 객체라는 말은 무엇일까?

코딩을 하다 보면 **객체(object)**라는 말을 자주 듣게 된다.

하지만 첫 장에서 객체지향 프로그래밍을 배우려는 것은 아니다.

지금은 아주 간단하게만 이해하자.

```json
{
  "name": "Apple",
  "price": 200
}
```

이처럼 여러 관련 값을 하나로 묶어 다루는 구조를 프로그램 안에서 객체라고 부르는 경우가 많다.

> **객체 = 관련된 값들을 하나의 묶음으로 다루는 구조라고 일단 생각하기**

나중에 Python과 JavaScript를 배우면 객체라는 말이 조금씩 다르게 사용되는 이유를 다시 배운다.

첫 장에서는 절대로 세부 개념을 외울 필요 없다.

---

### 15. 파싱은 무엇일까?

서버에서 JSON 형태의 글자가 도착했다고 하자.

앱은 이 데이터를 읽고 내부에서 사용할 수 있는 값으로 바꿔야 한다.

이렇게 정해진 형식의 데이터를 읽어 구조를 알아내는 일을 **파싱(parsing)**이라고 부른다.

> **파싱 = 정해진 형식의 데이터를 읽어서 프로그램이 사용할 수 있게 해석하는 과정**

예를 들어 JSON에:

```json
{
  "price": 200
}
```

이 들어 있다면 앱은 `price`가 200이라는 사실을 읽어낼 수 있다.

#### 파서라는 말

파싱을 하는 프로그램이나 코드 부분을 **파서(parser)**라고 부를 수 있다.

```text
parsing = 데이터를 해석하는 작업
parser  = 그 작업을 하는 코드나 도구
```

지금 화면처럼 처음부터 “parser에서 단위가 틀렸는지 확인한다”라고 말하면 초보자는 이해할 수 없다.

그래서 이 책에서는 **뜻을 먼저 이해하고 영어 이름은 나중에 붙인다.**

---

### 16. 캐시는 무엇일까?

앱을 사용할 때 같은 데이터를 매번 인터넷에서 다시 받으면 느릴 수 있다.

그래서 이전에 받아온 데이터를 잠깐 저장해 두었다가 다시 사용하는 경우가 있다.

이 임시 저장 공간을 **캐시(cache)**라고 부른다.

> **캐시 = 자주 쓰는 데이터를 다시 빨리 쓰기 위해 잠깐 보관해 두는 것**

예를 들어 어제 본 종목 가격을 앱이 기억해두었다가 앱을 켜자마자 먼저 보여줄 수 있다.

그 다음 인터넷에서 최신 가격을 받아와 화면을 갱신할 수 있다.

```text
앱 실행
↓
저장해둔 과거 값 먼저 표시
↓
최신 값 요청
↓
응답 도착
↓
화면 갱신
```

이때 인터넷 요청이 실패하면 과거 캐시 값만 계속 보일 수도 있다.

그래서 “화면에 숫자가 보인다”는 사실만으로 최신 데이터라고 확정하면 안 된다.

---

### 17. UI는 무엇일까?

앱 화면을 설명할 때 **UI**라는 말을 자주 쓴다.

UI는 `User Interface`의 약자다.

긴 영어를 외우지 말자.

> **UI = 사용자가 보고 누르고 입력하는 화면 부분**

예:

- 버튼
- 검색창
- 종목 카드
- 메뉴
- 숫자 표시
- 그래프

UI는 최종 결과가 보이는 장소다.

중요한 점은 **화면에 문제가 보인다고 해서 원인이 반드시 UI에 있는 것은 아니라는 것**이다.

가격이 이상하게 보일 때:

```text
서버가 잘못된 값을 줬을 수도 있고
↓
앱이 데이터를 잘못 읽었을 수도 있고
↓
저장된 과거 값이 남아 있을 수도 있고
↓
마지막 표시 과정에서 단위를 잘못 붙였을 수도 있다.
```

화면은 결과가 나타나는 마지막 장소일 뿐이다.

---

### 18. 바이트는 무엇일까?

여기까지 이해한 뒤에야 **바이트(byte)**라는 말을 배운다.

컴퓨터는 결국 전기적인 상태를 이용해 정보를 표현한다.

가장 작은 단위를 설명할 때 **비트(bit)**라는 말을 사용한다.

비트는 0 또는 1 같은 두 상태 중 하나를 나타낼 수 있다.

```text
0
1
```

보통 8개의 비트를 묶어 **1바이트(byte)**라고 한다.

```text
8 bit = 1 byte
```

왜 이것을 알아야 할까?

파일 크기, 메모리, 네트워크 전송량을 이야기할 때 바이트 단위를 자주 보기 때문이다.

```text
KB
MB
GB
```

지금은 계산식을 외울 필요 없다.

딱 하나만 기억하자.

> **글자, 사진, 음악, 프로그램도 결국 컴퓨터 안에서는 바이트 형태의 데이터로 저장된다.**

---

### 19. 글자는 컴퓨터 안에서 어떻게 저장될까?

사람은 `가`라는 글자를 보면 바로 이해한다.

하지만 컴퓨터는 글자 모양 자체를 기억하는 것이 아니라 숫자 규칙을 이용해 문자를 표현한다.

세계 여러 문자를 함께 표현하기 위한 큰 문자 규칙을 **유니코드(Unicode)**라고 한다.

그리고 그 문자를 실제 바이트로 저장하는 대표 방식 중 하나가 **UTF-8**이다.

처음 배우는 사람은 이 문장을 외우지 않아도 된다.

아래만 기억하면 된다.

```text
Unicode = 어떤 문자를 어떤 번호로 볼지 정한 큰 약속
UTF-8   = 그 문자를 실제 바이트로 저장하는 대표 방법
```

#### 왜 필요한가?

한글 파일이 다른 프로그램에서 깨지는 경험을 한 적이 있을 수 있다.

예:

```text
정상: 안녕하세요
깨짐: ì•ˆë…•í•˜ì„¸ìš”
```

이런 문제는 같은 바이트를 서로 다른 문자 규칙으로 해석했을 때 생길 수 있다.

초보자가 여기서 해야 할 일은 `Unicode` 번호를 외우는 것이 아니다.

> **글자는 저장할 때도 규칙이 필요하고, 읽을 때도 같은 규칙으로 해석해야 한다.**

이 감각만 가지면 충분하다.

---

### 20. 클라우드는 무엇일까?

**클라우드(cloud)**라는 말은 마치 데이터가 하늘에 떠 있는 것처럼 들린다.

실제로는 인터넷을 통해 다른 컴퓨터의 저장공간이나 프로그램을 사용하는 것이다.

> **클라우드 = 내 기기 밖의 컴퓨터 자원을 인터넷으로 사용하는 방식**

예를 들어 사진을 클라우드에 저장한다는 말은 보통 사진 데이터가 인터넷을 통해 서비스 회사의 컴퓨터로 전송되어 저장된다는 뜻이다.

```text
내 스마트폰
↓ 인터넷
서비스 회사의 컴퓨터
↓
저장
```

첫 장에서는 `load balancer`, `object storage` 같은 세부 서버 용어를 배우지 않는다.

그런 용어는 나중에 네트워크와 서버를 충분히 이해한 뒤에 다룬다.

지금은:

> 클라우드도 결국 다른 컴퓨터다.

이 문장만 기억하면 된다.

---

### 21. 지금까지 배운 것을 하나의 흐름으로 연결하기

이제 처음으로 전체 지도를 본다.

처음 화면에서 이런 지도를 바로 보여주면 어렵지만, 지금까지 용어를 하나씩 배웠기 때문에 의미를 따라갈 수 있다.

```text
사람이 버튼을 누른다
        ↓
앱의 화면(UI)이 입력을 받는다
        ↓
앱의 코드가 실행된다
        ↓
현재 상태를 확인한다
        ↓
필요하면 저장된 파일/데이터를 읽는다
        ↓
최신 정보가 필요하면 인터넷으로 요청한다
        ↓
서버가 요청을 처리한다
        ↓
응답 데이터가 돌아온다
        ↓
앱이 데이터를 읽고 값으로 만든다
        ↓
상태를 바꾼다
        ↓
화면(UI)이 새 값을 보여준다
```

이 흐름은 앞으로 계속 다시 등장한다.

하지만 지금은 모든 단계를 외우지 않는다.

**입력 → 처리 → 저장/통신 → 결과** 정도로만 큰 덩어리를 기억하면 된다.

### 22. 실제 예제 1 — 검색 버튼을 눌렀는데 아무것도 안 보인다

사용자가 주식 앱에서 `AAPL`을 입력하고 검색 버튼을 눌렀다.

그런데 화면에 아무 결과도 나오지 않는다.

초보자는 보통 이렇게 말한다.

> “앱이 고장났어.”

하지만 이제는 더 구체적으로 생각할 수 있다.

#### 단계 1: 입력은 들어갔을까?

검색창에 `AAPL`이 실제로 입력되어 있는지 확인한다.

#### 단계 2: 버튼 동작은 실행됐을까?

버튼을 눌렀을 때 코드가 실행되는지 확인한다.

#### 단계 3: 요청을 만들었을까?

서버에 데이터를 요청하는 동작이 시작됐는지 확인한다.

#### 단계 4: 인터넷은 연결되어 있을까?

기기 전체 네트워크 상태를 본다.

#### 단계 5: 서버 응답은 왔을까?

서버가 정상 결과를 보냈는지 본다.

#### 단계 6: 앱이 응답을 읽었을까?

받은 데이터를 파싱하는 과정에서 오류가 났는지 확인한다.

#### 단계 7: 상태가 바뀌었을까?

새 값이 앱의 현재 상태에 저장됐는지 확인한다.

#### 단계 8: 화면이 상태를 보여줬을까?

데이터는 있는데 UI가 갱신되지 않았을 수도 있다.

이렇게 문제를 여러 구간으로 나누는 습관을 **범위 좁히기**라고 생각할 수 있다.

영어로는 `isolation`이라는 말을 쓰기도 하지만 지금은 한국어 의미가 더 중요하다.

> **범위 좁히기 = 어디까지 정상이고 어디부터 실패했는지 찾는 것**

### 23. 실제 예제 2 — 가격이 100인데 화면에는 10000으로 나온다

이 문제는 화면 숫자만 보고 UI 버그라고 단정하면 안 된다.

가능한 원인은 여러 가지다.

```text
원본 서버 값이 10000이었을 수 있음
↓
앱이 100에 100을 곱했을 수 있음
↓
저장된 과거 값이 10000일 수 있음
↓
화면 표시 과정에서 단위를 잘못 적용했을 수 있음
```

이때 중요한 것은 **추측으로 고치지 않는 것**이다.

먼저 단계별 값을 확인한다.

```text
서버에서 온 값: ?
파싱 직후 값: ?
저장된 값: ?
화면에 넘긴 값: ?
화면에 표시된 값: ?
```

어느 지점에서 처음 값이 달라지는지 찾는다.

이것이 나중에 디버깅을 배울 때 핵심 원칙이 된다.

### 24. 실제 예제 3 — "100"과 100 때문에 생기는 오류

다음 코드를 보자.

```python
price = "100"
fee = 20
```

사람은 둘 다 숫자처럼 보인다고 생각할 수 있다.

하지만 `price`는 문자열이고 `fee`는 숫자다.

이 상태에서 바로 더하려고 하면 언어에 따라 오류가 나거나 예상하지 못한 결과가 생길 수 있다.

초보자가 가장 먼저 할 일은:

1. 값이 무엇인지 본다.
2. 따옴표가 있는지 본다.
3. 숫자인지 문자열인지 구분한다.

#### 따라 하기

```python
number_price = 100
text_price = "100"

print(number_price)
print(text_price)
```

화면에는 둘 다 `100`처럼 보일 수 있다.

하지만 프로그램 안에서는 종류가 다르다.

이것이 **보이는 것과 내부 표현이 다를 수 있다**는 첫 번째 중요한 경험이다.

### 25. 실제 예제 4 — 앱을 다시 켰는데 예전 값이 보인다

앱을 켰더니 어제 가격이 먼저 보이고 몇 초 뒤 최신 가격으로 바뀌었다.

이 현상은 무조건 버그가 아니다.

앱이 빠르게 화면을 보여주기 위해 저장해둔 과거 값을 먼저 보여주고, 그 뒤 최신 데이터를 받아왔을 수 있다.

```text
과거 캐시 표시
↓
최신 값 요청
↓
최신 응답 도착
↓
상태 변경
↓
화면 갱신
```

반대로 최신 요청이 실패한다면 과거 값만 계속 남을 수도 있다.

그래서 사용자는 “화면에 숫자가 있으니 최신이겠지”라고 가정하면 안 된다.

앱을 만드는 사람은 데이터의 **기준 시각**을 함께 표시하는 것이 좋다.

#### 4줄

`price`에 들어 있는 값을 출력한다.

```text
AAPL
200
```

이렇게 **코드를 우리말 행동으로 바꾸어 읽는 능력**이 코딩의 출발점이다.

- Unicode 세부 규칙

- JSON 문법 전체
- API 주소 형식 전체
- 서버 종류
- 네트워크 프로토콜
- 객체지향 프로그래밍
- 데이터베이스 내부 구조

이것들은 뒤에서 따로 배운다.

첫 장의 목표는 **용어 암기**가 아니라 **큰 지도 만들기**다.

---

### 37. 이 장을 마치기 전에 반드시 설명할 수 있어야 하는 12가지

아래 질문에 한 문장씩 답해본다.

1. 컴퓨터 프로그램의 기본 흐름은 무엇인가?
2. 프로그램과 앱은 어떤 관계인가?
3. 코드란 무엇인가?
4. 실행한다는 것은 무엇인가?
5. 값이란 무엇인가?
6. 숫자 100과 문자열 `"100"`은 왜 다를 수 있는가?
7. 변수란 무엇인가?
8. 상태란 무엇인가?
9. 파일과 폴더는 무엇인가?
10. 서버와 클라이언트의 역할은 무엇인가?
11. API는 무엇인가?
12. JSON은 무엇인가?

완벽한 전문용어가 필요하지 않다.

예를 들어 API를 다음처럼 말해도 충분하다.

> 앱이 서버랑 대화할 때 쓰는 정해진 방법.

이 정도로 자기 말로 설명할 수 있으면 성공이다.

---

### 38. 부모에게 설명하듯 말해보기

코딩을 정말 이해했는지 확인하는 좋은 방법은 **모르는 사람에게 쉬운 말로 설명하는 것**이다.

다음 말을 10살 아이에게 설명한다고 생각해보자.

#### 프로그램

“컴퓨터가 어떤 순서로 일을 해야 하는지 적어놓은 명령 묶음이야.”

#### 변수

“값을 기억해두려고 붙이는 이름표야.”

#### 서버

“내 앱이 뭔가를 물어보면 멀리 있는 컴퓨터가 대답해주는 역할을 할 수 있어.”

#### API

“두 프로그램이 서로 어떤 방식으로 말할지 정한 약속이야.”

#### JSON

“컴퓨터끼리 정보를 주고받기 쉽게 이름과 값을 정리해놓은 모양이야.”

이 정도 수준으로 설명할 수 있다면 첫 장의 핵심은 이해한 것이다.

### 39. 다음 장과 연결

첫 장에서 파일이라는 말을 아주 가볍게 배웠다.

하지만 실제로 파일을 다루려면 아직 모르는 것이 많다.

- 파일은 어디에 저장되는가?
- 폴더 안의 폴더는 어떻게 표현하는가?
- `a/b/c.txt`는 무엇을 뜻하는가?
- `.jpg`, `.csv`, `.zip`, `.apk`는 왜 끝부분이 다른가?
- 파일 이름만 바꾸면 종류도 바뀌는가?
- 다운로드한 파일이 원본과 같은지 어떻게 확인하는가?
- 한글이 깨지는 이유는 무엇인가?

이것이 Chapter 2의 주제다.

**Chapter 2에서는 파일·폴더·경로를 완전 초보 기준에서 다시 시작한다.**

### 40. 한 장 요약

이 장에서 배운 모든 내용을 10줄로 줄이면 다음과 같다.

1. 컴퓨터 프로그램은 입력을 받아 처리하고 결과를 출력한다.
2. 앱은 스마트폰에서 사용하는 프로그램이다.
3. 코드는 컴퓨터에게 시킬 일을 적은 명령이다.
4. 값은 프로그램이 다루는 실제 내용이다.
5. 숫자와 문자열은 화면에서 같아 보여도 종류가 다를 수 있다.
6. 변수는 값을 기억하기 위해 붙인 이름이다.
7. 상태는 프로그램이 지금 기억하고 있는 현재 상황이다.
8. 서버는 요청을 처리하고 결과를 주는 역할을 할 수 있다.
9. API는 프로그램끼리 대화하는 약속된 창구다.
10. 화면은 긴 데이터 흐름의 마지막 결과이므로 오류가 보인 위치와 원인이 같은 곳이라고 단정하지 않는다.

이 10줄이 이해되면 Chapter 1은 통과다.
