# TRACK 03 · 자료구조와 알고리즘

TRACK 02에서는 값을 저장하고 조건·반복·함수로 프로그램을 만드는 법을 배웠다.

하지만 데이터가 10개가 아니라 100만 개라면 어떻게 해야 할까?

같은 답을 내는 코드라도 어떤 방법은 0.01초가 걸리고 어떤 방법은 몇 분이 걸릴 수 있다.

이 TRACK에서는 두 질문을 계속 반복한다.

> 데이터를 어떤 모양으로 저장할 것인가?

> 문제를 어떤 순서와 방법으로 풀 것인가?

첫 질문이 **자료구조(data structure)**, 두 번째 질문이 **알고리즘(algorithm)**과 연결된다.

---

## BLOCK 01 · 자료구조란 무엇인가

### LESSON 01 · 데이터를 담는 모양

데이터를 저장하고 꺼내고 수정하기 좋게 조직한 방식을 **자료구조(data structure)**라고 부른다.

예:

```text
순서대로 저장
이름으로 찾기
먼저 들어온 것부터 꺼내기
가장 큰 값부터 꺼내기
부모-자식 관계로 저장
```

목적에 따라 다른 구조가 유리하다.

### LESSON 02 · 하나의 최고 자료구조는 없다

배열이 모든 문제에 최고라면 다른 자료구조가 필요 없었을 것이다.

자료구조를 고를 때 본다.

```text
검색이 많은가?
추가·삭제가 많은가?
순서가 중요한가?
중복을 허용하는가?
최솟값/최댓값을 자주 찾는가?
관계를 표현해야 하는가?
```

---

## BLOCK 02 · 알고리즘이란 무엇인가

### LESSON 01 · 문제를 푸는 절차

**알고리즘(algorithm)**은 어떤 문제를 해결하기 위한 명확한 절차다.

라면 끓이기도 절차가 있다.

```text
물 넣기
물 끓이기
면 넣기
정해진 시간 기다리기
완성
```

컴퓨터 알고리즘도 입력을 받아 정해진 단계로 처리하고 결과를 만든다.

### LESSON 02 · 정답만 맞으면 충분한가

데이터 10개에서는 아무 방법이나 빨라 보일 수 있다.

데이터가 10억 개라면 차이가 커진다.

알고리즘은:

```text
정답을 내는가?
얼마나 오래 걸리는가?
메모리를 얼마나 쓰는가?
```

까지 본다.

## BLOCK 03 · 배열

### LESSON 01 · 순서대로 붙어 있는 값들

**배열(array)**은 같은 종류의 값을 순서대로 저장하는 대표적인 자료구조다.

Python의 list는 동적 배열과 비슷한 특성을 가진다.

```python
scores = [80, 90, 100]
```

### LESSON 02 · 인덱스로 바로 찾기

배열에서 위치 번호를 알면 해당 값을 매우 빠르게 찾을 수 있다.

```python
print(scores[2])
```

결과:

```text
100
```

### LESSON 03 · 중간 삽입은 비용이 들 수 있다

연속된 배열 중간에 새 값을 넣으려면 뒤의 값들을 옮겨야 할 수 있다.

```text
[A][B][C][D]
      ↑ 여기에 X 삽입
[A][B][X][C][D]
```

찾기는 빠르지만 중간 삽입은 비쌀 수 있다.

---

## BLOCK 04 · 동적 배열

### LESSON 01 · 크기가 늘어나는 배열

처음부터 크기를 고정하지 않고 필요하면 더 큰 공간을 확보해 늘어나는 배열을 **동적 배열(dynamic array)**이라고 부른다.

Python list, Java ArrayList, JavaScript Array는 내부 구현은 다르지만 동적 배열처럼 사용되는 대표 예다.

### LESSON 02 · 용량보다 많아지면

내부 공간이 꽉 차면 더 큰 공간을 만들고 기존 값을 옮길 수 있다.

매번 추가할 때 복사하는 것은 아니기 때문에 뒤에 값을 추가하는 작업은 평균적으로 빠르다.

이 `평균적인 비용`을 뒤에서 **amortized cost**라는 이름으로 배운다.

## BLOCK 05 · 연결 리스트

### LESSON 01 · 값과 다음 위치를 연결하기

**연결 리스트(linked list)**는 각 데이터 조각이 다음 데이터 조각을 가리키도록 연결한 구조다.

```text
[A | next] → [B | next] → [C | next] → 없음
```

각 조각을 **노드(node)**라고 부른다.

### LESSON 02 · 중간 삽입

삽입할 위치의 연결을 알고 있다면 주변 연결만 바꾸어 새 노드를 끼울 수 있다.

```text
A → B → C

A → B → X → C
```

배열처럼 뒤의 모든 값을 옮길 필요는 없다.

### LESSON 03 · 몇 번째 값을 바로 찾기 어렵다

배열은 `scores[500]`처럼 위치로 바로 접근할 수 있다.

연결 리스트는 앞에서부터 연결을 따라가야 한다.

따라서 500번째 노드를 찾으려면 많은 노드를 지나야 할 수 있다.

---

## BLOCK 06 · 단일 연결과 이중 연결

### LESSON 01 · 단일 연결 리스트

각 노드가 다음 노드만 가리키면 **단일 연결 리스트(singly linked list)**라고 부른다.

```text
A → B → C
```

### LESSON 02 · 이중 연결 리스트

각 노드가 앞과 뒤를 모두 가리키면 **이중 연결 리스트(doubly linked list)**라고 부른다.

```text
A ⇄ B ⇄ C
```

뒤로 이동하기 쉽지만 각 노드가 더 많은 연결 정보를 저장한다.

## BLOCK 07 · 스택

### LESSON 01 · 마지막에 넣은 것을 먼저 꺼낸다

접시를 쌓는 모습을 생각하자.

마지막에 올린 접시를 먼저 꺼낸다.

이 구조를 **스택(stack)**이라고 부른다.

```text
push A
push B
push C

꺼내기 → C
꺼내기 → B
꺼내기 → A
```

### LESSON 02 · LIFO

이 특징을 **LIFO(Last In, First Out)**라고 줄여 말한다.

```text
마지막에 들어온 것 → 먼저 나감
```

### LESSON 03 · 어디에 쓰나

```text
함수 호출 관리
실행 취소(undo)
괄호 검사
DFS 탐색
```

등에 사용된다.

## BLOCK 08 · 큐

### LESSON 01 · 먼저 들어온 것을 먼저 처리

은행 번호표 줄을 생각하자.

먼저 온 사람이 먼저 처리된다.

이 구조를 **큐(queue)**라고 부른다.

### LESSON 02 · FIFO

**FIFO(First In, First Out)**는:

```text
먼저 들어온 것 → 먼저 나감
```

이라는 뜻이다.

### LESSON 03 · 어디에 쓰나

```text
작업 대기열
프린터 요청
메시지 처리
BFS 탐색
```

등에 사용할 수 있다.

## BLOCK 09 · deque

### LESSON 01 · 양쪽에서 넣고 뺀다

**deque(double-ended queue)**는 앞과 뒤 양쪽에서 값을 넣고 뺄 수 있는 자료구조다.

```text
앞 ← [A][B][C] → 뒤
```

Python에서는 `collections.deque`를 사용할 수 있다.

### LESSON 02 · list의 앞 삭제와 비교

Python list에서 맨 앞 값을 계속 삭제하면 뒤의 요소를 이동해야 해서 느릴 수 있다.

deque는 앞과 뒤 삽입·삭제를 효율적으로 지원하도록 만들어졌다.

## BLOCK 10 · 집합

### LESSON 01 · 중복이 없는 값들

**집합(set)**은 중복을 허용하지 않는 값 모음이다.

```python
users = {"A", "B", "A"}
print(users)
```

결과에는 `A`가 한 번만 남는다.

### LESSON 02 · 포함 여부

`이 값이 있는가?`를 빠르게 확인할 때 set이 유용하다.

```python
if "A" in users:
    print("있음")
```

## BLOCK 11 · key와 value

### LESSON 01 · 위치 번호가 아니라 이름으로 찾기

학생 번호로 학생 정보를 찾고 싶다.

```text
1001 → 민수
1002 → 지수
```

왼쪽처럼 찾는 기준을 **key**, 오른쪽 정보를 **value**라고 부른다.

### LESSON 02 · map

key와 value를 연결해 저장하는 추상적인 자료구조를 **map** 또는 **dictionary**라고 부른다.

Python dict, Java HashMap, JavaScript Map 등이 예다.

---

## BLOCK 12 · 해시 함수

### LESSON 01 · key를 계산해서 위치를 찾기

**해시 함수(hash function)**는 입력 데이터를 받아 일정한 범위의 숫자나 해시값으로 바꾸는 함수다.

해시 테이블에서는 key를 해시 함수에 넣어 저장할 위치를 빠르게 찾는 데 사용한다.

```text
"minsu"
↓ hash
42
↓
42번 주변 저장 위치
```

### LESSON 02 · 보안용 해시와 자료구조용 해시는 목적이 다르다

해시 테이블의 목표는 빠른 저장 위치 계산이다.

비밀번호나 파일 무결성에 쓰는 암호학적 해시는 공격에 견디는 강한 성질이 필요하다.

`hash`라는 단어가 같다고 요구 조건이 모두 같은 것은 아니다.

---

## BLOCK 13 · 해시 테이블

### LESSON 01 · key로 빠르게 찾기

**해시 테이블(hash table)**은 key의 해시값을 이용해 데이터를 저장하고 찾는 자료구조다.

평균적인 상황에서 key 검색·삽입·삭제를 매우 빠르게 할 수 있다.

### LESSON 02 · 순서를 보장하는가

해시 테이블의 핵심 목적은 key 검색이다.

언어의 특정 dictionary 구현이 입력 순서를 보존할 수는 있지만 `해시 테이블이라는 개념 자체 = 항상 정렬된 순서`라고 생각하면 안 된다.

---

## BLOCK 14 · 해시 충돌

### LESSON 01 · 다른 key가 같은 위치를 원한다면

서로 다른 key가 같은 해시 위치로 계산될 수 있다.

이것을 **해시 충돌(hash collision)**이라고 부른다.

```text
A → 5
B → 5
```

### LESSON 02 · 충돌 해결

해시 테이블은 충돌을 처리하는 방법이 필요하다.

대표적으로:

```text
chaining = 한 위치에 여러 항목을 연결해 저장
open addressing = 다른 빈 위치를 찾아 저장
```

같은 방법이 있다.

세부 구현은 언어마다 다르다.

## BLOCK 15 · 트리

### LESSON 01 · 계층 관계

폴더 구조처럼 부모와 자식 관계를 표현하는 자료구조를 **트리(tree)**라고 부른다.

```text
        루트
       /    \
    자식1  자식2
    /  \
 손자1 손자2
```

### LESSON 02 · 용어

```text
root = 가장 위 노드
parent = 바로 위 연결 노드
child = 바로 아래 연결 노드
leaf = 자식이 없는 끝 노드
```

---

## BLOCK 16 · 이진 트리

### LESSON 01 · 자식이 최대 두 개

각 노드가 최대 두 개의 자식을 가지는 트리를 **이진 트리(binary tree)**라고 부른다.

```text
    A
   / \
  B   C
```

`이진`은 두 개라는 뜻과 연결된다.

### LESSON 02 · 이진 트리라고 자동으로 정렬되지는 않는다

이진 트리는 자식 수에 대한 구조다.

값의 크기 규칙까지 가진 **이진 탐색 트리**와는 다르다.

---

## BLOCK 17 · 이진 탐색 트리

### LESSON 01 · 작은 값은 왼쪽, 큰 값은 오른쪽

**이진 탐색 트리(Binary Search Tree, BST)**는 보통 다음 규칙을 가진다.

```text
왼쪽 서브트리 값 < 현재 값
오른쪽 서브트리 값 > 현재 값
```

중복 처리 규칙은 구현에 따라 다를 수 있다.

### LESSON 02 · 균형이 중요하다

값이 잘 퍼진 트리에서는 검색 범위를 계속 줄일 수 있다.

하지만 한쪽으로만 길게 늘어지면:

```text
1
 \
  2
   \
    3
     \
      4
```

연결 리스트처럼 느려질 수 있다.

---

## BLOCK 18 · 균형 트리 맛보기

### LESSON 01 · 높이를 너무 크게 만들지 않기

트리가 한쪽으로 치우치지 않도록 스스로 균형을 맞추는 트리를 **균형 이진 탐색 트리**라고 부른다.

대표적으로 AVL tree, Red-Black tree가 있다.

### LESSON 02 · 이름을 외우기보다 이유를 이해한다

목적은:

> 트리 높이가 지나치게 커져 검색 성능이 나빠지는 것을 막는 것

이다.

## BLOCK 19 · heap

### LESSON 01 · 가장 작은 값 또는 큰 값을 빠르게 꺼내기

**heap**은 최솟값이나 최댓값을 빠르게 찾는 데 유용한 트리 기반 자료구조다.

**min-heap**에서는 부모가 자식보다 작거나 같다.

### LESSON 02 · 정렬된 배열과는 다르다

heap 전체가 작은 순서대로 완전히 정렬되어 있는 것은 아니다.

가장 중요한 규칙은 루트에 최솟값 또는 최댓값이 위치하도록 유지하는 것이다.

---

## BLOCK 20 · priority queue

### LESSON 01 · 먼저 들어온 순서가 아니라 우선순위

응급실에서는 먼저 온 사람보다 위급한 환자를 먼저 치료할 수 있다.

이처럼 각 항목의 **우선순위(priority)**에 따라 꺼내는 구조를 **우선순위 큐(priority queue)**라고 부른다.

### LESSON 02 · heap으로 구현할 수 있다

heap은 priority queue를 구현하는 대표적인 방법이다.

```text
일반 queue → 들어온 순서
priority queue → 우선순위 순서
```

## BLOCK 21 · trie

### LESSON 01 · 문자열의 앞부분을 공유한다

**trie(트라이)**는 문자열의 글자 경로를 트리처럼 저장하는 자료구조다.

예:

```text
car
cat
can
```

는 `ca`라는 앞부분을 공유한다.

### LESSON 02 · 어디에 쓰나

```text
자동완성
접두사 검색
사전 검색
```

같은 작업에 유용하다.

## BLOCK 22 · 그래프

### LESSON 01 · 복잡한 연결 관계

사람 관계, 도로, 컴퓨터 네트워크처럼 여러 대상이 서로 연결된 구조를 **그래프(graph)**라고 부른다.

그래프의 대상 하나를 **정점(vertex)** 또는 node라고 부른다.

연결을 **간선(edge)**이라고 부른다.

### LESSON 02 · 방향 그래프

A에서 B로만 갈 수 있는 연결처럼 방향이 있는 그래프를 **방향 그래프(directed graph)**라고 부른다.

```text
A → B
```

### LESSON 03 · 무방향 그래프

친구 관계처럼 양방향 연결을 표현하는 그래프를 **무방향 그래프(undirected graph)**라고 부른다.

```text
A — B
```

## BLOCK 23 · 그래프 표현

### LESSON 01 · adjacency list

각 정점이 연결된 이웃 목록을 저장하는 방법을 **인접 리스트(adjacency list)**라고 부른다.

```python
graph = {
    "A": ["B", "C"],
    "B": ["A"],
    "C": ["A"]
}
```

### LESSON 02 · adjacency matrix

정점 두 개가 연결되었는지를 표 형태로 저장하는 방법을 **인접 행렬(adjacency matrix)**이라고 부른다.

정점 수가 많고 연결이 적을 때는 메모리를 많이 쓸 수 있다.

## BLOCK 24 · 탐색이란 무엇인가

### LESSON 01 · 원하는 데이터를 찾는 과정

자료구조 안에서 원하는 값을 찾는 일을 **탐색(search)**이라고 부른다.

가장 단순한 방법은 앞에서부터 하나씩 보는 것이다.

### LESSON 02 · 선형 탐색

```python
def find(items, target):
    for index, item in enumerate(items):
        if item == target:
            return index
    return -1
```

처음부터 끝까지 하나씩 찾는 방법을 **선형 탐색(linear search)**이라고 부른다.

## BLOCK 25 · 이진 탐색

### LESSON 01 · 정렬된 데이터의 절반씩 버리기

정렬된 숫자 목록에서 73을 찾는다고 하자.

가운데 값을 본다.

```text
가운데 < 73 → 왼쪽 절반은 버림
가운데 > 73 → 오른쪽 절반은 버림
```

이처럼 검색 범위를 절반씩 줄이는 방법을 **이진 탐색(binary search)**이라고 부른다.

### LESSON 02 · 반드시 정렬되어 있어야 한다

정렬되지 않은 배열에서 이진 탐색을 그대로 사용하면 틀린 결과가 나올 수 있다.

전제 조건을 확인해야 한다.

## BLOCK 26 · 정렬이란 무엇인가

### LESSON 01 · 순서를 정한다

값을 특정 기준에 따라 순서대로 배열하는 것을 **정렬(sort)**이라고 부른다.

```text
숫자 오름차순
가격 내림차순
이름 가나다순
```

### LESSON 02 · 정렬 기준

객체 목록에서는 어떤 필드를 기준으로 할지 정해야 한다.

```python
users = [
    {"name": "A", "age": 30},
    {"name": "B", "age": 20}
]
```

나이순과 이름순은 결과가 다르다.

## BLOCK 27 · selection sort

### LESSON 01 · 가장 작은 값을 찾아 앞으로

**선택 정렬(selection sort)**은 남은 구간에서 가장 작은 값을 찾아 앞쪽으로 옮기는 과정을 반복한다.

```text
[4, 2, 3, 1]
가장 작은 1을 찾아 맨 앞으로
[1, 2, 3, 4] 방향으로 반복
```

### LESSON 02 · 이해는 쉽지만 큰 데이터에는 느리다

매 단계마다 남은 값을 많이 비교하기 때문에 데이터가 커질수록 비교 횟수가 빠르게 늘어난다.

## BLOCK 28 · insertion sort

### LESSON 01 · 카드 정리처럼 끼워 넣기

손에 든 카드를 정렬한다고 생각하자.

새 카드를 정렬된 앞부분의 알맞은 위치에 끼워 넣는다.

이 방식이 **삽입 정렬(insertion sort)**과 비슷하다.

### LESSON 02 · 거의 정렬된 데이터

데이터가 이미 거의 정렬되어 있으면 삽입 정렬이 좋은 성능을 낼 수 있다.

알고리즘 성능은 입력 상태에 따라 달라질 수 있다.

## BLOCK 29 · merge sort

### LESSON 01 · 반으로 나누고 다시 합친다

**병합 정렬(merge sort)**은 목록을 계속 반으로 나누고 작은 정렬 결과를 합친다.

```text
[4,1,3,2]
↓
[4,1] [3,2]
↓
[4] [1] [3] [2]
↓ 정렬하며 합치기
[1,4] [2,3]
↓
[1,2,3,4]
```

### LESSON 02 · 분할 정복

큰 문제를 작은 문제로 나누어 각각 해결한 뒤 합치는 전략을 **분할 정복(divide and conquer)**이라고 부른다.

병합 정렬은 대표적인 예다.

## BLOCK 30 · quick sort

### LESSON 01 · 기준값을 잡아 나누기

**퀵 정렬(quick sort)**은 **피벗(pivot)**이라는 기준값을 잡고 작은 값과 큰 값을 나누는 과정을 반복한다.

### LESSON 02 · 평균과 최악이 다르다

좋은 피벗이 선택되면 빠르지만 계속 치우친 분할이 발생하면 성능이 나빠질 수 있다.

따라서 알고리즘은 평균 성능뿐 아니라 최악의 경우도 본다.

## BLOCK 31 · 실행 횟수 세기

### LESSON 01 · 데이터가 두 배면 일이 얼마나 늘까

```python
for item in items:
    print(item)
```

항목이 10개면 약 10번 반복한다.

100개면 약 100번이다.

### LESSON 02 · 이중 반복

```python
for a in items:
    for b in items:
        compare(a, b)
```

항목이 10개면 약 100번 비교한다.

100개면 약 10,000번이다.

데이터 크기에 따라 작업량 증가 방식이 완전히 다르다.

## BLOCK 32 · Big-O

### LESSON 01 · 데이터가 커질 때 증가 속도 표현

입력 크기가 커질 때 연산량이 얼마나 빠르게 증가하는지 크게 표현하는 방법을 **Big-O 표기법**이라고 부른다.

### LESSON 02 · O(1)

입력 크기와 관계없이 필요한 작업 수가 거의 일정한 경우:

```text
O(1)
```

이라고 표현한다.

배열에서 알고 있는 인덱스의 값을 읽는 작업이 대표적이다.

### LESSON 03 · O(n)

데이터 n개를 한 번씩 보는 작업은:

```text
O(n)
```

이다.

### LESSON 04 · O(n²)

n개를 대상으로 중첩 반복을 두 번 하면:

```text
O(n²)
```

형태가 될 수 있다.

## BLOCK 33 · O(log n)

### LESSON 01 · 매번 절반씩 줄이기

이진 탐색은 매 단계 검색 범위를 절반으로 줄인다.

```text
1,024개
→ 512
→ 256
→ 128
→ ...
```

이런 증가 형태를 **O(log n)**이라고 표현한다.

### LESSON 02 · 왜 강력한가

데이터가 크게 늘어도 단계 수는 천천히 증가한다.

```text
1,024개 → 약 10단계
1,048,576개 → 약 20단계
```

## BLOCK 34 · O(n log n)

### LESSON 01 · 효율적인 비교 정렬에서 자주 본다

병합 정렬과 일반적인 효율적 정렬 알고리즘의 평균/최악 시간에서 **O(n log n)**을 자주 본다.

`n개를 여러 단계로 나누고 각 단계에서 n개 정도를 처리한다`고 생각하면 감을 잡기 쉽다.

## BLOCK 35 · 공간복잡도

### LESSON 01 · 시간만 중요한 것이 아니다

알고리즘이 추가 메모리를 얼마나 사용하는지도 중요하다.

입력 크기에 따라 필요한 추가 공간 증가를 **공간복잡도(space complexity)**라고 부른다.

### LESSON 02 · 시간과 메모리 교환

해시 테이블을 사용하면 메모리를 더 쓰는 대신 검색을 빠르게 만들 수 있다.

```text
더 많은 메모리 ↔ 더 빠른 검색
```

처럼 서로 교환 관계가 생기기도 한다.

## BLOCK 36 · amortized cost

### LESSON 01 · 가끔 비싼 작업이 있어도 평균은 싸다

동적 배열에 값을 추가할 때 대부분은 빠르지만 가끔 더 큰 배열로 복사해야 해서 비싸다.

많은 작업 전체에 그 비용을 나누어 평균적으로 평가하는 것을 **amortized analysis**라고 부른다.

### LESSON 02 · append의 평균 비용

동적 배열의 뒤에 값을 추가하는 작업은 일반적으로 **amortized O(1)**로 설명된다.

`매번 무조건 O(1)`과는 조금 다른 의미다.

## BLOCK 37 · 재귀와 call stack

### LESSON 01 · 함수 호출이 쌓인다

재귀 함수가 자신을 계속 호출하면 호출 정보가 **call stack**에 쌓인다.

종료 조건이 없으면 너무 많이 쌓여 stack overflow가 발생할 수 있다.

### LESSON 02 · 재귀와 반복

많은 재귀 알고리즘은 반복문으로 바꿀 수 있다.

트리 탐색처럼 재귀가 구조를 자연스럽게 표현하는 경우도 있다.

가독성, 깊이, 성능을 고려한다.

## BLOCK 38 · BFS

### LESSON 01 · 가까운 곳부터 넓게

그래프에서 시작점과 가까운 정점부터 단계별로 탐색하는 방법을 **너비 우선 탐색(Breadth-First Search, BFS)**이라고 부른다.

보통 queue를 사용한다.

### LESSON 02 · 최단 거리

간선마다 비용이 같은 그래프에서는 BFS로 시작점에서 각 정점까지 최소 간선 수 거리를 찾을 수 있다.

```text
친구 관계 몇 단계 떨어졌나?
미로에서 최소 이동 횟수는?
```

같은 문제에 사용할 수 있다.

## BLOCK 39 · DFS

한 경로를 가능한 깊이 따라가다가 돌아오는 탐색을 **깊이 우선 탐색(Depth-First Search, DFS)**이라고 부른다.

재귀 또는 stack으로 구현할 수 있다.

```text
경로 탐색
트리 순회
```

등에 활용한다.

## BLOCK 41 · greedy

### LESSON 02 · 항상 최적은 아니다

매 순간 좋아 보이는 선택이 전체 최적 결과를 보장하지 않는 문제도 있다.

그리디를 사용하려면 왜 지역 최적 선택이 전체 최적으로 이어지는지 증명할 수 있어야 한다.

## BLOCK 42 · dynamic programming

### LESSON 01 · 같은 작은 문제를 반복하지 않기

큰 문제를 작은 부분 문제로 나눴는데 같은 부분 문제를 여러 번 계산하는 경우가 있다.

결과를 저장해 재사용하는 전략을 **동적 계획법(dynamic programming, DP)**이라고 부른다.

### LESSON 02 · memoization

함수 계산 결과를 저장해 같은 입력이 오면 다시 계산하지 않는 방식을 **메모이제이션(memoization)**이라고 부른다.

```python
cache = {}

def fib(n):
    if n in cache:
        return cache[n]
    if n <= 1:
        return n
    cache[n] = fib(n - 1) + fib(n - 2)
    return cache[n]
```

## BLOCK 43 · 알고리즘의 정확성

### LESSON 01 · 몇 개 예제에서 맞았다고 항상 맞는가

테스트 10개가 모두 성공해도 모든 입력에서 정답이라고 증명된 것은 아니다.

### LESSON 02 · 불변식

반복 중에도 항상 참이어야 하는 성질을 **불변식(invariant)**이라고 부른다.

예를 들어 정렬 알고리즘에서:

```text
앞쪽 구간은 항상 정렬되어 있다
```

같은 성질을 유지하며 진행한다고 설명할 수 있다.

- selection/insertion/merge/quick sort의 큰 생각을 설명한다.
- O(1), O(log n), O(n), O(n log n), O(n²)의 증가 차이를 설명한다.
- 시간복잡도와 공간복잡도의 차이를 설명한다.
- BFS와 DFS를 직접 구현한다.
- greedy가 항상 정답을 보장하지 않는 이유를 말한다.
- memoization으로 중복 계산을 줄인다.
- 빈 입력·한 개·중복 값 같은 경계를 테스트한다.

### TRACK 프로젝트 · 길찾기와 친구 추천 엔진

다음 데이터를 그래프로 표현한다.

```text
A는 B, C와 친구
B는 D와 친구
C는 D, E와 친구
E는 F와 친구
```

필수 구현:

1. adjacency list를 만든다.
2. BFS로 A에서 F까지 최소 친구 단계 수를 구한다.
3. DFS로 A에서 도달 가능한 모든 사람을 찾는다.
4. 이미 방문한 사람을 set으로 관리한다.
5. 사람이 10명, 100명, 10,000명일 때 어떤 자료구조가 필요한지 설명한다.
6. BFS의 시간복잡도를 정점 V와 간선 E 기준으로 설명한다.

정답 숫자만 맞히는 것이 아니라 **왜 queue를 사용했고 왜 visited set이 필요한지** 설명할 수 있어야 통과다.
