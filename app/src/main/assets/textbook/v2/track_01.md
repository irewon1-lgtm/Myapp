# TRACK 01 · 컴퓨터와 프로그래밍의 언어

이 TRACK은 컴퓨터를 거의 모르는 사람을 기준으로 시작한다.

목표는 어려운 용어를 빨리 외우는 것이 아니다. `컴퓨터가 무엇을 하고 있는지`를 눈앞의 상황으로 설명할 수 있게 만드는 것이다.

규칙은 세 가지다.

1. 처음 나오는 말은 먼저 쉬운 뜻을 만든다.
2. 모르는 말을 또 다른 모르는 말로 설명하지 않는다.
3. 코드는 보기만 하지 않고 예상 → 실행 → 수정 → 오류 확인까지 한다.

---

## BLOCK 01 · 컴퓨터란 무엇인가

### LESSON 01 · 가장 쉬운 정의

컴퓨터는 정보를 받아 정해진 규칙대로 처리하고 결과를 내놓는 기계다.

```text
입력
↓
처리
↓
출력
```

계산기에 `2 + 3`을 누르면:

```text
입력 = 2, +, 3
처리 = 더하기
출력 = 5
```

### LESSON 02 · 컴퓨터가 알아서 의도를 읽지는 않는다

사람이 잘못된 규칙을 만들면 컴퓨터는 그 규칙도 정확하게 수행한다.

따라서 코딩에서 중요한 능력은 `코드를 많이 타이핑하는 것`보다 **내가 어떤 규칙을 만들었는지 검증하는 것**이다.

---

## BLOCK 02 · 입력·처리·출력

### LESSON 01 · 입력

**입력(input)**은 프로그램 안으로 들어오는 정보다.

키보드 글자, 화면 터치, 마이크 소리, 카메라 영상, 파일, 네트워크 데이터가 입력이 될 수 있다.

### LESSON 02 · 처리

**처리(processing)**는 들어온 정보를 규칙에 따라 계산·비교·변경하는 일이다.

### LESSON 03 · 출력

**출력(output)**은 처리 결과가 밖으로 나오는 것이다.

화면, 소리, 파일 저장, 다른 프로그램으로 보내는 데이터도 출력이 될 수 있다.

---

## BLOCK 03 · 하드웨어와 소프트웨어

### LESSON 01 · 하드웨어

손으로 만질 수 있는 컴퓨터 장치와 부품을 **하드웨어(hardware)**라고 부른다.

예:

```text
화면
키보드
CPU
RAM
SSD
카메라
```

### LESSON 02 · 소프트웨어

컴퓨터가 어떤 일을 하도록 만드는 프로그램과 관련 정보를 **소프트웨어(software)**라고 부른다.

```text
하드웨어 = 기계 쪽
소프트웨어 = 프로그램 쪽
```

둘은 함께 일한다.

---

## BLOCK 04 · CPU

### LESSON 01 · 명령을 처리하는 핵심 부품

**CPU**는 프로그램의 명령을 읽고 계산과 판단을 수행하는 핵심 부품이다.

한 줄 뜻:

> CPU = 프로그램 명령을 실제로 계산하고 처리하는 장치

### LESSON 02 · CPU가 모든 것을 저장하지는 않는다

CPU는 사진과 문서를 오래 보관하는 창고가 아니다.

컴퓨터에는 `계산하는 곳`, `지금 쓸 정보를 두는 곳`, `오래 저장하는 곳`이 따로 있다.

---

## BLOCK 05 · 코어와 클럭

### LESSON 01 · 코어

CPU 안에서 명령을 처리할 수 있는 실행 핵심을 **코어(core)**라고 부른다.

코어가 많으면 여러 일을 나누어 처리할 가능성이 커지지만 모든 프로그램이 코어 수만큼 정확히 빨라지는 것은 아니다.

### LESSON 02 · 클럭

CPU 내부 동작의 기본 주기와 관련된 속도 지표를 **클럭(clock)**이라고 부른다.

GHz 숫자가 높다고 무조건 모든 상황에서 더 빠른 CPU라는 뜻은 아니다.

---

## BLOCK 06 · RAM

### LESSON 01 · 지금 쓰는 정보를 놓는 빠른 공간

**RAM**은 실행 중인 프로그램이 지금 필요한 코드와 데이터를 빠르게 사용할 수 있도록 두는 메모리다.

책상 비유:

```text
RAM = 지금 펼쳐 놓은 책상
저장장치 = 책을 오래 보관하는 책장
```

### LESSON 02 · RAM이 부족하면

운영체제가 다른 앱을 종료하거나 저장장치를 보조 메모리처럼 사용하면서 느려질 수 있다.

`RAM 부족`과 `저장공간 부족`은 다른 문제다.

---

## BLOCK 07 · 저장장치

### LESSON 01 · 전원을 꺼도 남기는 곳

사진, 문서, 앱 파일처럼 오래 보관해야 하는 데이터를 **저장장치(storage)**에 기록한다.

PC에서는 SSD와 HDD를 많이 사용한다.

### LESSON 02 · SSD와 HDD

**HDD**는 회전하는 자기 디스크를 사용한다.

**SSD**는 반도체 메모리를 사용해 일반적으로 훨씬 빠른 접근 속도를 제공한다.

---

## BLOCK 08 · 파일과 폴더

### LESSON 01 · 파일

**파일(file)**은 저장된 정보를 이름 있는 하나의 단위로 다루는 것이다.

```text
photo.jpg
memo.txt
report.pdf
```

### LESSON 02 · 폴더

**폴더(folder)**는 파일과 다른 폴더를 묶어 정리하는 공간이다.

```text
공부
 ├─ 코딩
 └─ 영어
```

---

## BLOCK 09 · 경로

### LESSON 01 · 파일의 위치

**경로(path)**는 파일이나 폴더가 어디에 있는지 나타내는 정보다.

```text
study/python/hello.py
```

사람말:

```text
study 폴더 안의 python 폴더 안의 hello.py
```

### LESSON 02 · 절대 경로와 상대 경로

**절대 경로**는 전체 위치를 나타낸다.

**상대 경로**는 현재 위치를 기준으로 나타낸다.

파일을 못 찾는 오류에서는 `파일 없음`과 `경로 틀림`을 먼저 구분한다.

---

## BLOCK 10 · 확장자와 파일 형식

### LESSON 01 · 확장자

파일 이름 끝의 `.jpg`, `.txt` 같은 표시를 **확장자(extension)**라고 부른다.

### LESSON 02 · 파일 형식

파일 안의 데이터를 어떤 규칙으로 저장하고 읽는지를 **파일 형식(format)**이라고 부른다.

이름을 `photo.jpg`에서 `photo.txt`로 바꾼다고 사진 데이터가 글자 데이터로 변하지 않는다.

```text
확장자 = 이름의 표시
형식 = 실제 데이터 구조의 규칙
```

---

## BLOCK 11 · 0과 1, bit와 byte

### LESSON 01 · bit

컴퓨터의 가장 작은 정보 단위를 설명할 때 **bit**를 사용한다.

bit 하나는 0 또는 1처럼 두 상태 중 하나를 나타낸다.

### LESSON 02 · byte

일반적으로 8개의 bit를 묶어 **1 byte**라고 부른다.

```text
8 bit = 1 byte
```

글자, 사진, 프로그램도 결국 바이트 형태로 저장된다.

---

## BLOCK 12 · 문자도 숫자로 저장한다

### LESSON 01 · '가'를 어떻게 저장할까

컴퓨터는 사람처럼 글자 모양 자체를 이해하지 않는다.

글자와 숫자를 연결하는 약속이 필요하다.

가상의 규칙:

```text
A → 1
B → 2
```

보내는 쪽과 읽는 쪽이 같은 약속을 알아야 같은 글자가 나온다.

---

## BLOCK 13 · 인코딩

### LESSON 01 · 아주 쉬운 뜻

**인코딩(encoding)**은 정보를 정해진 규칙에 따라 다른 표현으로 바꾸는 과정이다.

문자에서는:

> 글자를 컴퓨터가 저장할 수 있는 바이트 형태로 표현하는 규칙

이라고 이해하면 된다.

### LESSON 02 · 문자 깨짐

저장할 때의 문자 규칙과 읽을 때의 문자 규칙이 다르면 한글이 이상하게 보일 수 있다.

```text
저장 규칙 ≠ 읽기 규칙
→ 문자 깨짐 가능
```

파일이 완전히 손상된 것과 인코딩을 잘못 읽은 것은 다른 문제다.

---

## BLOCK 14 · Unicode와 UTF-8

### LESSON 01 · Unicode

**Unicode**는 세계의 많은 문자와 기호에 공통된 번호를 정하는 큰 표준이다.

### LESSON 02 · UTF-8

**UTF-8**은 Unicode 문자를 실제 바이트로 저장하는 널리 쓰이는 방식이다.

```text
Unicode = 어떤 문자인지 정하는 큰 체계
UTF-8 = 그 문자를 바이트로 표현하는 대표 방식
```

둘은 같은 말이 아니다.

---

## BLOCK 15 · 운영체제

### LESSON 01 · 여러 프로그램과 기계를 관리한다

**운영체제(OS)**는 CPU, 메모리, 파일, 장치와 프로그램 실행을 관리하는 핵심 소프트웨어다.

예:

```text
Windows
Android
macOS
Linux
```

### LESSON 02 · 커널

운영체제에서 CPU 시간, 메모리, 장치 같은 핵심 자원을 관리하는 중심 부분을 **커널(kernel)**이라고 부른다.

---

## BLOCK 16 · 프로그램과 앱

### LESSON 01 · 프로그램

**프로그램(program)**은 컴퓨터가 특정 일을 하도록 만든 명령과 구조의 묶음이다.

### LESSON 02 · 앱

**앱(application)**은 사용자가 특정 목적을 위해 사용하는 프로그램을 부르는 흔한 말이다.

계산기, 메신저, 지도 모두 앱이다.

---

## BLOCK 17 · 코드

### LESSON 01 · 명령을 글로 적는다

프로그램을 만들기 위해 작성한 명령과 규칙을 **코드(code)**라고 부른다.

```python
print("안녕")
```

이 한 줄은 `안녕`이라는 글자를 보여 주는 작은 코드다.

### LESSON 02 · 모르는 코드는 조각으로 나눈다

```python
print("안녕")
```

`print`, 괄호, 따옴표를 한 번에 외우지 않는다.

```text
print → 값을 보여 주는 기능
( ) → 기능에 필요한 내용을 넣는 모양
"안녕" → 글자 값
```

정확한 이름은 뒤에서 하나씩 배운다.

---

## BLOCK 18 · 프로그래밍 언어

### LESSON 01 · 코드에도 문법이 있다

컴퓨터 프로그램을 작성하기 위해 만든 정해진 언어를 **프로그래밍 언어**라고 부른다.

예:

```text
Python
JavaScript
Kotlin
Java
C
```

### LESSON 02 · 언어를 외우는 것이 목표가 아니다

언어마다 문법은 다르지만 다음 생각은 반복해서 등장한다.

```text
값
변수
조건
반복
함수
데이터 구조
오류 처리
```

이 교재는 이런 공통 개념을 먼저 이해하게 만든다.

## BLOCK 19 · 소스 코드와 실행

### LESSON 01 · 소스 코드

사람이 작성하고 읽는 프로그램 코드를 **소스 코드(source code)**라고 부른다.

### LESSON 02 · 실행

작성한 프로그램을 실제로 동작시키는 것을 **실행(run, execute)**이라고 부른다.

```text
코드를 작성했다 ≠ 실행했다
실행했다 ≠ 결과가 맞다
```

이 세 상태를 구분하는 습관이 중요하다.

---

## BLOCK 20 · 컴파일러와 인터프리터

### LESSON 01 · 고급 언어를 컴퓨터가 실행할 수 있게 바꾸기

사람이 작성한 코드는 실행을 위해 더 낮은 수준의 형태로 바뀌거나 실행 환경에 의해 해석되어야 한다.

### LESSON 02 · compiler

소스 코드를 실행 가능한 다른 형태로 미리 변환하는 프로그램을 **컴파일러(compiler)**라고 부른다.

### LESSON 03 · interpreter

코드를 실행하면서 해석하고 수행하는 방식의 실행 프로그램을 **인터프리터(interpreter)**라고 부른다.

실제 언어 구현은 두 방식이 섞일 수 있다. `언어 A는 무조건 100% 인터프리터`처럼 단순하게 외우지 않는다.

---

## BLOCK 21 · runtime

### LESSON 01 · 프로그램이 실제로 실행되는 때와 환경

**runtime**은 프로그램이 실제로 실행되는 시간이나 그 실행을 지원하는 환경을 뜻할 때 사용한다.

예:

```text
compile-time error = 빌드/컴파일 단계에서 발견
runtime error = 실행 중 발생
```

## BLOCK 22 · 값

### LESSON 01 · 프로그램이 다루는 실제 내용

```text
10
3.14
"안녕"
True
```

이런 실제 내용을 **값(value)**이라고 부른다.

값은 계산하거나 저장하거나 비교할 수 있다.

### LESSON 02 · 숫자 10과 글자 "10"

```python
print(10 + 20)
```

결과:

```text
30
```

```python
print("10" + "20")
```

결과:

```text
1020
```

값의 종류가 다르면 같은 기호도 다르게 동작할 수 있다.

## BLOCK 23 · 자료형

### LESSON 01 · 값의 종류

값의 종류를 **자료형(data type)** 또는 **타입(type)**이라고 부른다.

처음에는:

```text
정수
실수
글자
참/거짓
```

부터 익힌다.

### LESSON 02 · boolean

참과 거짓 두 값만 가지는 타입을 **Boolean**이라고 부른다.

Python에서는:

```text
True
False
```

를 사용한다.

## BLOCK 24 · 변수와 상태

### LESSON 01 · 변수

값을 이름으로 다시 사용할 수 있게 만든 것을 **변수(variable)**라고 부른다.

```python
price = 1200
```

사람말:

```text
price라는 이름에 1200을 넣는다.
```

### LESSON 02 · 상태

프로그램이 현재 가지고 있는 값들의 상황을 **상태(state)**라고 부른다.

```text
로그인됨 = 참
현재 탭 = 2
검색어 = "사과"
```

앱 버그의 많은 부분은 상태가 예상과 다르게 바뀌는 문제다.

## BLOCK 25 · 연산과 비교

### LESSON 01 · 연산자

값에 계산이나 비교를 적용하는 기호를 **연산자(operator)**라고 부른다.

```text
+ - * /
> < ==
```

### LESSON 02 · 비교 결과

```python
print(10 > 5)
```

결과:

```text
True
```

비교는 조건문을 만드는 기초가 된다.

## BLOCK 26 · 오류

### LESSON 01 · 문법 오류

프로그래밍 언어의 문법 규칙을 어기면 **문법 오류(syntax error)**가 발생할 수 있다.

```python
print("안녕)
```

따옴표가 닫히지 않았다.

### LESSON 02 · runtime error

문법은 맞지만 실행 중 문제가 생길 수 있다.

```python
print(10 / 0)
```

0으로 나누려고 하면서 오류가 발생한다.

### LESSON 03 · 논리 오류

코드는 실행되지만 결과가 의도와 다를 수도 있다.

```python
price = 1000
count = 3
print(price + count)
```

총가격을 구하려 했다면 `1003`은 잘못된 결과다.

## BLOCK 27 · 디버깅 첫걸음

### LESSON 01 · 문제를 찾고 고친다

프로그램 문제의 원인을 찾아 수정하는 과정을 **디버깅(debugging)**이라고 부른다.

기본 순서:

```text
Expected 확인
Actual 확인
처음 달라지는 지점 찾기
한 부분만 수정
다시 실행
```

### LESSON 02 · 오류 메시지는 공격이 아니다

오류 메시지는 `너는 코딩을 못한다`는 평가가 아니다.

프로그램이 이해하지 못했거나 실행할 수 없었던 지점을 알려 주는 정보다.

## BLOCK 28 · I/O와 병목 맛보기

### LESSON 01 · I/O

**I/O(Input/Output)**는 프로그램과 파일·네트워크·화면 같은 장치 사이에서 데이터를 주고받는 일을 넓게 가리킨다.

### LESSON 02 · bottleneck

전체 속도를 가장 크게 제한하는 부분을 **병목(bottleneck)**이라고 부른다.

CPU가 느린지, 파일 읽기가 느린지, 네트워크가 느린지 측정해야 한다.

---

## BLOCK 29 · 해시와 무결성 맛보기

### LESSON 01 · 무결성

데이터가 엉뚱하게 바뀌거나 깨지지 않고 의도한 상태를 유지하는 성질을 **무결성(integrity)**이라고 부른다.

### LESSON 02 · hash

데이터를 정해진 계산에 넣어 일정한 길이의 대표값을 만드는 방법을 **해시(hash)**라고 부른다.

파일이 바뀌었는지 확인하는 데 사용할 수 있다.

보안에서 필요한 정확한 성질은 TRACK 09에서 다시 깊게 배운다.

## BLOCK 30 · 터미널 맛보기

### LESSON 01 · 글자로 명령하기

글자로 명령을 입력하고 결과를 보는 창을 **터미널(terminal)**이라고 부른다.

터미널 안에서 명령을 해석하는 프로그램을 **셸(shell)**이라고 부른다.

### LESSON 02 · 명령 전에 현재 위치를 확인한다

파일을 다루는 명령은 현재 작업 폴더가 어디인지에 따라 결과가 달라질 수 있다.

처음 습관:

```text
현재 위치 확인
대상 확인
명령 의미 확인
실행
결과 확인
```
