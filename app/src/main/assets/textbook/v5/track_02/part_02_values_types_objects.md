# PART 02 · 값·타입·객체 — Python에서 이름과 데이터가 실제로 연결되는 방식

Python 코드를 읽을 때 `x = 10`을 단순히 “상자 x에 10을 넣는다”라고만 이해하면 곧 한계가 온다. 리스트를 다른 변수에 대입했더니 두 곳이 함께 바뀌고, `==`와 `is`가 다른 결과를 내며, 함수에 객체를 넘긴 뒤 바깥 값이 달라지는 현상을 설명할 수 없기 때문이다. Python의 핵심 모델은 **이름(name)이 객체(object)에 바인딩되고, 객체가 타입·값·정체성을 가진다**는 구조다.

## CHAPTER 01 · 대입은 복사가 아니라 이름을 객체에 바인딩한다

### 시작 전 용어집

#### 1. 객체

- **뜻:** Python에서 `name = expression`을 실행하면 먼저 오른쪽 표현식을 평가해 객체를 얻고, 그 객체에 왼쪽 이름을 바인딩한다.
- **왜 중요한가:** 이 설명은 정수처럼 변경 불가능한 값뿐 아니라 리스트, 함수, 클래스에도 동일하게 적용된다.
- **예시:** items = [10, 20] / alias = items

#### 2. 함수

- **뜻:** 이 차이는 함수 인자, 전역 변수, collection 내부 객체, closure를 이해하는 기초가 된다.
- **왜 중요한가:** 오른쪽 표현식이 어떤 객체를 만드는가, 왼쪽 이름이 어느 namespace에 속하는가, 이후 코드가 이름을 다시 바인딩하는가 아니면 객체를 변경하는가.
- **예시:** items = [10, 20] / alias = items

#### 3. mutable

- **뜻:** ”라고 보면 이상하지만, 두 이름이 같은 mutable object를 참조한다고 보면 자연스럽다.
- **왜 중요한가:** 반대로 `x = 10; y = x; x = 20`에서 `y`가 10으로 남는 이유는 정수 객체 자체를 수정한 것이 아니라 이름 `x`를 새로운 정수 객체에 다시 바인딩했기 때문이다.
- **예시:** items = [10, 20] / alias = items

#### 4. collection

- **뜻:** 대입문 자체는 일반적으로 객체 내부 데이터를 복제하지 않는다.
- **왜 중요한가:** `items`와 `alias`는 두 개의 리스트를 가진 것이 아니라 같은 리스트 객체를 가리킨다.
- **예시:** items = [10, 20] / alias = items

```python

alias = items
alias.append(30)
```

 그래서 `alias.append(30)`의 결과가 `items`를 통해서도 보인다. 문제를 “변수 값이 복사됐는데 왜 같이 바뀌지?

 **이름의 재바인딩과 객체의 mutation은 서로 다른 연산**이다. 

대입을 볼 때는 세 질문을 분리한다.  이 세 축을 나누면 데이터 흐름을 훨씬 정확하게 추적할 수 있다.

## CHAPTER 02 · 객체에는 identity, type, value가 서로 다른 축으로 존재한다

### 시작 전 용어집

#### 1. 객체

- **뜻:** Python 객체를 설명할 때 identity는 “이 객체가 바로 그 객체인가”, type은 “어떤 연산과 의미를 제공하는가”, value는 “현재 어떤 데이터를 나타내는가”에 해당한다.
- **왜 중요한가:** 값이 같더라도 서로 다른 객체일 수 있고, 같은 객체를 여러 이름이 가리킬 수도 있다.
- **예시:** a = [1, 2] / b = [1, …

#### 2. identity

- **뜻:** 값 비교를 identity 우연에 의존시키면 실행 환경이나 생성 방식에 따라 결과가 달라질 수 있다.
- **왜 중요한가:** 언어 계약상 어떤 관계를 원하는지에 맞춰 `==`와 `is`를 선택한다.
- **예시:** a = [1, 2] / b = [1, …

#### 3. type

- **뜻:** `==`는 일반적으로 값의 동등성을 묻고 `is`는 객체 정체성이 같은지를 묻는다.
- **왜 중요한가:** 두 리스트 `[1, 2]`와 `[1, 2]`는 내용이 같아서 `==`가 참일 수 있지만 별도로 생성했다면 `is`는 거짓이다.
- **예시:** a = [1, 2] / b = [1, …

#### 4. value

- **뜻:** `None`처럼 단일 객체의 존재 자체를 검사할 때는 `is None`을 사용하는 이유가 여기에 있다.
- **왜 중요한가:** 구현 최적화 때문에 작은 정수나 일부 문자열 객체가 재사용되는 경우가 있어도 이를 프로그램 규칙으로 사용하면 안 된다.
- **예시:** a = [1, 2] / b = [1, …

```python
a = [1, 2]
b = [1, 2]
c = a

print(a == b)  # 값 비교
print(a is b)  # 정체성 비교
print(a is c)  # 같은 객체 참조
```

  

사용자 정의 클래스에서는 equality의 의미를 직접 정의할 수 있다. 두 고객 객체를 같은 고객으로 볼 기준이 데이터베이스 ID인지 모든 필드가 같은지에 따라 `==`의 업무 의미도 달라진다. 따라서 equality는 단순 연산자가 아니라 데이터 모델의 계약이다.

## CHAPTER 03 · mutable과 immutable의 차이는 변경 가능성보다 aliasing 효과에 있다

### 시작 전 용어집

#### 1. mutable

- **뜻:** 정수, 문자열, tuple 같은 대표적인 immutable 객체는 생성된 뒤 그 객체의 값을 제자리에서 바꾸지 않는다.
- **왜 중요한가:** 연산 결과가 달라지면 새로운 객체가 만들어지고 이름이 다시 바인딩된다.
- **예시:** def add_tag(tags, tag): / tags.append(tag) # 전달된 객체를 …

#### 2. aliasing

- **뜻:** 리스트, dict, set 같은 mutable 객체는 동일한 identity를 유지한 채 내부 상태를 변경할 수 있다.
- **왜 중요한가:** 여러 이름이나 collection이 같은 mutable object를 공유하면 한 경로에서의 변경이 다른 경로에서도 관찰된다.
- **예시:** def add_tag(tags, tag): / tags.append(tag) # 전달된 객체를 …

#### 3. tuple

- **뜻:** tuple 안에 mutable list가 들어 있다면 tuple의 슬롯은 바뀌지 않아도 내부 list는 수정될 수 있다.
- **왜 중요한가:** 데이터 구조의 불변성을 평가할 때는 바깥 컨테이너와 참조된 객체 그래프를 구분해야 한다.
- **예시:** def add_tag(tags, tag): / tags.append(tag) # 전달된 객체를 …

#### 4. 객체

- **뜻:** 첫 함수는 호출자와 공유한 객체를 수정하고, 두 번째 함수는 새 값을 돌려준다.
- **왜 중요한가:** 대용량 객체의 복사 비용, 공유가 필요한 상태, 동시성, 디버깅 가능성을 함께 고려한다.
- **예시:** def add_tag(tags, tag): / tags.append(tag) # 전달된 객체를 …

이 차이가 중요한 이유는 aliasing이다.  함수가 인자로 받은 리스트를 정렬하거나 항목을 추가했을 때 호출자의 리스트가 변하는 것도 같은 원리다. 이런 효과가 의도된 API라면 계약으로 드러내고, 의도하지 않았다면 복사하거나 immutable representation을 사용한다.

```python
def add_tag(tags, tag):
    tags.append(tag)       # 전달된 객체를 변경

def with_tag(tags, tag):
    return [*tags, tag]    # 새 리스트를 반환
```

두 함수는 결과 모양이 비슷해도 상태 변화 계약이 다르다.  어느 방식이 항상 우월한 것은 아니다. 

immutable이라는 사실도 중첩 구조 전체가 불변이라는 뜻은 아니다.

## CHAPTER 04 · 숫자 타입은 표현 범위와 연산 의미를 함께 결정한다

### 시작 전 용어집

#### 1. 타입

- **뜻:** `bool`은 조건 판단에 쓰이지만 Python의 타입 계층에서 정수와 관계가 있다.
- **왜 중요한가:** 이 사실을 이용해 `True + True` 같은 코드를 업무 로직에 쓰는 것은 의도를 흐릴 수 있다.
- **예시:** `bool`은 조건 판단에 쓰이지만 Python의 타입 계층에서 정수와 …

#### 2. API

- **뜻:** 파일 형식, 데이터베이스, 네트워크 API, NumPy 같은 다른 실행 모델과 경계를 넘으면 다시 고정 폭과 overflow 계약이 등장할 수 있다.
- **왜 중요한가:** `float`는 대부분의 플랫폼에서 IEEE 754 binary floating-point 의미와 연결되며 많은 십진수를 정확하게 표현하지 못한다.
- **예시:** 파일 형식, 데이터베이스, 네트워크 API, NumPy 같은 다른 …

#### 3. 경계

- **뜻:** Python의 일반 `int`는 고정 폭 machine integer와 달리 값이 커질 때 필요한 정밀도를 확장하는 의미를 제공한다.
- **왜 중요한가:** 그렇다고 숫자 연산 비용이 항상 일정하거나 외부 시스템의 정수 범위 문제가 사라지는 것은 아니다.
- **예시:** Python의 일반 `int`는 고정 폭 machine integer와 달리 …

#### 4. 계약

- **뜻:** 금액처럼 십진 규칙이 계약인 값은 최소 화폐 단위 정수나 `decimal` 계열처럼 목적에 맞는 모델을 선택해야 한다.
- **왜 중요한가:** 타입이 허용하는 연산과 도메인에서 의미 있는 연산은 다를 수 있다.
- **예시:** 금액처럼 십진 규칙이 계약인 값은 최소 화폐 단위 …

`0.1 + 0.2` 같은 결과가 사람이 기대한 십진 표기와 미세하게 어긋날 수 있는 이유는 계산 오류라기보다 표현 모델 때문이다. 

   프로그램 설계는 “실행 가능한가”보다 “이 값에 이 연산이 의미 있는가”를 기준으로 해야 한다.

숫자를 문자열에서 변환할 때도 실패 가능성을 모델링한다. `int(text)`는 모든 문자열에 성공하지 않으며, 공백·부호·진법·범위 정책이 외부 요구사항과 맞는지 확인해야 한다. 입력 단계에서 숫자를 얻었다고 끝나는 것이 아니라 단위, 최소/최대, 특수값 허용 여부를 별도 검증한다.

## CHAPTER 05 · 문자열은 문자 목록이 아니라 Unicode 추상화 위의 sequence다

### 시작 전 용어집

#### 1. Unicode

- **뜻:** Unicode code point와 사용자가 지각하는 grapheme cluster는 항상 일치하지 않는다.
- **왜 중요한가:** 결합 문자나 emoji sequence에서는 한 화면 글자가 여러 code point로 구성될 수 있다.
- **예시:** raw = "한글".encode("utf-8") / text = raw.decode("utf-8")

#### 2. sequence

- **뜻:** Python의 `str`은 텍스트를 표현하는 객체이고, 파일이나 네트워크에서 다루는 raw byte sequence와는 다르다.
- **왜 중요한가:** 외부 bytes를 text로 바꾸려면 encoding을 사용해 decode하고, text를 bytes로 내보내려면 encode해야 한다.
- **예시:** raw = "한글".encode("utf-8") / text = raw.decode("utf-8")

#### 3. 객체

- **뜻:** 이 경계를 흐리면 운영체제·파일·HTTP·데이터베이스 사이에서 깨진 문자나 비교 실패가 발생한다.
- **왜 중요한가:** 문자열 indexing 단위를 화면의 “한 글자”와 동일하다고 가정해서도 안 된다.
- **예시:** raw = "한글".encode("utf-8") / text = raw.decode("utf-8")

#### 4. bytes

- **뜻:** 텍스트를 다룰 때는 `bytes ↔ decoding ↔ str ↔ normalization/validation ↔ domain value` 단계를 분리한다.
- **왜 중요한가:** 각 단계의 실패를 구분하면 “인코딩 문제”라는 넓은 표현 대신 어느 경계에서 의미가 달라졌는지 추적할 수 있다.
- **예시:** raw = "한글".encode("utf-8") / text = raw.decode("utf-8")

```python
raw = "한글".encode("utf-8")
text = raw.decode("utf-8")
```

   UI의 글자 수 제한과 protocol의 byte 제한은 따라서 다른 문제다.

문자열 비교에는 대소문자, normalization, locale, security policy가 영향을 줄 수 있다. 사람이 같은 글자로 인식하는 두 문자열이 내부 sequence까지 동일하다는 보장은 없다. identifier, 검색어, 비밀번호는 서로 다른 정규화 정책을 요구한다. 모든 문자열에 한 번의 `.lower()`를 적용하는 방식은 충분한 계약이 아니다.

## CHAPTER 07 · 변환은 정보 손실과 실패 가능성을 가진 연산이다

## CHAPTER 08 · 얕은 복사와 깊은 복사는 객체 그래프를 다르게 다룬다

### 시작 전 용어집

#### 1. 객체

- **뜻:** 리스트를 `list(original)`이나 slicing으로 복사하면 바깥 리스트는 새 객체가 되지만, 안에 들어 있는 요소 참조는 그대로 공유될 수 있다.
- **왜 중요한가:** 중첩 리스트나 dict가 있다면 복사본 내부를 수정했는데 원본도 바뀌는 상황이 생긴다.
- **예시:** original = [{"name": "A"}] / copy1 = list(original)

#### 2. list

- **뜻:** deep copy는 참조된 객체 그래프를 재귀적으로 복제하려고 하지만 무조건적인 해결책은 아니다.
- **왜 중요한가:** 공유되어야 하는 객체까지 복제하면 identity 의미가 깨질 수 있고, 큰 그래프에서는 비용이 커진다.
- **예시:** original = [{"name": "A"}] / copy1 = list(original)

#### 3. dict

- **뜻:** 파일 handle, lock, 외부 resource처럼 단순 복제가 의미 없는 객체도 있다.
- **왜 중요한가:** 복사 전략은 데이터 구조가 어떤 공유 관계를 의도하는지에서 결정해야 한다.
- **예시:** original = [{"name": "A"}] / copy1 = list(original)

#### 4. 재귀

- **뜻:** 많은 경우 더 좋은 해법은 복사 함수를 선택하기 전에 모델을 단순화하는 것이다.
- **왜 중요한가:** 변경 가능한 중첩 구조를 여러 계층이 공유하지 않도록 하고, 경계에서 immutable snapshot을 만들거나 필요한 필드만 새 값으로 구성하면 aliasing 위험이 줄어든다.
- **예시:** original = [{"name": "A"}] / copy1 = list(original)

이것이 shallow copy의 핵심이다.

```python
original = [{"name": "A"}]
copy1 = list(original)
copy1[0]["name"] = "B"
# original[0]도 같은 dict 객체를 가리킨다.
```

   

  데이터 업데이트를 함수 하나에 모으면 누가 언제 mutation하는지도 추적하기 쉽다.

디버깅할 때는 `id()` 자체의 숫자에 의미를 두기보다 어떤 이름과 컨테이너가 같은 객체를 공유하는지 관계를 추적한다. 객체 그래프 관점은 중첩 collection, 클래스 인스턴스, 캐시, 함수 인자를 다룰 때 반복해서 필요해진다.

- **예시:** 사용자 정의 타입에서 `__eq__`와 `__hash__`를 설계할 때 이 …
